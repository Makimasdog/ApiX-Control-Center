# 开发约定

仓库规则以 [AGENTS.md](../AGENTS.md) 为准，当前任务分工见[工作模式](../协作/当前工作模式.md)。本页只保留日常步骤，历史分支放在[归档](归档/阶段设计与分支历史.md#分支管理历史)。

## 开发与验证

1. 检查当前分支和工作区，不自动切换分支，不处理本轮无关改动。
2. 修改 src/web 等源码，使用 `npm run build` 生成 dist；不手工编辑或提交 dist。
3. 运行 `npm run check` 和与改动相关的测试；需要完整回归时执行 `npm test`，清单以 package.json 为准。
4. 模拟 HTTP/CLI 通过不代表真实模型或业务系统验收。真实协作脚本可能收费，须明确授权，不在普通文档整理中运行。

## 审查与提交

审查最终 diff、新增文件、调用方、错误路径、数据一致性和访问边界，修复后执行相关验证。结果和未验证项写入协作目录，自审不能称为独立审查或人工批准。

只按明确文件清单暂存，核对暂存区与审查内容一致后提交。审查后改代码须重新审查；不使用全量暂存、reset 或 clean，不捏造共同作者。未经用户要求不推送、合并或删除分支。

本开发线为 codex/readiness-p0-p2，默认分支为 main；不得将本地提交或旧跟踪引用当作 GitHub 最新状态。跨设备同步须先 fetch、检查领先/落后及未提交文件；冲突不盲目覆盖。历史上对某次推送、合并或双 Agent 的授权不自动成为当前授权。

## 文档与证据

当前资料从[阅读导航](README.md)进入。每项事实应有源码或原始证据，带上提交和验证范围；产品限制放使用指南，具体协议放参考，不重复扩充长 Wiki。移动或合并文档后检查链接、源码路径与代码围栏。

已有原始审查和截图保留在协作目录，调整引用路径不改写历史结论。已验证结果统一见[变更回顾](变更回顾.md)；本轮整理不代表重新运行了历史测试。
