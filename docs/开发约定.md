# 开发约定

仓库规则以 [AGENTS.md](../AGENTS.md) 为准，当前任务分工见[工作模式](../协作/当前工作模式.md)。本页只保留日常步骤，历史分支放在[归档](归档/阶段设计与分支历史.md#分支管理历史)。

## 开发与验证

1. 检查当前分支和工作区，不自动切换分支，不处理本轮无关改动。
2. 修改 src/web 等源码，使用 `npm run build` 生成 dist；不手工编辑或提交 dist。
3. 运行 `npm run check` 和与改动相关的测试；需要完整回归时执行 `npm test`，清单以 package.json 为准。
4. 模拟 HTTP/CLI 通过不代表真实模型或业务系统验收。真实协作脚本可能收费，须明确授权，不在普通文档整理中运行。

## 审查与提交

任务交付回归入口：`npm run test:delivery`。`npm run test:delivery:browser` 启动隔离的真实服务及本地模型协议夹具，输出地址与结果文件路径，需浏览器驱动完成界面操作并核验后写入结果；无人操作或 watchdog 到期会失败，不能将启动服务当作通过。实际流程见 [P1.1 自审](../协作/20261019-P11任务交付与评测自审.md)。

评测沿用 `npm run eval:coding:real -- --mode deterministic --tasks all`，执行五类受控工程任务，不请求模型。默认 smoke 只测连通性；真实模型默认 `not_run`，先 `--inspect --tasks all` 查看配置及任务集合哈希。批准文件须使用 schemaVersion 2，绑定配置、按序任务集合哈希、操作/检查/费用批准、币种、总额/单请求上界/总请求数/总期限，以及 perTaskMaxMinor、perTaskMaxRequests、perTaskMaxMinutes。`--approval 文件 --tasks all` 才会执行真实模型；`--mode local-protocol` 只接受回环地址但同样要求显式清单。实际用量和账单未知保留 null，预留金额不等于计费；固定响应结果不证明模型能力。报告 JSON 与静态页位于输出的隔离目录，不自动批准、推送或合并。

审查最终 diff、新增文件、调用方、错误路径、数据一致性和访问边界，修复后执行相关验证。结果和未验证项写入协作目录，自审不能称为独立审查或人工批准。

只按明确文件清单暂存，核对暂存区与审查内容一致后提交。审查后改代码须重新审查；不使用全量暂存、reset 或 clean，不捏造共同作者。未经用户要求不推送、合并或删除分支。

本开发线为 codex/readiness-p0-p2，默认分支为 main；不得将本地提交或旧跟踪引用当作 GitHub 最新状态。跨设备同步须先 fetch、检查领先/落后及未提交文件；冲突不盲目覆盖。历史上对某次推送、合并或双 Agent 的授权不自动成为当前授权。
