# R3 P2 / P3：稳定投影与最终请求诊断

日期：2026-10-30。状态：**P2/P3 已实施，显式试验开关；P4 尚未完成**。不默认迁移旧会话、不调用付费模型、不迁移原生消息或 tools 协议。以 [Token 契约](../专题/Token用量与优化.md) 为当前产品入口；原始设计见 [R3](2026-10-29-Reasonix源码核查与ApiX缓存优化方案.md) 和 [R2 细则](2026-10-28-最终请求诊断与稳定前缀实施细则.md)。

## 配置与兼容

旧会话或缺少设置行默认为 `legacy`。在「Token 用量与优化」选择「输入布局 → 稳定布局（试验）」后显式应用；standard/saving 均支持。原有 mode 仍独立表示目录与结果优化，不改变授权。旧客户端只写 mode 会保留当前 promptStrategy。

`POST /api/assistant/sessions/:id/optimization` 扩展 `{version, mode, promptStrategy?, promptSettingsVersion?}`。显式提交策略时同时校验会话 version 与独立的设置版本；缺行设置版本为 0，实际切换时递增并清空当前代指针。模式、策略、会话版本与审计事件同事务保存，写失败整体回滚。响应 details 和 GET context 的 optimization 返回 `promptStrategy/promptSettingsVersion/generation`；尚未准备推理时 generation 为 null。运行、待审批、委派及未核对副作用继续使用既有门禁。

新前端只在服务端返回设置版本后显示布局选项；按会话、任务及请求序列更新，较旧设置版本响应不能覆盖当前选择。切回 legacy 后保留原始历史、用量、输出引用和私有视图，不自动删除证据。旧代码仅使用原 mode 表；已用 `a909014` 旧源码构建，在一次性数据库副本验证降级读取与 legacy 继续，再升级恢复稳定布局，见自审。

## 布局、字段去向与帧不变量

`prompt-projection.ts` 独立生成文本帧，仍交给现有三协议适配器；JSON action 契约和重试冻结不变。宿主对象键用现有 canonical 规范化，目录按名称排列；数组语义顺序和代码/用户字符串中的空白不改写。generation UUID、时间、usage ID 不进入固定头。

```text
APIX_AGENT_LOOP_JSON
APIX_PROMPT_LAYOUT stable-prefix-v1
固定行为与 JSON action 契约
STABLE_CONTEXT {固定基础目录、初始 deferred 索引、稳定读策略}
CHECKPOINT {摘要、水位、当前指令快照、已发现定义、必要用户/任务快照}
EVENT {kind:project_instructions, version, supersedes, revoked, instructions}
EVENT {id, role, kind, body}
EVENT {新增事件}
CURRENT_STATE {动态宿主状态、当前指令版本与优先级}
固定 JSON action 结束契约
```

同代的旧 coreText（到最后一条 EVENT 的 LF）必须是新 coreText 的 UTF-8 字节前缀。尾部会被新帧与最新状态替换，因此不承诺上轮整个 prompt 是本轮前缀，也不把文本帧称为原生 assistant/reasoning 重放。

| 原字段/来源 | stable 去向 |
| --- | --- |
| instruction、基础工具目录 | 固定行为与 STABLE_CONTEXT；内容变化显式换代 |
| deferredTools、contextReadPolicy | STABLE_CONTEXT 的初始发现索引/固定读策略，不按发现结果回填 |
| context.instructions | 首次/变更追加完整版本块；删除为 revoked 块；CURRENT_STATE 明确有效版本与完整替换语义；检查点携带当前快照 |
| summary、compacted_through | CHECKPOINT，同代固定 |
| history | 按水位完整分页读取，事件帧首次选择表示后持久化 |
| initialRequest、latestUserRequest | 原始用户 EVENT；检查点保留必要正文快照，尾部为原始 user message eventId 引用 |
| currentTask | 原始 task_started EVENT；检查点保留任务快照，尾部保留当前任务元数据，description 不每轮重复 |
| taskFeedback | 原始 delivery_changes_requested EVENT；检查点保留当前反馈，尾部提供 deliveryId/taskId 引用 |
| toolAccess、toolLimits、policy、capabilities | CURRENT_STATE；执行仍由实时 registry、治理和原审批/恢复门禁校验 |
| recalledMemories、memoryIndex、outputIndex | CURRENT_STATE，沿用现有有界召回/索引，不改写固定头 |
| needsVerification、hasVerification、verificationState | CURRENT_STATE；历史验收、失败和未知事实仍有独立 EVENT |
| contextBudget | CURRENT_STATE；稳定预算按实际渲染 prompt 的 UTF-8÷3 加 256 Token 适配层余量估算，仍非供应商实际 Token |
| context.environment/project/projectProfile/skills/employees/autonomy/workflow/child 及其余 describe 字段 | 去除已投影 instructions 后的 context 整体进入 CURRENT_STATE，未知字段保留，不笼统冻结/删除 |

项目指令版本块完整替换前版本；删除有明确撤销声明。该版本化只管理模型输入，不能替代权限撤销。知识引用沿用 `knowledge.assertSession`：已用资料更新、删除或撤权时先停止，不把旧片段继续发送。

事件生产方清单沿用 [P0/P1 盘点](2026-10-30-R3-P0P1实施与事件投影清单.md)。stable 固定排除 activity/context_budget/optimization_changed，明确保留 memory_recalled/compacted、用户选择和否决、执行/验证/恢复、文件/命令/npm 生命周期及交付反馈。**stable 新 kind 未归类时报 unsupported_event_kind 并停止准备；legacy 保持 P1 的默认保留行为。** 扫描水位独立于最后发送事件：被排除的预算事件可推进扫描，但不能移除旧帧。读取按捕获的最大事件 ID 分页到结束；超过原有 200 条保护界限进入检查点流程，不以 LIMIT 201 静默遗漏后续事件。

## 首次表示、发现与预算

工作片段 `read_file/read_context/read_output` 及 `search_tools` 的完整返回从首次帧保留，不应用 legacy 的滑动 32 KiB 文件池；普通大结果沿用已有 outputs.history 的单事件有界预览、完整引用与 hostResultSummary。失败、unknown、退出码及证据元数据不省略。同代保存后不因年龄重选 full/reference。工作片段是否可保留由总上下文预算决定，不把 32 KiB 变成整代总文件容量。

saving 仅对当前可见代中完全相同、成功的 read_file/read_context 正文去重；以完整 body（版本、范围、游标及元数据均包含）比较，后帧指向本代已有正文事件。压缩后重新从原事件选择表示并重建依赖，前目标退出时恢复正文。read_output 片段保留实际观测内容，不重复折叠或按可变日志引用猜测相等。

standard 固定基础内置目录；saving 固定核心内置目录和初始发现索引。发现后的完整定义由 EVENT 追加，不插回固定头。新检查点保留当前有效已发现定义；发现成员新增不换代，既有定义失效/变更换代，执行仍实时比对 registry/version。若完整规则、定义或单条工作片段不能容纳，明确停止并要求缩小输入；不截断 Schema 后声称工具可用。本版没有自动淘汰发现定义或自动缩小读取范围。

实际帧、固定头和尾部均纳入预算；稳定目标还受现有 512 KiB prompt 上限约束。新增帧超预算时先走受控压缩旧完整执行组；无法形成安全边界则明确要求拆分任务。压缩后候选不缩小时拒绝提交，原检查点保持。**失败/无收益的持久抑制尚属 P4**，不能把“本次不提交”说成“恢复后不会重复付费尝试”。

## 存储、恢复与错误路径

- `assistant_prompt_settings`：独立策略、版本、当前代指针；当前代以 `(session_id,id)` 外键约束，避免跨会话引用。
- `assistant_prompt_generations`：固定头、检查点、边界摘要、扫描水位、指令版本/哈希、已发现定义、完整性与帧集合清单哈希。
- `assistant_prompt_frames`：代内 sequence、原 event ID/source hash、渲染文本及 hash；代内事件唯一，指令块无原 event ID。

仅准备推理或明确压缩路径写新视图。stable GET context 走不写入预览，不创建帧、代、引用或模型请求；尚无代时不冒充已经准备。私有帧包含原事件内容，保留在本地 SQLite，与原始证据同访问边界；完整正文不进入 model_prompt_diagnostics。新表会话删除级联清理；当前 API 软删除沿用原可见性门禁，旧视图不自动清理。

帧、必要引用、扫描水位和当前代指针在同一短 SAVEPOINT 中落库。会话版本变化时拒绝过期准备。已有 source 变化、帧文本/集合/顺序异常时停止并报告，不自动重跑工具或悄悄修补已发送帧。原历史未损坏时可显式切回 legacy；不得把修复私有视图等同于重放副作用。

压缩先在事务外生成/校验候选，复核会话、知识引用和权限；事务内提交旧 summary/compacted_through、新代/帧与 compacted 事件。失败全部回滚。切回 legacy 使用同一摘要水位，不恢复压缩前的旧模型历史。

边界变化由明确原因建代：布局/模式、基础目录或既有发现定义、模型配置版本、固定指令、权限范围、压缩水位。taskId、调用数、面板刷新及单纯新增工具不自动换代。项目指令可表达完整替换时追加版本块。模型配置版本包括应用内更换凭据引用；未收集密钥或其哈希，应用外直接替换环境凭据不提供独立版本观测。

## P3：真实请求的核心/尾部诊断

描述边界由同一 builder 生成，按 UTF-8 字节给出 coreEnd/tailEnd 和 instruction/checkpoint/events/current_state/ending 区域。保留原 wire/prompt LCP、参数差异、事件集合移除/改写/重排、宿主字段哈希和传输事实；新增可选 `requestDiagnostics.stableCore`：

`bytes/hash/commonPrefixBytes/previousCorePreserved/tailChanged/generationChanged/generationReason/change`。

`change` 区分 unknown、preserved、unreported_change、declared_generation。旧记录或 legacy 没有新字段；首次、重启、LRU 淘汰没有可比较核心时为 null/unknown，不填零。同代旧核心破坏与合法换代分开；即使合法换代也保留真实 historyChanges，不隐藏移除事实。动态尾部变化不冒充历史改写。

比较仍按项目/会话/路由/用途/布局隔离；基线只在观察响应头并结束 invocation 后晋升。诊断存储失败不发请求；普通重试复用冻结 body，取消/清理沿用原安全事实。GET 不生成基线或新帧。字节前缀、核心保持、原生 usage 独立展示；供应商命中原因始终未知。

## P4 仍需完成

1. **持久失败/无收益抑制**：以 generation、有效用户/工具输入水位及输入签名记录失败；同一有效输入的普通 resume、预算审计事件、面板刷新不解除抑制，不重复付费压缩。
2. **明确解除条件**：新增有效输入或显式手动压缩才重新评估；区分扫描水位与有效输入水位，避免 context_budget 等审计事件触发新的尝试。
3. **补足压缩专项回归**：阈值以下零压缩、成功换代、失败/无收益跨重启不循环、过期候选/撤权回滚、完整工具组、约束和去重依赖恢复。本轮已完成原子检查点与去重恢复，但未交付上述跨恢复抑制状态。
4. **另行授权真实收益实验**：先固定任务集、供应商/端点/模型/思考配置、调用/费用上限及停止规则，再交叉配对比较 standard legacy/stable、saving legacy/stable；覆盖短读、多轮、编辑验证、指令变更和压缩恢复。保存全部 attempt，报告正确性、总输入/输出/缓存读、请求/补读/压缩/纠错/失败、耗时、首轮/稳定段/压缩恢复及覆盖率；费用没有账单仍未知。
