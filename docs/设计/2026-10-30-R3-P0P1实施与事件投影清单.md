# R3 P0 / P1 实施与事件投影清单

日期：2026-10-30。P0、P1 已实施；P2、P3、P4 待实施。主契约见 [Token 用量与优化](../专题/Token用量与优化.md)，方案边界见 [R3](2026-10-29-Reasonix源码核查与ApiX缓存优化方案.md)。本轮由 Codex 实现并自审，无独立审查，无付费模型调用。

## P0：用量计量

Chat Completions 按响应字段读取 `prompt_cache_hit_tokens` / `prompt_cache_miss_tokens`，不识别模型名称，也不修改请求。标准 `cached_tokens` 与原生 hit 是候选：相等取一次；仅一个有效取有效值；冲突置缓存读为 null。计数只接受非负安全整数，显式零保留，非法值覆盖对应候选为 null，缺失字段沿用。候选按 attempt 保留，后续空快照不能消除冲突，明确一致的后续快照可修复。

已知总输入要求缓存读不超过输入；原生 hit+miss 须安全求和并与总输入一致，否则缓存读未知。缺少有效总输入且两分项有效时允许重建，来源为 `derived_from_provider_parts`。只有一个分项不能推断总数。miss 不作为缓存写入。独立有效的输入和输出保留；`usageComplete` 仍只表示成功终端具备有效输入和输出，不代表缓存分项完整。

`ModelUsage` 与 `unknownUsage()` 的五项计数形状不变。解析器用 WeakMap 保留累计候选，`ModelAttempt.usageDetails` 携带 `standardHit/nativeHit/nativeMiss/providerInput/inputSource/cacheSource/cacheConsistency`。`model_usage_details(usage_id, body)` 附表与原账本和请求诊断在同一 SAVEPOINT 结算；写失败回滚为 pending，沿用计量故障门禁。外键随用量物理删除级联清理；旧行无元数据，不回填。最近记录只读取已按项目/会话/当前任务限定的 usage ID。

任务、会话、项目汇总新增 `cacheRead`：`ratio/eligibleCalls/totalCalls/excludedCalls/pairedInputTokens/pairedCachedInputTokens/coverageComplete/overflow`。仅成对有效且缓存读不超过输入的非 pending attempt 进入分子分母；含已观测失败与重试。分母为零或合计不安全时 ratio 为 null，溢出时两项合计也为 null。旧行已有有效成对计数可参与比例，但来源仍未知。面板展示“已观测请求中的输入缓存占比”及覆盖率，冲突记录显示缓存未知，输入/输出仍独立展示。

## P1：事件生产方与模型投影盘点

过滤只在 `assistant-loop.assemble → trimHistory → outputs.history` 的模型视图入口执行；UI 的 `eventPage` 仍直接投影原始事件，不调用 `trimHistory`。两种模式使用同一固定分类。以下“保留”均受原有压缩水位、201 条读取边界与结果折叠规则约束，表示不再按最近 8 条规则过滤，不代表正文永久冻结。

| kind | 生产方 | 当前 body 关键字段 | 模型投影规则 |
| --- | --- | --- | --- |
| `activity` | `assistant-loop` 工具决策分支 | `content`（模型调用工具前的说明，敏感描述脱敏） | 从首次就排除；工具名、参数与结果由下列执行事实表达 |
| `context_budget` | `assistant-loop.context` | 预算 categories、window、usedTokens、指令元数据/hash | 继续排除；不参与事件年龄判断 |
| `optimization_changed` | `assistant-loop.setOptimization` | `mode` | 继续排除；模式由当前宿主状态提供 |
| `memory_recalled` | `assistant-loop.context` | `memories[].title/version/kind/stale` | 始终保留；当前召回正文仍由 `recalledMemories` 提供 |
| `compacted` | `assistant-loop.context` 压缩成功事务 | `schema/reason/preserve/summary/through/count`、压缩前后估算 | 始终保留；当前有效摘要仍由 `summary` 提供 |
| `tool_started`、`tool_result` | `assistant-loop.execute` | `tool/args/ok/result/error/operationId/fault` | 保留配对及宿主状态，沿用结果折叠/引用规则 |
| `tool_retry`、`tool_loop_stopped`、`operation_reused`、`knowledge_scope_changed` | `assistant-loop` 重试/预算/复用/知识范围入口 | `tool/attempt/delayMs/content/reason/operationId` | 保留重试、停止、复用和范围变更事实 |
| `process_unknown`、`restart_interrupted`、`stopped`、`resumed`、`error` | `assistant-loop` 安全恢复/停止/错误入口 | `resource/error/fault/content/confirmed` | 保留，恢复门禁照旧 |
| `message`、`request`、`request_answer`、`intent_confirmed`、`answer` | `assistant-loop` 消息/询问/回复/完成入口 | `content/question/options/kind/tool/args/approved/selected/correction` 等 | 保留用户约束、审批、纠正与答复；审批结果实际 kind 为 `request_answer`，不是 `approval` |
| `verification_contract`、`verification_evidence`、`completion_rejected`、`delivery_verified` | `assistant-loop` 验收流程 | 契约版本、指纹、检查状态、进程与证据标识 | 保留，执行与验收权限仍实时校验 |
| `protocol_repair` | `assistant-loop` 格式纠正 | `content` | 保留格式纠正事实 |
| `model_retry`、`inference_accounting_failure` | `control-plane` 推理重试与 `createAssistantInference.recordFailure` | `attempt/delayMs/fault`；`id/projectId/sessionId/stage/error` | 保留模型重试和计量失败事实 |
| `delegation_result`、`supervision_event`、`child_stop_error`、`memory_edited`、`task_baseline_limited` | `assistant-loop` 委派/监督/停止/记忆/基线入口 | 子会话状态、监督观测、停止错误、记忆标题、基线失败原因等 | 保留；大结果沿用折叠规则 |
| `task_started`、`review_snapshot`、`review_snapshot_expired`、`task_baseline` | `assistant-delivery` | `taskId/description/ref/manifest/version/reason` | 保留任务与证据引用事实 |
| `delivery_record`、`delivery_summary`、`delivery_accepted`、`delivery_changes_requested` | `assistant-delivery` 冻结/用户审阅；`assistant-loop` 完成 | 交付版本、文件、检查、范围；`deliveryId/taskId/comment` | 保留交付证据与用户反馈；不能当作展示说明删除 |
| `file_edit_intent`、`file_edit_result`、`file_recovery_checked` | `assistant-coding` | `operationId/path/beforeSha256/plannedAfterSha256`、实际写入结果、恢复记录 | 保留写入意图、结果与恢复事实 |
| `command_intent`、`command_identity`、`command_finished`、`command_recovery_checked` | `assistant-commands` | `operationId/identity/commandHash/tool`、终态与输出引用、项目恢复记录 | 保留命令生命周期与副作用边界 |
| `command_log_anchor`、`command_log_expired` | `execution/command-logs` | `operationId/channel/reason` | 保留日志引用及失效事实 |
| `npm_validation_started`、`npm_validation_prepared`、`npm_validation_step`、`npm_validation_finished` | `validation/npm-validation` | 验证 run、准备策略、`taskId/checkId/script/status`、检查结果 | 保留准备/步骤/完成事实，沿用既有结果折叠规则 |
| 其他未列 kind | 外部宿主通知/既有兼容事件 | 原通知 body | 默认保留；不基于未知 kind 猜测展示性质 |

盘点重点：当前唯一 `activity` 生产方只写展示说明，无执行成功、审批或交付状态。没有把“含错误字段的任意事件”统一删除。`memory_recalled` 和 `compacted` 有明确事实字段，本轮保留全程可见，避免旧逻辑在年龄增长后退出；未引入新的事实事件种类。原始事件不删除，legacy 布局仍可用。

## 验收与后续工作

测试走真实解析器、HTTP/SSE、SQLite 账本、context GET、生产模型投影和主循环。覆盖标准/原生/一致/冲突、拆分快照、零/非法/安全整数、部分流失败、来源重建、原子结算、旧行与成对覆盖率，以及含预算事件的超过 8 条追加。复用历史实测的 `assistant/activity/{content}` 与 `system/context_budget` 结构，最终请求诊断确认 activity 从首轮不存在，追加后无此类 remove；文件池仍可触发 rewrite。

测试结果和自审见 [实施自审](../../协作/审查/2026-10/2026-10-30-R3-P0P1实施自审.md)。这些验证不证明真实供应商缓存命中率提高。

后续按 R3 继续：

1. **P2**：独立模型投影、持久化帧与恢复；固定头/工具基础目录/检查点/追加 EVENT/动态 CURRENT_STATE；指令首次、变更、撤销及压缩退出后补发；同代结果冻结、明确切代、legacy 回退及实时权限校验。
2. **P3（与 P2 共同验收）**：实际发包诊断新增稳定核心/动态尾部、generation 与声明破坏边界；保留已有事件移除/重排和字节证据。当前 `usageDetails` 是计量元数据，不等于 P3 稳定投影诊断。
3. **P4**：压缩接入稳定检查点，抑制同一有效输入的失败/无收益重复压缩；同任务、同模型配对实验，比较正确性、总 Token、补读、耗时、前缀和压缩恢复。真实 DeepSeek/其他供应商收益尚待验证。

原生多消息/工具协议迁移、隐藏推理采集、缓存保温、供应商显式缓存、自动费用引擎均未纳入本次实现。
