## 运行与配置

`runtime-contract.ts` 定义运行输入和句柄；`cli-runtime.ts` 只管理旧 CLI 通信；`runtime-controller.ts` 管理持久绑定、状态、指导、用量与续聊资格；`runtime-interactions.ts` 管理问题/审批的持久状态。`codex-app-server.ts`、`claude-agent-sdk.ts` 实现新通道，`native-runtime.ts` 提供事件通道、问题桥与进程树关闭。control-plane 保留任务、权限、预算、worktree、mailbox、验证和一次业务收尾。

- 员工种类不变，backend 为 cli/codex-app-server/claude-agent-sdk；不复制员工身份。缺设置行视为 cli/0。改设置要求 expectedVersion；活跃、排队、待批准、停止未知任务存在时拒绝修改。保存同步递增已有能力档案版本，原有计划配置校验仍生效。
- 原有 `agentProviders.prepare` 继续隔离供应商密钥。Codex 复用其 -c 配置，模型单独传到原生 thread/turn；Claude SDK **必须先绑定 Anthropic Messages 供应商**，支持既有 API Key/Bearer 编码，不代管本机订阅登录。SDK env 按 Run 传入，不改 process.env。
- Claude 的配置与历史位于应用数据目录 `native-runtimes/claude/<employeeId>`，不复制用户认证文件。`settingSources=[]`，关闭 hooks，保留宿主已加载的项目指令。仅开放 Read/Glob/Grep/Edit/Write/Bash/AskUserQuestion，不加载外部 MCP、厂商子 Agent 或浏览器。SDK 延迟加载，CLI 路径不初始化 SDK。
- Codex 沿用现有 CODEX_HOME/CLI 默认配置根及认证选择，独占 App Server/thread；不读取认证文件正文。使用 `project_doc_max_bytes=0` 避免重复自动注入宿主已提供的项目规则，`agents.enabled=false` 与兼容开关 `features.multi_agent=false` 关闭内部子 Agent。其余用户/系统配置仍受 Codex 自身优先级与托管策略约束，不能把这些开关称为 OS 文件隔离。
- Run 保存配置指纹、实际观测的运行时/SDK 版本、工作区及原生会话关联。指纹含员工、任务/计划、供应商公开版本、模型/能力/运行方式、项目和员工权限、执行文件路径/大小/修改时间；不含密钥。版本未上报时为 null。启动准备与每次新指导/回答/延续重新检查现有准入。

官方接口依据：[Codex App Server](https://learn.chatgpt.com/docs/app-server)、[项目指令配置](https://learn.chatgpt.com/docs/config-file/config-advanced)、[原生子 Agent 开关](https://learn.chatgpt.com/docs/agent-configuration/subagents)、[Claude SDK TypeScript](https://code.claude.com/docs/en/agent-sdk/typescript)。D0 使用本机生成的 JSON Schema 核对必需方法，不手改或提交生成物；SDK 固定依赖与许可证见 package-lock/THIRD_PARTY。本轮没有复制 emperor-agent 源码。

## 状态与停止证据

原生回合完成后，先检查已接受的排队输入：还有输入则继续本 Run 的下一回合；否则进入 closing，关闭原生进程树，取得证据后才保存报告、更新任务终态、结算和推进 DAG。重复回合完成不会重复输出或收尾。原生 outcome 与实际 exitCode 分开，不能把关闭进程的退出码伪造成 0。执行 completed 只表示可进入验证，accepted 仍走原验收。

| stopEvidence | 含义 |
| --- | --- |
| root_exited | 旧 CLI 的根进程已退出，保留原契约；不等于本轮新增的完整后代证明 |
| quiescent | 新后端在根仍活跃时执行 Windows taskkill /T /F（POSIX 为独立进程组终止），并观察到根 close；本机已验证普通后代终止 |
| unknown | 意外断连、根先退出、启动/关闭或后代停止无法确认；不能冻结为成功交付，保留原恢复/预算未知要求 |

原生 interrupt ACK 不作为停止证明。停止先拒绝新输入、取消本地未处理队列并使交互失效，再中断/关闭。服务正常退出尝试关闭新后端；崩溃后绑定、待交互、未确认投递转为未知/失效，不重接旧回调、不自动推理。既有未知 Run 仍须人工检查。

等待问题/审批期间暂停 agent-health 沉默探测及 coordinator/autonomy 的进度催询，运行总期限不延长。交互最多 15 分钟且受原运行总期限约束；过期请求拒绝旧回答并请求停止。本轮不保证主动脱离受管进程树的外部守护服务停止，也不新增 OS 沙箱；实际模型工具链仍需真实验收。

## 数据与 HTTP

增量附表：employee_runtime_settings、agent_run_bindings、agent_runtime_turns、agent_runtime_interactions、agent_runtime_deliveries、agent_runtime_continuations。迁移幂等，不回填旧 session/用量，旧记录显示为旧 CLI、原生历史未知。新记录随 Run/消息归属级联清理；应用不新增原生历史自动删除。回退保留附表，不删历史。

所有接口沿用现有本机 owner 认证、请求体限额和错误出口。路径参数仅为 ApiX ID，不接受原生路径或会话 ID。原生会话标识、配置指纹、env 和凭据不返回展示 API。

| 接口 | 契约 |
| --- | --- |
| POST /api/employees/:id/runtime-settings | backend、expectedVersion；新后端须 acknowledgeExperimental=true；只影响后续新 Run |
| GET /api/runs/:id/runtime | backend/phase、能力、公开版本、回合、投递状态、待处理数、停止证据、候选恢复可用性 |
| GET /api/runs/:id/runtime-events | afterId/beforeId 互斥；默认 100、最大 200；游标绑定本 Run；items/nextCursor/hasMore；只读、不重放 |
| POST /api/runs/:id/messages | requestId、content（最多 16000 字符）、mode=steer/queue；Codex 支持两者，Claude 仅 queue；CLI 不支持直投 |
| GET /api/runs/:id/interactions | 脱敏的当前与已处理问题/审批、权限快照、期限及接收状态 |
| POST /api/runs/:id/interactions/:interactionId/answer | requestId、answer、expectedPermissionVersion；question 用对应问题的 answers，approval 仅 decision=approve/deny，不接受新增工具/目录/env；Codex 仅桥接 command/file 的操作审批，未知请求明确拒绝，不授予整轮新权限 |

新运行的公开事件使用 schemaVersion=1、Run 与宿主事件 ID；只保存文本输出、公开工具摘要、回合、交互和用量事实，不保存私有思考。旧厂商原始事件在新展示分页中仅给类型摘要，原诊断入口保持原行为。运行中凭据在写公开事件/输出前脱敏；usage 原字段另保存在回合记录，不从展示文本反推。

RUNTIME_UNSUPPORTED/INVALID_CURSOR/INVALID_ARGUMENTS 为 400；不兼容、停止后输入、旧回合、交互过期、权限变化、幂等冲突、投递未知为 409。错误使用既有 ToolError 封装，无额外服务器。

## 指导、问题与用量

指导保存到原 mailbox，建立直投记录并由宿主 ack，避免再次普通领取；accepted/queued 不自动 complete。协调会话和主助手的既有 guidance 入口同样接到直投服务；协调面板显示单独的 nativeDelivery，不把宿主 ack 误称员工已处理。

同 Run 的 requestId 与正文/模式指纹幂等，同 ID 不同内容拒绝。saved/accepted/queued/processed/rejected/unknown/cancelled 各自展示；processed 只表示所在回合已结束，不证明逐条指导语义已满足。可能已接收时保留 unknown，相同 ID 重试只读旧记录，不再发原生输入。问题回答同样先保存处理状态，再交给运行时；重复同答案不再次回复，旧 Run/旧权限/过期请求拒绝。

员工用量继续写 apix_run_usage，来源 native-turns。每个宿主回合保存已知原生计数字段及 source/basis；异常计数保留 null，其余厂商字段不落库；重复快照替换，回合间汇总，不重复累计 Claude assistant 与 result。Codex 采用当前回合 last 快照，thread total 不相加；Claude 输入为 input_tokens+缓存读+缓存写。任一必需字段缺失时该汇总保留 null，不补零。费用和真实账单仍未知；同一 Run 的多轮持续占用同一预算预留。

## 续聊、工作台与回退

现有任务 recovery 增加 continuation=fresh/native（默认 fresh）与 resumeFromRunId。native 必须同任务/员工/backend、兼容配置及工作区、旧运行 quiescent、有原生会话记录；原有代码指纹、依赖、需求、权限与批准检查继续生效。原生历史是否实际可读在 thread/resume/SDK resume 中再次验证，失败不静默改为 fresh。创建新 Run、新 mailbox 凭据、新预算；旧交互、指导和凭据不复用。自动修复/改派保持 fresh；accepted 任务不能续改。

员工设置提供逐员工试验开关。2026-10-30 首版只提供主会话输入区附近的员工行与弹出 Run 面板，未完整呈现主会话工作台；2026-10-31 补齐布局与连接，不能把首版记录当作完整前端验收。

“与 ApiX 对话”的顶部固定展示协作工作台和管理员工入口。没有子流程时明确显示尚未委派；有子流程时展示实际员工任务、员工名称与运行来源、状态、用时、待处理数量。未启动的任务不提供虚假的 Run 入口；选中行绑定明确的任务与 Run。切换主会话清除旧员工行和已打开面板，旧异步响应不得回填新会话。

点击员工行后，窗口宽度至少 1100px 时在主会话旁打开过程与成果面板；1280px 保持主会话输入与成果入口同时可见。1800px 起面板内部的过程、成果分列；较窄桌面纵向组织两者，提供“成果与检查 / 返回过程与互动”快捷定位。小于 1100px 使用原生对话框抽屉，隔离背景焦点；关闭或 Escape 返回员工入口。员工详情及任务历史仍使用统一 Run 对话框。原有“交付与详情”与员工面板互斥，避免同时挤入三个详情区。

Run 面板显示按回合折叠的公开过程、指导、问题/单次审批、投递状态，以及代码差异、宿主检查和原验收/恢复入口。没有宿主检查记录时明确标“未验证”；员工报告不替代检查证据。展示仍读取既有接口，不新增批准、验收或运行事实源。

历史与增量共用纯折叠函数，按 Run+事件 ID 去重；旧异步响应有选择代次检查。文本增量只更新对应节点，展开状态及指导草稿不随轮询重建。接近底部才跟随；读取失败有重试，未活跃时停止普通轮询；有分页缺口继续补读。宽窄切换移动同一份面板 DOM，保留问题输入、指导输入和展开状态；切换员工按 Run 保留未发送指导及其重试标识。主会话 DOM 不重建，保留草稿与阅读位置。指导草稿仅在当前页面内存中，刷新不会恢复。沿用现有 HTML 前端、配色和身份记录，不引入新框架。

回退顺序：停止并核对活跃 Run → 将后续员工设置改回 cli → 验证新 CLI 任务和旧历史可读。旧二进制不支持新交互 API，必须先切回 CLI；不是在同一 Run 中自动换后端重试。副本回退脚本以本轮基线构建旧服务，验证读取升级库、运行新 CLI 任务及保留新表。
