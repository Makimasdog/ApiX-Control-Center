## 1. 本次决策与当前基线

## 3. 最终请求诊断的三个层次

### 3.1 测量对象

| 层次 | 计算依据 | 能证明什么 | 不能证明什么 |
| --- | --- | --- | --- |
| Wire | 最后一次 JSON.stringify 得到、实际传给 request.end 的 UTF-8 bodyText | 请求体哈希、字节数与字节公共前缀；参数是否变化 | 供应商实际渲染模板、分词或缓存键 |
| Logical input | 同一个 prepared 请求中的固定 system 与实际 prompt 文本；辅助描述绑定 promptSha256 | prompt 文本公共前缀；变化落在哪个宿主区域 | 不能把该字节数换算成真实缓存 token |
| History frames | 同 generation 中两次共同携带的帧 ID、内容哈希和顺序 | 追加、删除、重排、正文改写是否发生 | 尾部变化不应被混成历史改写 |

保持三个哈希：wireBodyHash、logicalInputHash、carriedHistoryHash；分别计算 wireBodyPrefixBytes、logicalInputPrefixBytes。请求参数变化单独列出允许的字段名（如 reasoning_effort、max_tokens、stream、缓存控制），不把参数值自动灌入日志。

精确定义：wireBodyHash=SHA256(bodyText的UTF-8字节)；promptSha256=SHA256(prompt的UTF-8字节)；logicalInputHash覆盖带类型标签/长度边界的adapterSystem与prompt，防止无分隔拼接歧义；logicalInputPrefixBytes只比较实际prompt文本，固定system另算systemHash。这些都是本地表示，不是供应商模板渲染后的token序列。

不对 legacy 请求体做排序、删字段或规范化后再发包。诊断阶段必须证明**开关前后请求体逐字节相同**，才有资格作为观测基线。

### 3.2 改动区域的归因

assistant 组装器为 prompt 提供有界的宿主区域描述：instruction、tool_catalog、checkpoint、history、task_state、memory_recall、reference_index、verification、budget、reply_contract。legacy 无法精确到细项时可返回 context/opaque，不能编造 eventId 或字节偏移。

精确字节偏移只来自内存中的真实字符串/Buffer 比较。JSON 转义会改变 wire 偏移，因此不能把 prompt 的偏移直接应用于 HTTP body。变化字段路径来自同一 prepared 对象/可信 builder，正文内同名字符串不得被正则误判为结构。字段级候选归因与精确字节偏移分别标注。

推荐输出 firstChangedRegion、firstChangedHostField、firstChangedEventId，以及 historyMutation=none|rewrite|remove|reorder|unknown。只输出宿主白名单字段名；不输出原文切片、命令参数、文件内容或用户自定义 JSON 键。

## 4. 准备、记账、发包与重试时序

### 4.1 与当前代码兼容的生命周期

当前顺序是 onAttemptStart → inferAttempt 构造 body → 创建 HTTP 请求 → request.end(JSON.stringify(body))。R2 采用：

```text
onAttemptStart(attempt)                   // 原有 pending 登记
try:
  prepared ??= prepareModelRequest(...)   // 第一次尝试准备并冻结，不开启网络
  onRequestPrepared(attempt, metadata)    // 附加到该 pending；同步可靠持久化
  if aborted / scope revoked: stop
  inferPrepared(prepared.bodyText, ...)   // 然后才创建 http(s)Request
finally:
  原有 onAttempt(...) 与实际传输清理       // 结算一次，错误优先级保持
```

prepare 必须保留直接配置验证、密钥存在性、端点验证、512 KiB prompt 限额、stream_options、reasoningParameters 等。业务内容在同 invocation 的重试期间冻结；timeout 可以随总 deadline 缩短，但不能重组 prompt 或改变发包参数。使用现有总超时，准备和持久化后再计算剩余时间，超时/中止则零发包。

RD-01 默认给有 session/usage 归属的 assistant_loop、format_repair、compaction 安装诊断回调；其他旧消费者没有回调时走原路径，不新增产品开关或环境变量。D01 的“开/关”由测试中是否提供回调控制。冻结的是 bodyText 与配置，不是每 attempt 的比较结论；重试诊断按当前 attempt 生成，不能把第一条 usage_id 或比较元数据复制给后续尝试。

准备失败时沿现有 try/finally 保存 failed attempt，usage 为已知值或 null；不是改成无账本的本地错误。onAttemptStart 本身失败维持原语义：无请求、不进入网络重试。准备失败不能被误归类为可重试供应商 5xx。

onRequestPrepared 位于 **httpRequest/httpsRequest 调用之前**，而不只是 request.end 前；构造 ClientRequest 也可能开始连接。回调失败必须使本次零连接、零请求，并通过宿主创建的 InferenceAccountingError 走现有阻断；不能仅 console.warn 后继续。

pending 登记与诊断附加可分成两个短事务。崩溃在两者之间时允许“pending 且诊断为空”，不能补造已发包。诊断附加必须校验 usage_id、attempt、session/project 和 status=pending；禁止修改另一次尝试。不得在网络期间持有 SQLite 事务。

### 4.2 接口草案

```ts
// 新增可选项；既有 inferModel(settings, prompt, onDelta?, options?) 不变。
interface PreparedRequestMetadata {
  schema: 1;
  apiType: string;
  wireBodyHash: string;
  wireBodyBytes: number;
  logicalInputHash: string;
  promptSha256: string;
  comparison: RequestComparison; // 下节契约，不含正文
}
interface InferenceOptionsExtension {
  promptDescriptor?: PromptDescriptor; // 宿主提供，含布局/分区/帧摘要
  onRequestPrepared?(attempt: number, value: PreparedRequestMetadata): void;
}
```

Store 当前同步写入，回调按同步 void 实施，不使用 fire-and-forget Promise。若选择异步存储，应显式升级为 Promise 并 await，补测拒绝路径，不能依赖 TypeScript 的 void 可赋值性掩盖未等待调用。

PromptDescriptor 至少含 schema、layout、generation（legacy 为 null）、promptSha256、固定区域摘要、有序 frame IDs/hashes、宿主配置代次与辅助调用关联；不含授权结论。模型返回同名字段不得成为描述信息。描述的 promptSha256 不匹配时停止，不把过期 spanMap 附到新请求。

建议只在 assistant 的 deps.infer 最后添加可选 descriptor 参数，透传 createAssistantInference → inferManager → options；旧五参数调用、coordination、legacy_director 继续使用原字符串路径，无 descriptor 时诊断标记 opaque。不得通过给 prompt 注入 ID 来传递关联信息。

共享纯类型可放在models的诊断模块；models不得反向导入assistant实现，宿主区域分类由assistant builder提供。prepared回调只能得到元数据，不能拿可变body对象再修改发包内容。

onAttempt 的 ModelAttempt 可增加可选 transportObservation，区分 request_created、write_completed、response_headers、terminal。write_completed 只表示交给本地传输，不代表供应商已收到/缓存。原有三协议 usage 累计快照、部分输出不重试、清理未知优先级必须保持。

## 5. 比较基线、持久化与访问边界

### 5.1 baseline 选择

主比较键为 session + 不透明 routeScopeId + purpose + layout。routeScopeId 根据可信的供应商配置引用/版本、模型、协议和认证配置代次生成；不存 URL、认证头、Key、Key 的直接哈希。配置版本不可用时，保守开启新比较范围，不猜测认证等价。进程外修改环境通常在重启后生效，重启比较基线置空；不为检测轮换额外哈希真实密钥。

比较前一条已观察到 response_headers 的实际尝试，不把仅准备成功或连接失败请求当作供应商已见基线。HTTP 错误响应可作为“请求已到达某服务”的基线，但不假设服务建立了缓存。对 first request、scope change、baseline eviction、restart 返回 baselineUnavailableReason，不伪造 0 字节共同前缀。

重试额外比较同 invocation 的首次 prepared 字节，应完全相同；它不更新正常回合的历史完整性基线。format_repair 和 compaction 使用独立 purpose；只有显式提供 auxiliaryOfUsageId 时再增加与主请求的辅助比较，不将其混进正常第 N 轮轨迹。

不同 generation 可比较固定头和实际字节，但历史连续性应标为 unknown/generation_boundary，不把合法检查点更替当成“未声明历史改写”。所谓稳定阶段还要求前后 generation 相同。

### 5.2 保存和内存边界

独立 `model_prompt_diagnostics` 表与 usage_id 一对一；不改 model_token_usage 原列。记录 prepared 摘要、baselineUsageId、scope/layout/generation、区域/帧哈希、变化枚举、两个公共前缀长度、诊断状态及传输观测。usage 仍是唯一 actual token 来源，不复制另一套可独立修改的真实用量。

精确 LCP 需要前一请求的内存字节。首版用有界 LRU，例如最多 8 个比较键且合计 8 MiB（候选内存保护值，测量后调整）；仅保留必要前一基线与正在比较的请求，不持久化完整请求。淘汰不影响推理，精确指标为 null 并说明 memory_budget。大正文的一次性在途内存不算“缓存无限可存”的借口。

哈希和变化元数据持久化后，重启可以看到历史记录，但没有字节基线就不能计算跨重启精确 LCP。稳定帧的哈希连续性可从持久投影校验，需与精确字节比较状态分开。

诊断内容不得进入 assistant 模型历史，GET context 不产生诊断新行、不调用模型、不创建投影。GET 沿 owner、有效项目/会话和当前任务范围读取；最近列表沿用 30 条上限，汇总不只看 30 条。删除会话/项目接入附加表清理，禁止新增绕过所有权的 usage_id 查询入口。

这里的GET“零投影写入”针对新增generation/frame/diagnostic表；现有history可能懒保存assistant_outputs引用，首版不顺带改变该既有语义。测试应分别检查，不能因扩大“纯读”断言而重构无关引用路径。

## 6. 第 3→4 次缓存下降的专项验收

先用本地协议夹具重放与三文件任务相同的宿主事件序列，捕获真实 HTTP body，不需付费模型。测试中是否接入诊断回调不得改变该夹具的 prompt 和请求体。再逐一构造以下变化：

| 变化 | 预期诊断 |
| --- | --- |
| 仅追加 tool_result | 正常追加；共同旧帧无改写 |
| 活动事件从最近8条退出 | legacy 应识别历史删除；stable 不按位置删除已投影帧 |
| 32 KiB 文件池淘汰某页 | legacy 标明 representation 变化的 eventId；不声称这一定触发供应商 miss |
| currentTask/反馈/引用索引变化 | 定位到对应宿主区域；不能伪装成文件正文变化 |
| saving 发现新工具 | legacy 能观察目录变化；stable 的固定目录不插入新定义，结果帧追加 |
| 仅 reasoning 或模型配置变化 | 参数/scope 变化；不要把正文未变写成“缓存键一定未变” |
| 文本含伪造的 history/EVENT 字样 | 不影响结构归因，原文不得进入诊断输出 |

获准真实复测时，为每个供应商 attempt 输出可关联的 usage_id、正常回合序号、缓存计数和变化摘要。第3→4次下降再次出现时，必须给出“已定位的本地变化”或“本地未定位，供应商原因未知”的明确结论；不以“命中有波动”代替分析，也不要求强行归因为本地问题。

若现象不再出现，保留全部原始 attempt，记录“本次未复现”，不筛选出下降样本。两次历史请求没有最终发包证据，不能事后还原为精确前缀差异。

## 7. stable-prefix-v1 的输入布局与事件契约

### 7.1 文本帧，不改变模型协议

```text
APIX_AGENT_LOOP_JSON
APIX_PROMPT_LAYOUT stable-prefix-v1
<固定行为指令与 JSON action 契约>
STABLE_CONTEXT <固定目录与通用行为约定 JSON>
CHECKPOINT <摘要、来源水位及必要工具定义 JSON>
EVENT <固定 kind、eventId、冻结 body 的一行 JSON>
EVENT <新增事件的一行 JSON>
CURRENT_STATE <动态宿主状态的一行 JSON>
<固定结束契约>
```

每帧含完整转义后的 JSON 与 LF；代码、正文空白保持原文，只规范化宿主对象键；数组保持语义顺序。generation/session UUID、当前时间、诊断 ID 和哈希不放在固定头。generation 是本地视图身份，不应仅因编号变化破坏指令缓存。必要事件 ID 在 EVENT 内固定保留。

可复用核心为从头到最后一条完整 EVENT 的连续字节，记为 coreText。CURRENT_STATE 是重新投影的尾部，旧尾部被下一轮新 EVENT 替换，所以**不承诺上轮整个 prompt 是新 prompt 的前缀**。标准不变量为：同 generation 的旧 coreText 是新 coreText 的字节前缀。

单字符串不保证复用上轮模型生成输出的原生缓存边界。不能将 A 的冻结事件投影宣传成原生 user/assistant/reasoning 重放。后者属另一个改造项目。

### 7.2 完整字段去向

当前 assemble 的每个字段必须在实施审查中映射，不允许“重构时顺手省掉”：

| 当前数据 | stable 去向 |
| --- | --- |
| instruction、固定目录、稳定工具/技能访问约定 | STABLE_CONTEXT；真实内容变化按明确边界换代 |
| context.instructions、项目规则与可变技能内容 | 按 R3 首次/变更时追加版本 EVENT，尾部明确当前有效版本；删除有撤销声明；检查点携带当前有效约束，无法可靠覆盖时保守换代 |
| summary / compacted_through | CHECKPOINT；当前代固定 |
| history | EVENT 帧；使用固定分类，不再调用位置相关 trimHistory |
| toolAccess、toolLimits、policy、capabilities | CURRENT_STATE；宿主执行仍实时复核 |
| currentTask、taskFeedback、latestUserRequest、initialRequest | 事件中保留原始用户意图；尾部仅给当前引用与必要任务状态，避免重复整段用户正文 |
| recalledMemories、memoryIndex、outputIndex | 有界 CURRENT_STATE 或现有按需读取，不重新注入固定头；不得丢掉现有关键约束 |
| needsVerification、hasVerification、verificationState | CURRENT_STATE 保留真实宿主事实，历史证据仍在 EVENT |
| contextBudget、contextReadPolicy | 预算在尾部；稳定的读策略放固定行为契约 |
| context 中其余字段 | 实施者逐字段列单，归入稳定/事件/尾部，不能笼统把整个 describe 结果固定或删除 |

### 7.3 固定事件分类与水位

- 必须保留用户 message、intent_confirmed、用户回复/纠正、审批决定、验收契约与交付反馈；不能只保留 kind=message 而遗漏选择和否决。
- tool_started/tool_result 及命令中间事件作为完整执行组；关联使用可信 operation/task/event 关系，不靠正文猜测。当前串行前提必须列入测试。
- 验证证据、completion_rejected、delivery_summary/record、process_unknown、知识/权限变动、恢复与错误事实不能因年龄静默消失；体积大的结果可采用有界投影，但宿主失败/未知字段必须保留。
- activity 可自始至终固定排除，不做“最近几条才发送”；context_budget、缓存诊断、optimization_changed 与投影维护事件固定排除。memory_recalled 审计与实际记忆正文分开，避免重复注入。
- 实施前盘点 assistant-loop、delivery、命令模块等所有事件生产方，提交事件种类→投影规则清单；未知 kind 不得默认为可丢弃。新 kind 若没有规则，拒绝生成该请求并报告 unsupported_event_kind。

读取按固定 event watermark 分页到结束。单页不足并不代表所有事件读取完成；保留现有200事件保护界限时应触发明确检查点，不得截掉第201条之后的数据。投影扫描游标与最后发送帧水位分开，排除的审计事件可以推进扫描水位但不能删除已发送帧。

GET/UI history 继续旧行为。新模型视图只在准备推理或明确手动压缩路径写入。

## 8. generation、存储与结果预算

### 8.1 新表与切换

推荐附加表：assistant_prompt_settings（独立策略配置）、assistant_prompt_generations（固定头/检查点/身份/当前代）、assistant_prompt_frames（eventId、sourceHash、renderedText/hash、去重依赖）、model_prompt_diagnostics。具体字段基于主方案并加入 active/current 原子指针或等价约束；外键和唯一性在一次性 SQLite 实测。

不向 assistant_optimization 加列，不修改原 mode 语义；旧行/缺设置行均为 legacy。generation 分配与当前项切换同一短事务、校验会话版本；并发准备不能各自 MAX+1 产生两个当前项。原事件/输出仍是事实源，帧是可重建的私有视图。

generation 切换原因固定枚举：layout_version、optimization_mode、instructions（通用指令或项目指令保守换代）、catalog_contract、model_route、credential_revision、compaction、explicit_strategy_switch、history_rewind、permission_scope_change。taskId/调用次数/面板刷新不自动换代。文件新版本作为新帧，不修改旧 read_file。

切换前检验 live 设置与固定快照版本。权限撤销优先中止，不为缓存继续发旧上下文；无法确认旧摘要没有已撤销资料时停止检查。静态指令比较内容哈希，不只比较大小/mtime；沿用有界读取，不每轮全库扫描。

### 8.2 冻结与预算，不照搬滑动文件池

首次进入模型时保存已选的 full/reference 表示，后续不因年龄重算。legacy 的32 KiB近期池继续原样存在；**stable 不把32 KiB解释为一代永久只能发送这些文件**，也不在新文件加入时把老帧从 full 改成 reference。

候选单页24 KiB规则计算的是序列化结果 UTF-8 字节，不保证20KB源码序列化后一定入池。read_file、read_context/read_output 的实际工作片段尽量完整保留；大普通日志/MCP结果首次做确定性有界投影，保留原引用和完整性事实。所有新帧、固定头、尾部及协议开销进入总上下文预算。

新增文件帧会超总预算时，先受控压缩旧完整执行组，再加入新帧；不通过先折叠新读结果、立即要求模型补读来解决。即使整理后仍无法容纳单页，应清楚返回需范围读取/缩小输入，不假装已读完整。

去重仅对当前可见代中内容、版本、范围、元数据完全相同的结果：后来的帧可指向前一正文帧。依赖目标必须实际在本代可见；不能跨代使用悬空 duplicateOfEventId。压缩/重建时若目标不保留，应从原事件恢复正文或重新绑定可见目标。去重不删除原事件，不阻止用户显式重读，不以路径相同认作版本相同。

保存 sourceHash 后源事件变化视为异常，停止而不是改写旧帧。投影保存失败只重建视图，不重执行工具；临时失败不按供应商可重试故障处理。

### 8.3 工具发现

standard 固定当前目录；saving 固定现有核心目录和初始 deferred 索引。search_tools 的完整参数定义作为完整结果帧追加，不再插回早期目录；其定义不得被通用4KiB预览截断后仍声称可用。

压缩保留有效、必要的已发现工具定义，超预算则显式标记需重新发现。MCP换身份/版本、权限撤销仍按实时 registry 阻止执行；缓存目录或旧发现帧不授予权限。P2仅开放 standard 组合；相关发现/压缩规则验收后才开放 saving。

## 9. 检查点、恢复、回退和 API

压缩固定有效事件水位与完整执行组；用现有推理链记录 compaction 成本。生成候选后验证确实缩小、有足够近期原文、用户约束和失败事实，并重新核对会话/权限版本。事务内提交新 generation 与既有 summary/compacted_through；不能只更新新表，导致回退 legacy 后恢复旧历史状态。

同代/有效水位压缩失败有持久失败记录，普通 resume、面板刷新、审计事件不解除抑制；显式手动压缩或有新的有效用户/工具输入才可重试。失败记录不进入模型历史、不制造新有效水位。

策略通过既有 optimization 接口扩展可选 promptStrategy。为避免旧客户端静默覆盖新设置，新增独立设置版本：GET 返回 promptSettingsVersion（缺行0）；POST 显式切换策略时同时提交 session version 与 promptSettingsVersion，冲突拒绝。旧客户端只保存 mode 时保留策略，不要求提交新版本；mode 变化仍触发下一安全边界换代。所有配置写入+事件+会话version在一个事务，运行/审批/委派/未知副作用状态拒绝切换。

保存成功的响应必须携带新的会话version与promptSettingsVersion；前端按当前会话/任务绑定更新，不能继续提交旧版本或跨会话复用设置版本。

GET context 只返回当前作用域诊断摘要、策略/设置版本与既有usage，未准备代时generation=null。不持久化新帧，不调用模型。缺少新字段时旧前端继续使用原路径，新前端在旧服务上隐藏扩展区域。

回退优先用新代码内切回 legacy：先确认在途调用与副作用→安全边界切换→保留原事件/用量/引用→继续。旧二进制降级另外在一次性旧库副本演练，不通过删除新数据降级。清理旧视图只能发生在新检查点可靠提交之后，且不删除原始证据。

## 12. 收益实验、推广与交接提示

基线应固定为当前 `legacy+saving`（含补读修复），主比较为 `stable-prefix-v1+saving`；standard单独比较，思考强度和模型保持不变。短三文件任务继续作为回归，新增自然包含较多轮次的定位/编辑/失败修复任务，以及跨32KiB/压缩/发现任务。不要为了命中率制造无意义调用或填充固定头。

至少分别报告：全部请求的token加权缓存占比、有命中的请求比例、同代稳定阶段占比、总输入/未缓存输入/输出/推理、补读/压缩/纠正/失败次数、任务成功率、总耗时与版本费率估算（若可得）。分母必须为同一有观测请求集合；unknown不填0，缓存与推理子项不重复相加。首轮不保证冷缓存；不能清缓存时明确uncontrolled。稳定阶段定义为同代至少存在一条合格基线、无边界变化的正常请求，不得事后只挑高命中段。

同任务交叉顺序重复，建议每类型先至少3次，预算不足则说明样本量。比较其他Harness时统一模型、端点、任务与口径，不能拿Qwen四请求新会话对比DeepSeek长会话宣传值。吞掉失败或只报告热阶段90%均不能通过E01。

候选推广条件沿主方案：硬门全通过、代表任务未观察到验收退化，任务总费用有可信下降证据；10%仅为候选产品门槛，不是预测或统计保证。费用/样本不充分时保持显式试验开关；如果前缀稳定却供应商收益不明显，交付调查报告而不是继续扩大重构。

接手Agent首先做RD-01，**不要从调大文件池、换模型、关思考、原生消息重写或接显式缓存开始**。基线变动先重读AGENTS.md与当前diff；不启动额外子Agent、不覆盖无关改动，不将本设计自审当作实现审查。真实数据迁移、部署、付费请求按用户实际授权处理；每阶段提交前重新审最终diff、调用方、失败路径、数据一致性及访问边界。
