# R3 P4：压缩持久抑制与跨恢复

日期：2026-10-30。**持久失败/无收益抑制、解除条件及本地跨恢复验证已实施；真实收益实验仅有草案，未授权、未执行。** 默认布局仍为 legacy，稳定布局继续显式开启；计价、原生消息和供应商缓存控制未扩展。

## 状态与入口

`context-compaction.ts` 为每个会话保存最近一次未成功压缩的状态。`assistant-loop.context` 仍按原预算和阈值判断是否需要整理，`compactHistory` 负责一次候选的准备、模型调用、校验与事务提交。

```text
需要压缩 → 同有效输入已有记录？
  自动：有 → 拒绝该次自动压缩，不调用模型
  手动：允许重新评估
→ 调用前保存 in_progress
→ 调用/解析/预算/候选校验/提交失败：failed 或 no_gain
→ 成功：同事务提交摘要、水位、稳定代/帧、compacted 事件并删除记录
```

进行中记录在模型调用前提交，所以调用中断或进程在响应后、检查点提交前退出，重开数据库后仍会抑制普通重试。`in_progress` 表示进行中或结果尚未确认，不声称供应商已收到请求。请求是否发送与用量仍以既有传输观测和账本为准。

无收益判定沿用 P2 的 **stable 候选实际渲染预算不小于原预算**，不提交该候选，记录 `no_gain`。legacy 也有失败/中断持久抑制，但保持原摘要验收行为，本轮不另加 legacy 的无收益判定，避免改动实验基线。共享请求重试规则不变：同一压缩 invocation 的受控传输重试仍按既有上限记账；抑制针对后续新 invocation，不抹掉已发生的失败/纠错/压缩消耗。

## 有效输入与解除条件

有效签名由旧 `summary/compacted_through` 和该水位之后所有有效事件的 `id/role/kind/body` 生成。按 200 条有效记录分页到结束，独立于模型视图的扫描水位、legacy 的 201 条读取批次和当前压缩前缀切分；只持久化 hash 与有效水位，不另存正文。generation 是尝试的来源元数据，**单独变更 generation、模型配置、窗口或优化模式不解除同输入抑制**。

| 可以形成新有效输入 | 生产记录 |
| --- | --- |
| 用户新消息、选择/审批回答、纠正、任务目标、记忆编辑、交付反馈 | role=user 的 message、request_answer、intent_confirmed、task_started、memory_edited、delivery_changes_requested、delivery_accepted |
| 工具、执行、验收或委派的新观测 | tool_result、file_edit_result、verification_contract、verification_evidence、command_finished、npm_validation_prepared/finished、delegation_result、supervision_event |

以下不会解除：resumed/stopped/restart_interrupted、error/process_unknown、context_budget/activity/optimization_changed、memory_recalled/compacted、model_retry/inference_accounting_failure、file/command recovery_checked、日志引用/失效审计，以及助手的 request/answer。它们仍按 P2 的事实分类进入必要的模型视图；不作为再次压缩的授权来源。未知 kind 也不会自动成为有效输入，stable 原有未知 kind 拒绝准备的规则不变。

解除方式只有：

1. 新增上述有效用户/工具观测后，签名改变，下一次真正需要压缩时可以尝试。GET 只报告旧记录不再适用，不主动删除或触发尝试。
2. 用户明确调用现有「压缩历史」（含原 session version 与安全门禁）时允许重新尝试。每个手动请求若失败仍留下新记录，后续普通恢复不会把这次明确操作变成持续授权。
3. 成功提交的检查点和抑制记录同事务清理；不是靠切换布局或清空 UI 绕过失败。

在预算以下且未超过保护数量时，主推理不受一条旧压缩记录全局阻断。stable 的 200 条保护按 `trimHistory` 后实际模型事件计算：被固定排除的三类记录仅推进扫描水位，不单独触发压缩；其他事实仍参与保护。legacy 的原计数规则保持不变。应用外修改规则文件或模型/窗口设置本身不算新增有效事件，需新增用户指示或显式手动压缩后再评估。

## 存储、失败与访问

新增 `assistant_compaction_blocks` 附表，每会话一行：

`session_id / input_signature / effective_watermark / checkpoint_through / generation / reason / created_at`。

会话外键物理删除级联；沿用 owner、项目/会话、软删除和已有恢复门禁。只存 hash、ID、原因枚举和时间，不存模型正文、凭据、端点或错误堆栈。记录不写为模型事件，不制造新的有效输入；会话原错误/恢复日志继续保留。

- 初始记录写失败：尚未启动压缩模型请求，直接停止。
- 失败原因更新失败：保留已经提交的 in_progress；保留原异常类别，尤其不覆盖 MODEL_CLEANUP_UNKNOWN/INFERENCE_ACCOUNTING_UNKNOWN 的更高优先级安全事实。
- 成功清理记录失败：回滚同一 SAVEPOINT 的摘要、水位、新代/帧和 compacted 事件；原检查点仍可用，外层保留失败记录。
- 会话停止、过期候选、权限/知识变更继续拒绝提交。记录不会绕过原账本或进程未知的恢复要求；显式手动重试也不授予额外权限或释放未知费用。
- 不补造历史失败记录；旧会话没有记录时仍按既有路径运行。记录不是累计失败审计账本，只保留最近未成功候选；完整用量与既有事件仍独立保存。
- 此处 legacy 指新代码中的现有布局；旧二进制不读取本表，降级重开不具备本轮抑制行为，不能将其当作同版本重启保护。

## API 与界面

`GET /api/assistant/sessions/:id/context` 新增可选 `compaction`：无记录为 null；有记录返回 `{blocked, reason, effectiveWatermark, generation, createdAt}`。blocked 表示最近记录是否仍适用于当前有效输入，不表示整个任务必须停下；reason 为 in_progress/failed/no_gain。GET 不写记录、不解除抑制、不调用模型，私有 signature 不输出到 UI。

上下文占用区显示“自动压缩已暂停”、原因及明确重试方式；新增有效输入时显示可重新评估。手动压缩失败后刷新只读状态，避免停留在“正在压缩”；旧服务缺少该字段时不显示新提示。刷新、普通恢复和服务重启不会自动执行手动重试。
