# ApiX 交互与执行重构决策（2026-10-22）

分支：`codex/apix-flow-model-project-refactor-20261022`。交付版本：0.2.0。

## 决策

需要按职责逐步重构，不整体推倒重写。当前问题主要出在两套对话入口并存、设置借用任务详情容器，以及相互独立的授权被串成了普通任务的前置步骤。底层已有任务隔离、预算、真实命令证据、重启恢复和验收契约，不应在界面整合时一起替换。

本轮完成“交互入口和模型配置分离、普通测试直达执行、扫描边界统一”。后续再根据真实使用证据拆分剩余控制器，而不是先更换框架或数据库。

## 百炼 404 的验证边界

用户选择使用百炼通用接口。本机全局配置已经是通用接口，但旧对话中保留过另一套专属服务地址及模型 ID。使用当前已配置的通用服务凭据，只对同一官方服务执行 GET 模型目录，返回 200，所选 `deepseek-v4.1-flash-1017` 在目录中。没有调用收费推理，也没有修改用户的历史对话、项目或 API Key。

目录可见不保证具体推理一定成功。旧对话先停止运行，再点击“使用当前应用配置”；这会更新该对话的服务、协议、模型与凭据引用，不修改历史消息。若仍返回 404，以新版错误中的实际请求路径和模型对应服务商配置继续核对，不擅自切换模型或重试收费调用。

参考：[阿里云错误码说明](https://help.aliyun.com/en/model-studio/error-code)、[部署介绍](https://help.aliyun.com/zh/model-studio/model-deployment-introduction)。官方文档将模型不存在、端点和模型不匹配列为需要核对的情况；专属部署的模型标识以实际部署为准。

## 入口和权限

- “与 ApiX 对话”：唯一主要任务入口，读取项目、运行已有测试、修改和检查代码，必要时再委派。
- “管理总览”：聚合真实状态，跳转已有工作，不另建第三套执行循环。
- “应用与协作设置”：应用默认模型、项目执行方式、调度与预算；多 Agent 持续协作属于高级可选配置。
- “多 Agent 任务（高级）”：保留既有计划与委派流程及历史，用于确实需要员工并行和冻结模块契约的任务。
- 侧栏“新对话”进入主 Agent；历史记录标注对话/高级任务并使用可理解的状态文字。

自动执行复用已有项目权限 API，带权限版本进行乐观检查，并在发送前检查项目是否切换。它允许当前项目的文件工具和命令测试，不会注册员工、开启工作流、增加费用预算或代替可信验收。停止、只读、失效授权、并发写入、费用约束、MCP 启用与可信契约仍按已有边界处理。

真实代码修改后的可信验证和正式验收继续区分；本轮不以“少点击”为由把任意退出码 0 或模型回复当作验收通过。运行一个既有测试且未修改源码，可以直接完成诊断，不需要先搭建员工系统。
