# 管理总览设计

## 参考与定位

信息架构参考 [Claw Empire](https://github.com/GreenSheep01201/claw-empire) 的 Dashboard、Kanban、Agent Detail 和评审路径：用户先看到整体状态，再进入具体任务、员工和决策。ApiX 使用自己的浅色、简洁界面，不使用像素办公室、角色动画、经验值或排行榜，也未复制参考项目的代码与素材。

ApiX 是管理者 Agent。Pi 是它的推理底座，同时可以作为独立员工运行；二者的身份与授权分开。总览用于监督，创建目标和修改任务仍进入 ApiX 目标工作台。看板不允许拖动任务改变执行状态，也不提供绕过需求确认和权限审批的直接派发。

## 页面结构与数据

1. **项目概况**：当前项目的目标、执行中任务、用户待处理事项和参与员工数。
2. **ApiX 等待你的决定**：澄清、需求确认、计划审查、交付验收和异常处理。点击进入对应目标。
3. **员工动态**：展示当前项目计划中的员工及运行任务数；点击进入员工详情，查看用量和历史。
4. **任务流转**：按待启动、执行中、待验收、需处理、已完成显示当前计划任务；支持文本和员工筛选。任务卡片进入所属目标。

目标与派发关系来自 `/api/coordination/sessions?projectId=…`。项目、任务和员工状态来自 `/api/snapshot`。看板只显示当前项目且关联到 ApiX 目标当前计划的任务。任务状态由持久化的运行和验收流程提供，总览只读呈现，不能通过界面假造完成状态。项目切换会立即清空上一项目的目标数据；异步响应仅在项目和请求版本仍匹配时应用。

## 后续扩展边界

可以进一步增加跨项目组合视图、项目范围的员工编组和事件流驱动刷新。当前概况按单个项目统计；员工仅在参与该项目计划后出现。实时性取决于现有 snapshot 轮询（约 1.5 秒）及目标列表请求，不代表运行时进程的逐毫秒状态。
