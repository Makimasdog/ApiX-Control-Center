## 实施顺序

| 阶段 | 实施与验收 | 预估 | 依赖 |

## P0 数据与隐私

1. 会话上下文继续使用 SQLite 中的 assistant_sessions 与 assistant_events、现有上下文压缩和会话管理 API。个人记忆不会从对话、项目或工具输出自动采集。
2. 工作记忆使用本机 apix.sqlite 的 personal_work_memory，单条记录是带标题、正文、版本、召回开关和到期时间的 JSON 文档。
3. 长期记忆使用 APIX_DATA_DIR 下 personal-memory/<UUID>.md，正文为 Markdown，首部为 JSON 元数据。应用通过同目录临时文件替换写入。两种持久层各有一个权威数据源。
4. 个人记忆归本机所有者，可在不同助手会话显式召回。ApiX 的个人记忆 API、UI 和召回路径不调用外部模型或云存储，条目也不会自动进入模型上下文、工作台快照、员工任务或工具结果。
5. 关闭条目召回或到期会立即排除后续召回。删除会移除 SQLite 记录或长期文件。原始对话、用户导出的副本、已有备份、SQLite 日志及磁盘残留遵循各自的保留方式。

关键词召回复用现有英文词和中文双字匹配，按相关性返回最多五条且正文合计不超过 6000 字符。会话召回仅使用该会话最近一条用户消息作为查询。个人记忆面板可独立按关键词查询。

## P0 HTTP 接口

所有端点使用本机所有者认证。以下路径相对于 /api/personal-memory。tier 为 work 或 long-term。

| 方法与路径 | 用途 |
| --- | --- |
| GET / | 列出个人条目，包含停用和到期记录 |
| GET /{tier}/{id} | 读取条目 |
| POST /{tier} | 新建，服务端生成 UUID |
| POST /{tier}/{id} | 修改，提交 version、title 与 content。省略召回开关或到期时间时保留原值。 |
| POST /{tier}/{id}/delete | 以 version 删除 |
| POST /recall | 用 query 关键词召回 |
| GET /sessions/{id}/recall | 用已有助手会话的最近用户消息召回 |

标题上限 120 字符，正文上限 3000 字符，查询上限 10000 字符。新条目 recall 默认为 true，expiresAt 默认为 null，可提交 UTC ISO 8601 到期时间。不存在的条目或会话返回 404，过时的修改和删除返回 409，格式无效返回 400。

当前为手工维护的小型记忆集，列出和召回会读取完整记忆集。长期文件由应用管理，编辑请使用 UI 或 API。受信任的本机进程仍受操作系统文件权限约束。多个 ApiX 实例共用同一数据目录不在本阶段验收范围内。

## P0 验收方式

执行 npm run build、npm run check，再运行 node --test --test-concurrency=1 test/personal-memory-http.test.mjs test/project-memory.test.mjs test/assistant-loop.test.mjs test/token-usage-http.test.mjs。浏览器中打开助手标题栏的「个人记忆」，分别新增、修改、停用、召回和删除工作与长期条目。
