# 项目目录与文件归属

从 [文档导航](README.md) 找使用和设计说明；从 [代码索引](参考/代码索引.md) 找具体模块。

```text
ApiX-Control-Center/
├── server.mjs              # HTTP 服务入口、API 路由
├── control-plane.mjs       # 依赖装配、SQLite 与执行桥
├── agent-discovery.mjs     # 本机运行时发现
├── src/                   # 后端模块，目录说明见 src/README.md
│   ├── assistant/         # 主 Agent、工具、上下文、编码与交付
│   ├── models/            # 模型协议、供应商与对话配置
│   ├── execution/         # 命令托管、日志、Windows 支持文件
│   ├── agents/            # 员工 CLI 适配、设置和事件
│   ├── coordination/      # 需求、规划、调度、契约与协作任务
│   ├── messaging/         # 消息信箱
│   ├── projects/          # 项目身份、基线、交接与检查 Worker
│   ├── validation/        # Node/npm 接入与托管验证
│   └── infrastructure/    # 环境加载与静态文件映射
├── web/
│   ├── index.html         # 工作台页面
│   ├── agent-os.js        # 现有页面交互脚本
│   ├── styles/            # 页面样式
│   └── *.ts               # 前端功能模块
├── test/
│   ├── *.test.mjs         # 自动回归
│   ├── *fixture*.mjs      # 隔离夹具
│   └── manual/            # 手工验证页面和说明
├── scripts/               # 脚本说明见 scripts/README.md
│   ├── evaluation/        # 编码任务及评测
│   ├── verification/      # 浏览器、真实协作及自主执行验证
│   └── diagnostics/       # 独立能力诊断
├── docs/                  # 当前使用、设计、开发说明
│   ├── 参考/              # 具体协议、模块与工具说明
│   ├── 归档/              # 有日期/版本边界的历史资料
│   │   └── 历史补充/      # 原根目录 Wiki、功能说明和简历素材
│   └── 附录/              # 面试等非产品资料
├── 协作/                  # 计划、审查、验收原始证据
├── 示例/                  # README 展示截图
└── dist/                  # 构建输出，不提交
```

根目录保留启动装配入口、包配置、许可证、README 和 Agent 规则。`架构设计文档.md` 是旧链接兼容入口，正文只在 `docs/架构设计.md` 维护。三个服务端入口暂不拆分业务逻辑；目录整理不承担 Runtime 重构。

src/scripts 内部责任边界分别见 [后端模块导航](../src/README.md)、[脚本导航](../scripts/README.md)。新增实现归入所属领域，不在两者根目录继续平铺。

前端源文件已归入 `web/`，浏览器仍请求 `/index.html`、`/agent-os.js`、`/*.css` 和 `/dist/web/*.js`。`src/infrastructure/static-files.mjs` 将公开 URL 映射到固定文件；不会公开整个 web、docs、test 或 src 目录。新增页面资源时在映射中明确登记并验证访问边界。

当前说明写在 docs，历史补充只保留原文与原日期，不代表当前功能验证。新增审查和截图继续放协作，不复制到源码旁。手工测试页不通过生产服务公开。

`node_modules/`、`dist/`、`.tmp*/` 和本机 `.env` 是依赖、生成物或本地数据。本次整理保留它们；需要清理时先核对活动任务和证据引用，不直接批量删除。`.claude/`、`.qoder/`、`.archify/` 等工具目录各自保留。
