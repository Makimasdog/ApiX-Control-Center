从 [文档导航](README.md) 找使用和设计说明；从 [代码索引](参考/代码索引.md) 找具体模块。

│   ├── models/            # 模型协议、供应商与对话配置
│   ├── execution/         # 命令托管、日志、Windows 支持文件

│   ├── coordination/      # 需求、规划、调度、契约与协作任务

根目录保留启动装配入口、包配置、许可证、README 和 Agent 规则。`架构设计文档.md` 是旧链接兼容入口，正文只在 `docs/架构设计.md` 维护。三个服务端入口暂不拆分业务逻辑；目录整理不承担 Runtime 重构。

src/scripts 内部责任边界分别见 [后端模块导航](../src/README.md)、[脚本导航](../scripts/README.md)。新增实现归入所属领域，不在两者根目录继续平铺。

前端源文件已归入 `web/`，浏览器仍请求 `/index.html`、`/agent-os.js`、`/*.css` 和 `/dist/web/*.js`。`src/infrastructure/static-files.mjs` 将公开 URL 映射到固定文件；不会公开整个 web、docs、test 或 src 目录。新增页面资源时在映射中明确登记并验证访问边界。

当前说明写在 docs，历史补充只保留原文与原日期，不代表当前功能验证。新增审查和截图分别放协作的月度审查与截图子目录，不复制到源码旁。手工测试页不通过生产服务公开。

`node_modules/`、`dist/`、`.tmp*/` 和本机 `.env` 是依赖、生成物或本地数据。依赖和本机配置保留；旧临时产物集中到 `.tmp/archive/`，需要清理时先核对活动任务和证据引用。`.claude/`、`.qoder/`、`.archify/` 等工具目录各自保留。

## 临时产物

- 新增本地日志、缓存、浏览器证据统一放 `.tmp/logs/`、`.tmp/cache/`、`.tmp/reports/` 或 `.tmp/work/`，不再新增根级 `.tmp-用途`。这些内容由现有 `.tmp*/` 规则忽略，不提交数据库、凭据或缓存。
- `.tmp-desktop/` 是现有桌面打包与安装包的固定位置，保留原位。重新打包可能覆盖构建内容，需要保留的发布物另行复制保存。
- 旧脚本仍可能创建根级 `.tmp-*`。确认相关测试或任务结束后，先预览再归档：

```powershell
powershell -NoProfile -File scripts/maintenance/archive-local-artifacts.ps1 -WhatIf
powershell -NoProfile -File scripts/maintenance/archive-local-artifacts.ps1
```

脚本只收拢根级 `.tmp*`，排除 `.tmp/`、`.tmp-desktop/` 和链接；不停止进程、不删除文件、不覆盖同名目标。结果和逐项日志在 `.tmp/maintenance/archive-*.json`，旧内容在 `.tmp/archive/时间戳/`。运行中的数据应先停止相关任务再归档，文件占用导致的失败会保留原项并报错。

需要恢复时，按日志的 source/target 将单项移回项目根目录，先确认原位置不存在且相关进程已停止。历史报告中的 `.tmp-*` 是当时的证据路径；优先找已提交的截图/验收 JSON，再按归档日志查本机原件。归档没有释放磁盘空间，本机归档不会随 Git 同步。
