# 03 · 关键类与函数

> 本项目的“类”很少，绝大多数模块采用**闭包工厂**（`createXxx(deps)` 返回一组方法）和**纯函数**。这样做的目的是把状态封闭在作用域内、把依赖显式注入、便于测试时替换真实依赖。

## 1. 核心类型契约

定义在 [contracts.ts](../../src/coordination/contracts.ts)，被所有协调层模块引用。

| 类型 | 字段/取值 | 用途 |
| --- | --- | --- |
| `PermissionMode` | `full_access` / `ask_approval` / `read_only` | 项目级权限三档 |
| `InteractionMode` | `structured` / `conversational` | 需求澄清方式 |
| `RequirementField` | `goal` / `scope` / `constraints` / `deliverable` / `acceptance` | 需求五字段 |
| `Requirements` | `Record<RequirementField, string>` | 需求对象 |
| `RequirementAssessment` | `score`、`threshold`、`missing`、`conflicts`、`ready` | 需求就绪评估 |
| `PlanStep` | `prompt`、`employeeId`、`dependsOn`、`moduleId?`、`scheduling?` | 计划步骤（`dependsOn` 是零基索引，保证 DAG 无环） |
| `Employee` | `id`、`name`、`role`、`runtime`、`enabled`、`capabilityProfile?` | 员工（一个 Runtime 可注册多个岗位） |
| `Task` | `id`、`project_id`、`plan_id`、`employee_id`、`runtime`、`prompt`、`status` | 一次员工执行的持久化状态 |
| `Session` | `id`、`project_id`、`title`、`status`、`requirements_json`、`revision`、`confirmed_revision`、`plan_id`、`interaction_mode` | 协作会话 |
| `Store` | `db`、`row<T>()`、`rows<T>()`、`now()` | SQLite 访问抽象 |
| `ModelBackend` | `infer(prompt, onDelta?, context?)` | LLM 推理抽象 |
| `InferenceContext` | `sessionId?`、`projectId`、`purpose`、`onTool?` | 推理审计与计费上下文 |
| `CoordinatorDecision` | `kind`、`question`、`updates`、`conflicts`、`mode`、`error?` | 主 Agent 的结构化决策 |
| `AgentCapabilities` | `available`、`managed`、`observable`、`cancellable`、`resumable`、`stateSource`、`mailbox?` | UI 与调度用的能力声明 |
| `DomainEvent` | `sequence` 等（见 `contracts.ts`） | 事件账本记录 |

配套校验工具：

| 函数 | 签名 | 行为 |
| --- | --- | --- |
| `parseJsonObject` | `(raw: string) => Record<string, unknown>` | 先直接 `JSON.parse`；失败后用括号匹配提取唯一顶层对象；空串、多个对象、括号不匹配都抛 `SyntaxError` |
| `text` | `(value: unknown, max = 10000) => string` | 非空、去首尾空白、长度上限校验 |
| `object` | `(value: unknown) => Record<string, unknown>` | 断言为普通对象 |

## 2. 助手层工厂函数

### 2.1 `createAssistantLoop(deps)`

位置：[assistant-loop.ts](../../src/assistant/assistant-loop.ts#L102)。依赖 `deps` 至少包含数据库 `Store`、推理、工具执行、项目根目录、子流程查询/停止、MCP 发现、记忆、命令状态等能力。

返回对象（源码 `return` 于 L528）：

| 方法 | 作用 |
| --- | --- |
| `create(input)` | 新建助手会话 |
| `list(projectId)` / `details(id)` | 会话列表 / 聚合详情 |
| `message(id, input)` | 发送用户消息并驱动主循环 |
| `reply(id, input)` | 回答 `ask` / `clarify` 挂起请求 |
| `stop(id)` / `resume(id)` | 停止 / 检查后继续 |
| `tick(childId)` / `notify(childId)` | 子流程事件唤醒与防抖 |
| `contextInfo(id)` / `compact(id, input)` | 上下文占用 / 压缩历史 |
| `setOptimization(id, input)` | 标准 / 节省模式切换（带版本校验与事务） |
| `notes` / `remember` / `editMemory` | 项目记忆 |
| `eventPage(id, ...)` | 分页读取事件 |
| `startTask(id, input)` | 结束当前任务并开始下一任务 |
| `delivery` / `deliveryFile` / `reviewDelivery(id, input)` | 交付物、文件读取、验收决定 |
| `readOutput(id, args)` | 按 `outputRef` 回读完整工具结果 |
| `projectDiagnosis` / `npmProposal` / `approveNpm` | Node/npm 只读诊断与准备方案 |
| `isBusy(id)` | 单会话互斥状态 |

主循环内部关键步骤：`assemble`（上下文）→ `infer`（模型）→ `parseAction`（动作）→ `governed tool`（治理后执行）→ `result`（摘要/折叠）→ 循环；`finish` 后进入交付与验收流程。

### 2.4 验收与交付

| 函数 | 签名 | 作用 |
| --- | --- | --- |
| `verificationContract(root, input)` | 生成验收契约与版本哈希 | 固定检查脚本、参数、超时、可写路径 |
| `contractCurrent(root, c)` | 判断契约是否仍有效 | 文件变化后必须重新批准 |

`reviewLimits`：3000 项、8 MiB 扫描，文本 256 KiB/文件，交付资料 24 MiB/份、合计 128 MiB、保留 30 天。

## 3. 模型层函数

| 函数 | 签名 | 作用 |
| --- | --- | --- |
| `directModelSettings(saved)` | 校验并补全供应商配置 | 缺 URL/模型、密钥未设置、远程无 Key 都抛错 |
| `prepareModelRequest(saved, prompt)` | 生成冻结请求 | 支持 `openai-completions` / `openai-responses` / `anthropic-messages`；流式；提示词上限 512 KiB；生成参数哈希 |
| `inferModel` | 由 `ModelBackend` 调用 | 实际网络请求、流式增量、错误归一 |
| `getProviderConfig(id)` / `validateModelConfig(cfg)` | 供应商预设与校验 | 本地回环可免密钥 |
| `BUILTIN_PROVIDERS` | 常量 | DeepSeek、阿里云百炼、豆包、OpenAI、Anthropic、智谱、月之暗面、Ollama、LM Studio 等预设 |
| `readLocalModels` | 扫描本地模型 | Ollama / LM Studio |
| `agentProviders` 系列 | 员工 CLI 供应商绑定 | Codex / Claude Code 共用供应商中心 |

模型请求要点：

- 系统指令由宿主固定，工具、权限、验收均不由模型自行决定。
- Chat Completions 显式请求 `stream_options.include_usage`。
- Anthropic 使用 `x-api-key` + `anthropic-version: 2023-06-01`，`max_tokens: 8192`。
- 推理参数由 `reasoningParameters(settings)` 生成，支持不同供应商的思考强度。

## 6. 助手工具协议（24 个内置工具）

协议：模型只返回一个 JSON 对象，宿主校验后用 `ToolError` 统一错误。工具按职责分九类：

| 类别 | 工具 | 只读 | 备注 |
| --- | --- | --- | --- |
| 知识 | `search_knowledge`、`read_knowledge` | 是 | 必须带 `citation`；资料不授予权限 |
| 诊断 | `diagnose_project` | 是 | 不安装、不执行脚本、不请求模型 |
| 文件 | `read_file`、`search_files`、`list_files`、`get_diff` | 是 | `read_file` 返回 SHA256 与分页游标 |
| 文件写 | `edit_file`、`write_file` | 否 | 编辑需先读并传 `expectedSha256` |
| 命令 | `run_command`、`verify` | 否 | 直接 `spawn`，无 shell；`verify` 仅诊断 |
| 验收 | `configure_verification`、`run_check` | 否 | 契约必须用户批准；`verified ≠ accepted` |
| 技能/记忆 | `load_skill`、`read_memory`、`remember` | 混合 | `remember` 需 `evidence` |
| 员工/委派 | `inspect_agents`、`inspect_quota`、`configure_agents`、`delegate`、`send_agent_message` | 混合 | 持续授权必须批准；委派前冻结模块契约 |
| 发现/上下文 | `search_tools`、`read_context`、`read_output` | 是 | 大结果按引用回读，不重复执行 |

工具参数由 Ajv（`ajv` + `ajv-formats`）按 JSON Schema 校验；校验器按 Schema 缓存，避免重复编译。
