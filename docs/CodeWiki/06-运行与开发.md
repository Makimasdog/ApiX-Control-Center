# 06 · 运行与开发

## 1. 环境要求

| 项 | 要求 |
| --- | --- |
| Node.js | `>=22.19.0 <23` 或 `>=24.22.0 <25`（内置 `node:sqlite`）；FTS5 可用时优化知识库检索，不可用时自动降级 |
| Git | 必需；托管快照/worktree 也依赖 |
| CLI Agent | 可选：Pi、Codex、Claude、Gemini、OpenCode、Kimi；委派任务时才需要 |
| 操作系统 | 主要面向 Windows；服务端逻辑跨平台 |

## 2. 安装与启动

```powershell
npm ci
npm start
```

- `prestart` 自动执行 `npm run build`（`tsc`），把 `src/**/*.ts` 与 `web/**/*.ts` 编译到 `dist/`。
- 打开 `http://127.0.0.1:4173/`（端口可用 `PORT` 修改）。
- 首次访问会要求本机 owner token：查看 `~/.apix-agent-os/owner-access.json` 的 `token`，或设置 `APIX_OWNER_TOKEN`。
- 默认数据目录 `~/.apix-agent-os/`，数据库 `apix.sqlite`；升级或改环境变量后重启服务，不删除数据库与托管工作区。

## 3. 环境变量

| 变量 | 用途 | 默认 |
| --- | --- | --- |
| `PORT` | HTTP 端口 | `4173` |
| `APIX_DATA_DIR` | 数据目录 | `~/.apix-agent-os` |
| `APIX_OWNER_TOKEN` | 指定 owner 访问令牌（32–128 位字母数字/`-_`） | 自动生成 |
| `APIX_ASSISTANT_CONTEXT_TOKENS` | 助手上下文窗口声明 | `32768` |
| `APIX_PI_ENTRY` / `APIX_CODEX_ENTRY` 等 | 员工 CLI 的绝对 JS/原生入口 | 空 |
| `APIX_MANAGER_PI_ENTRY` | 已停用，主 Agent 不依赖 Pi | — |
| `APIX_LEGACY_API` | 设为 `1` 才开放旧接口；否则旧路由返回 409 | 未设置 |
| 供应商 Key | 如 `DEEPSEEK_API_KEY`，由供应商配置引用 | 空 |

根目录 `.env` 自动加载，进程已有同名变量优先。URL/模型示例变量不会自动写入界面；密钥只放本地。

## 4. 模型配置

1. 打开“应用与协作设置 → Agent 供应商中心”。
2. 新建供应商：Base URL、模型 ID、协议（Chat Completions / Responses / Anthropic Messages）、API Key。
3. 应用到 ApiX；本地回环服务可免密钥。
4. 输入框上方按对话选择模型与思考强度；全局设置只影响新对话。
5. Codex / Claude Code 员工在同一页面绑定供应商；员工模型单独维护。

连接测试会产生费用，必须显式批准；成功只证明本次推理，不等于保存即有权限。

## 5. 常用脚本

| 命令 | 作用 |
| --- | --- |
| `npm run build` | `tsc` 编译后端与前端 TS |
| `npm run check` | `tsc --noEmit` + 多个 `.mjs` 语法检查 + `check-stale-dist` + ESLint |
| `npm run lint` / `lint:enforce` | ESLint（后者只输出错误） |
| `npm test` | `pretest` 构建后运行全部 `node:test` 回归 |
| `npm run test:coverage` | 带覆盖率、单并发、20 分钟超时 |
| `npm run test:coding:mvp` | 编码 MVP 相关 4 个测试文件 |
| `npm run test:delivery` | 交付审阅、HTTP、评测与预算 |
| `npm run test:npm` | Node/npm 项目接入与 HTTP |
| `npm run test:ui:all` | 启动真实服务的多组浏览器验证 |
| `npm run test:real` | 真实协作/自主执行验证（可能收费） |
| `npm run eval:coding:real` | 真实模型编码评测（可能收费） |
| `npm run desktop:dev` | Electron 开发模式 |
| `npm run desktop:pack` | 生成 Windows x64 未安装目录 |
| `npm run desktop:dist` | 生成 Windows 安装包 |

注意：

- 浏览器验证脚本会启动服务并走完界面流程；只启动服务不算验证成功。
- 真实模型与真实员工验证可能收费，须显式批准。
- `check-stale-dist` 失败说明 `dist/` 有源码已删除/改名的孤儿产物：删除整个 `dist` 后重新 `npm run build`。

## 6. 桌面版

| 文件 | 职责 |
| --- | --- |
| `desktop/main.cjs` | Electron 主进程：窗口、生命周期、加载本机服务 |
| `desktop/backend.cjs` | 启动/停止 Node 后端 |
| `desktop/dev-watch.cjs` | 开发监听与重启 |
| `desktop/electron-builder.cjs` | Windows x64 打包配置 |

桌面端复用同一 HTTP 服务与 owner token，不另起一套后端；打包产物在 `.tmp-desktop/`（不提交）。

## 7. 测试与验证策略

- 自动回归：`test/*.test.mjs`，使用 `node:test`、`--test-concurrency=1`；尽量使用真实实现与隔离夹具，少用 mock。
- 夹具：`test/*fixture*.mjs` 提供数据库、CLI、服务桩。
- 浏览器验证：`scripts/verification/*` 启动真实服务，覆盖交付、npm、UI、导航、工作流图、恢复等流程。
- 评测：`scripts/evaluation/*` 提供编码任务目录与离线/真实模型入口。
- 历史夹具不自动适配当前鉴权与 API 隔离，不能当成本轮验收。

## 8. 排障速查

| 现象 | 排查 |
| --- | --- |
| 启动后要求令牌 | 读取 `~/.apix-agent-os/owner-access.json`，或设置 `APIX_OWNER_TOKEN` |
| 401 / 403 | 检查 Bearer/Cookie；API 的 `Host` 必须是 `127.0.0.1:<port>` 或 `localhost:<port>` |
| 413 请求过大 | 对话消息 256KB、配置类 64KB、其余默认 30000 字符 |
| 409 旧接口 | 未设置 `APIX_LEGACY_API=1` |
| 404 静态资源 | 资源未登记到 `static-files.mjs` 白名单 |
| 一直排队 | 查前置任务是否 accepted、暂停、额度、预算、并发与权限；队列约每 5 秒复核 |
| 状态未知 | 确认原进程已停止、核对工作区指纹，再显式恢复或换人；不自动重放 |
| 更改授权被拦截 | 先处理冲突任务；开关不会恢复旧任务或解除运行时暂停 |
| 中文变问号 | 检查 CLI 版本与原始事件；已丢失 UTF-8 的原始输出无法还原 |
| `check-stale-dist` 报错 | 删除整个 `dist` 后重新构建 |

## 9. 开发约定（摘要）

来自 [AGENTS.md](../../AGENTS.md)：

1. **源码形态**：根 `.mjs` 只允许入口文件；新业务放 `src/**` 或 `web/**`；根 `.mjs` 引用 `./dist/src/...`。
2. **高内聚低耦合**：临时文件与生成物不得随意放项目目录，统一进 `.tmp*/` 或对应目录。
3. **改动范围**：不为猜测性的竞态/安全边界加复杂度；不提前抽只用一次的函数；入口层校验一次，内部信任类型。
4. **测试**：测真实实现，不把业务逻辑抄进测试；少用 mock。
5. **提交**：每次修改纳入 Git；提交前审查最终 diff（新增文件、调用方、错误路径、数据一致性、访问边界）；用明确文件清单暂存，不用 `git add .`；未经要求不推送/合并。
6. **文档**：新增或变更功能同步更新 `docs/INDEX.md`；代码量大时更新 `docs/`。

## 10. 新增一个功能的最小清单

1. **领域模块**：在 `src/<领域>/` 写实现，类型尽量复用 `contracts.ts`。
2. **装配**：在 `control-plane.mjs` 创建实例并导出处理函数，不把业务写进入口。
3. **路由**：在 `src/infrastructure/api-routes.mjs` 声明方法、路径、限额；旧接口加 `legacy`，流式加 `raw`。
4. **前端**：在 `web/` 增加页面模块或视图组件；新静态资源登记 `static-files.mjs`。
5. **测试**：加 `test/*.test.mjs`（HTTP 层 + 领域层），必要时加浏览器验证脚本。
6. **文档**：更新 `docs/INDEX.md`；结构或表结构变化时更新本 Wiki 对应章节。
7. **验证**：`npm run check` → 相关测试 → 必要时 `npm run test:ui:*`。
