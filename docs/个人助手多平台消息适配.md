# 个人助手多平台消息适配

## Web 消息

在「与 ApiX 对话」输入文字或添加附件，可选择 Markdown。Web 显示普通文本、Markdown 粗体和行内代码，并保留原有证据链接。图片和常见音频格式支持预览，其他附件可下载。附件按会话保存在本机 SQLite，归档或删除的会话关闭附件访问。恢复会话时可再次访问原记录。

现有 `POST /api/assistant/sessions/{id}/messages` 保持兼容。新客户端调用 `POST /api/assistant/sessions/{id}/channel-messages`，提交 `content`、`requestId`、可选的 `format`（`plain` 或 `markdown`）与 `attachments`。附件为 `{name, mime, data}`，`data` 使用标准 base64。单条消息最多 10000 字符和 4 个附件，附件合计最多 4 MiB。可发送仅包含附件的消息。沿用会话级请求 ID，兼容旧的纯文本请求。复用同一 ID 但改变正文、格式或附件会返回 409。

所有者通过 `GET /api/assistant/sessions/{id}/media/{mediaId}` 访问附件。模型仅收到正文和本地附件提示或元数据。附件字节和渠道凭据不会进入模型请求。

## 配置外部渠道

外部渠道在独立 Gateway 中启用，运行 `npm run gateway`。默认没有外部账号。用本机环境或未纳入 Git 的 `.env` 配置 `APIX_MESSAGE_CHANNELS`，值为一行 JSON 数组。以下为结构示例，标识需要替换为本机项目与实际平台账户的值。

```json
[
  {"channel":"wechat","accountId":"weixin","projectId":"项目ID","peerId":"微信对端ID","tokenEnv":"APIX_CHANNEL_WECHAT_TOKEN"},
  {"channel":"telegram","accountId":"telegram","projectId":"项目ID","conversationId":"聊天ID","peerId":"发送者ID","tokenEnv":"APIX_CHANNEL_TELEGRAM_TOKEN"},
  {"channel":"discord","accountId":"discord","projectId":"项目ID","conversationId":"频道ID","peerId":"发送者ID","tokenEnv":"APIX_CHANNEL_DISCORD_TOKEN"}
]
```

每条配置指定一个项目和获准的对端。令牌通过相应的 `APIX_CHANNEL_*_TOKEN` 环境变量提供。设置后重启 Gateway。所有者接口 `GET /api/assistant/channels` 可查看配置错误、轮询状态和最近 10 条投递状态。平台启用后，来自配置会话与发送者的新消息可调用所选模型，费用沿用项目的模型账本和预算。

| 渠道 | 接入与能力 |
| --- | --- |
| 微信 | 使用已配对的腾讯 iLink Bot 令牌和直聊对端 ID。轮询保存游标，回复关联入站上下文。接收文本、图片、文件及语音附件，有转写时一并归一化。SILK 文件通过下载查看。令牌配对沿用腾讯的流程。[微信 iLink 协议](https://github.com/Tencent/openclaw-weixin/blob/main/docs/protocol_zh_CN.md) |
| Telegram | 使用 Bot API 令牌和明确的聊天及发送者 ID。启用 long polling 的 Bot 需使用这一轮询客户端。接收文字、图片、文件和语音，保留粗体与行内代码的常用实体。首次启动可处理 Telegram 保留的该对端更新。[Telegram Bot API](https://core.telegram.org/bots/api) |
| Discord | 使用 Bot 令牌、频道 ID 和获准发送者 ID，配置查看频道、读取历史、发送消息与适用的消息内容权限。通过 REST 查询消息，首次建立游标后处理新增消息。支持 Markdown 文本与图片、文件和语音附件，回复禁用自动提及。[Discord 消息接口](https://docs.discord.com/developers/resources/message) |

渠道按平台、账号、项目、会话、发送者和凭据配置隔离会话。对端消息只进入该渠道的文字对话窗口。窗口沿用现有推理预算，无项目文件、工具、员工或项目记忆权限。外部记录可在 Web 查看，回复通过原渠道发送。外部自动回复为文本，入站媒体在本机 Web 查看。超出媒体预算或下载失败时显示降级提示。

轮询游标和投递状态持久化。遇到重复更新时复用同一请求记录。若出站结果未知，保留 `uncertain` 或中断时的 `sending` 记录供所有者核对，后续轮询不重发。Discord 连续未读页超过适配器处理上限时保留原游标并显示轮询异常。

## 验收

执行 `npm run build`、`npm run check` 和 `node --test --test-concurrency=1 test/personal-channels-http.test.mjs test/personal-channel-adapters.test.mjs`。在 Web 发送一条 Markdown 和图片消息，核对预览、附件权限及旧会话兼容。真实账号联调需准备微信、Telegram 和 Discord 的测试凭据，分别验证直聊或授权会话的来回文本和入站媒体。
