# 03 · 空间语法与设计令牌

令牌落地文件：`web/styles/tokens.css`（新增，纯追加，不改既有变量名与取值），由 `design-system.css` 顶部 `@import` 引入。

现状实测（`web/styles/*.css`，11 个文件）：

| 项 | 实测 |
|---|---|
| 十六进制色值 | 115 处，其中 42 处为 `:root` 令牌定义本身，**73 处为绕过令牌的硬编码** |
| 分布 | design-system 22 / desktop 17 / styles 15 / assistant 11 / knowledge 4 / agent-workbench 2 / director 1 / workflow-graph 1（coordinator、overview、phase4 为 0） |
| 断点阈值 | 33 个不同值：16 个 ≤620（组件级）、17 个 ≥650（页面级）；min/max 混用 |
| z-index 取值 | 1、2、4、5、10、20、21、39、40、100（10 个不同值，无阶梯定义） |
| 已有令牌 | `--app-bg` `--sidebar-bg` `--surface` `--surface-hover` `--surface-inset` `--text-primary` `--text-secondary` `--text-muted` `--border` `--border-control` `--accent` `--accent-hover` `--accent-subtle` `--accent-alt` `--on-accent` `--success(-subtle)` `--warning(-subtle)` `--danger(-subtle)` `--shadow` `--shadow-overlay`，另有 `--ui-*` 别名 |

结论：颜色令牌已基本齐备且对比度多数达标，**真正缺的是空间、排版、动效、层级四类令牌**，以及 73 处硬编码的清零。

## 3.1 空间语法

### 3.1.1 三档内容宽度（按真实侧栏宽度算出来的）

侧栏固定 244px，顶栏 64px。主内容可用宽度 = 视口 − 244 − 2×留白：

| 视口 | 可用宽度 | 说明 |
|---|---|---|
| 1440 | 1132 | 最宽档必须 ≤ 1120，否则必然横向溢出 |
| 1024 | 732 | 标准档也已放不下，靠 `min()` 自动收缩 |
| 768 | 736 | 侧栏已折叠，留白 16 |
| 390 | 366 | 留白 12 |

| 档 | 令牌 | 值 | 用于 |
|---|---|---|---|
| 窄 | `--w-narrow` | 640px | 设置表单、对话框正文、知识库阅读、空态 |
| 标准 | `--w-default` | 880px | 任务详情、运行事件流、项目详情、员工详情 |
| 宽 | `--w-wide` | 1120px | 总览、任务列表 + 详情、员工网格、数据表格 |

实现：`width: min(var(--w-wide), 100%)` + `padding-inline: var(--gutter)`。**不写 1280**：1440 视口下可用仅 1132，1280 会在首屏就产生横向滚动。

### 3.1.2 断点收敛（33 → 4）

| 断点 | 令牌/条件 | 留白 | 网格 gap | 布局 |
|---|---|---|---|---|
| ≥ 1360 | 宽屏 | 32 | 24 | 宽档完整 |
| 1024–1359 | `--bp-wide` | 24 | 24 | 宽档被压缩；任务页仍可两栏 |
| 768–1023 | `--bp-mid` | 16 | 16 | 单列；任务页左列表折叠为下拉 |
| ≤ 767 | `--bp-narrow` | 12 | 12 | 侧栏抽屉（现有 760 阈值统一到 767） |

归并规则（页面级 17 个阈值 → 4）：`650/700/710/720/760` → ≤767；`800/820/850/860/900/1000` → 768–1023；`1080/1099/1100/1200` → 1024–1359；`1450/1600` → ≥1360。组件级 16 个 ≤620 的阈值本轮不动（属于卡片内部最小宽度，见 08 明确不做第 12 条）。

### 3.1.3 网格

12 列，只用四种跨列组合：

| 版式 | 跨列 | 用在哪 |
|---|---|---|
| 全宽单列 | 12 | 页面头、待办条、事件流、表格 |
| 主 + 侧 | 8 + 4 | 总览（待办 + 用量）、任务概览（行动卡 + 预算） |
| 三等分 | 4 + 4 + 4 | 统计卡行、员工网格（≥1024 三列 / 768 两列 / 390 一列） |
| 双列阅读 | 6 + 6 | 项目详情（信息 + 最近任务） |

### 3.1.4 纵向节奏

| 关系 | 值 | 令牌 |
|---|---|---|
| 页面头 → 首区块 | 32 | `--s-6` |
| 区块 → 区块 | 24 | `--s-5` |
| 区块内卡片/行 | 16 | `--s-4` |
| 卡片内元素 | 12 | `--s-3` |
| 标签 → 值、图标 → 文字 | 8 | `--s-2` |

卡片内边距 24（≤767 为 16）；列表行高 48；表格行高 40。

### 3.1.5 每页统一骨架

```
[待办条 48px，跨页常驻，可为空]
[页面头：h1 22/32 + 说明 13/20（≤2 行）+ 右侧 ≤2 按钮 + 1 更多菜单]
[主内容：宽度档 + 12 列]
```

现状问题是每页各写一套容器：`page-intro`（2 处）、`section-block`（3 处）、`surface-card`（37 处）、`block-header`（2 处）混用，且 `director`/`memory`/`projects`/`resources` 四页的 intro 直接写死在 `index.html`，另外两页由 TS 生成。B2 把它们统一到一个 `page-head` 结构。

### 3.2.1 两个必须修的对比度缺陷

| # | 位置 | 现值 | 实测 | 修法 | 批次 |
|---|---|---|---|---|---|
| 1 | 深色 `--border-control` | `#5b6478` | 2.74:1（< 3:1） | 改 `#66718a` → 3.33:1；同时修掉 INDEX 已登记的"输入区与执行方式选择框边框对比度待修复" | B1 |
| 2 | 浅色 `--accent-alt` 用作文字 | `#0d9488` | 3.74:1（< 4.5:1） | 保留原值用于图标/≥18px；新增 `--accent-alt-text: #0b7f76`（4.87:1）用于正文 | B1 |

### 3.2.2 用色规则

- 状态永不只靠颜色：胶囊 = 圆点 + 文字；错误块 = 图标 + 标题 + 正文。
- 装饰分隔用 `--border`；任何"必须能看见的边界"（输入框、选中分段、聚焦卡片）用 `--border-control`。
- 焦点环沿用现有实现：`outline: 2px solid var(--accent); outline-offset: 3px;`（深色下 `--accent` 已切换，无需另一套规则）。
- 深色下不使用纯白文字（上限 `#eef0f6`），避免光晕。
- 已有的 `prefers-contrast: more` 与 `prefers-reduced-transparency: reduce` 媒体查询必须保留，新组件同样响应。

## 3.3 排版

字体栈（现有，不改）：`-apple-system, BlinkMacSystemFont, "Segoe UI", "Microsoft YaHei", system-ui, sans-serif`；基础 `font-size: 14px`。
等宽（ID、事件码、路径）：`"Cascadia Mono", Consolas, "Microsoft YaHei UI", ui-monospace, monospace`。

| 令牌 | 字号 | 行高 | 字重 | 用处 |
|---|---|---|---|---|
| `--fs-display` | 28 | 36 | 600 | 总览首屏数字、空态大标题 |
| `--fs-h1` | 22 | 32 | 600 | 页面 `h1`（每页唯一） |
| `--fs-h2` | 18 | 26 | 600 | 区块标题、任务标题 |
| `--fs-h3` | 16 | 24 | 600 | 卡片标题、抽屉标题 |
| `--fs-lead` | 15 | 24 | 400 | 页面头说明、契约摘要 |
| `--fs-body` | 14 | 22 | 400 | 正文、表格单元、事件文本（= 现有 14/1.55） |
| `--fs-form` | 13 | 20 | 400 | 表单标签与值、侧栏条目（现有 13px） |
| `--fs-caption` | 12 | 18 | 400 | 时间戳、计数、元信息（现有 12px） |
| `--fs-micro` | 11 | 16 | 600 | 侧栏分组标题、`section-caption`（现有 11px，合法化） |

| 规则 | 值 |
|---|---|
| 正文档 | 14 / 22，`max-width: 42em`（约 42 汉字/行） |
| 表单档 | 13 / 20；标签与输入值同档，不与正文混用 14 |
| 数字 | 计数、用量、预算用 `font-variant-numeric: tabular-nums` |
| 数字 + 单位 | 整体 `white-space: nowrap`（`1.2M tokens`、`92%`、`4 分 12 秒`） |
| 大数字 | `clamp(22px, 3vw, 28px)`，不在卡片里硬写 32 |
| 中文断行 | 正文 `word-break: normal; overflow-wrap: break-word;`；长 ID/路径 `word-break: break-all` 仅限等宽单元格并带 `title` |
| 禁止 | `text-align: justify`（中文会出现不规则字距） |
| 截断 | 标题 2 行 `line-clamp`；单行 `ellipsis` + `title`；不出现 1–2 字符孤行 |

## 3.6 阴影

| 令牌 | 浅色 | 深色 |
|---|---|---|
| `--shadow-1` | 沿用现有 `--shadow: 0 1px 2px #18213a08, 0 8px 22px #18213a0b` | 沿用 `0 2px 8px #0002, 0 12px 36px #0003` |
| `--shadow-2`（新增） | `0 4px 12px -2px #18213a14, 0 2px 4px -2px #18213a0d` | `0 6px 16px -4px #0009, inset 0 1px 0 #ffffff0a` |
| `--shadow-3` | 沿用 `--shadow-overlay: 0 20px 70px #10182738` | 沿用 `0 16px 64px #0008` |

用法：卡片静态 `--shadow-1`；抽屉、下拉、命令条 `--shadow-2`；对话框 `--shadow-3`。深色下阴影不可见，靠 `--border` 与内高光建立层级。

## 3.7 动效

| 令牌 | 值 | 用途 |
|---|---|---|
| `--dur-1` | 140ms | 颜色/背景切换（现有 `transitions: 140ms ease`） |
| `--dur-2` | 180ms | 按钮、输入聚焦、hover |
| `--dur-3` | 240ms | 抽屉、下拉、折叠 |
| `--dur-4` | 320ms | 对话框入场（现有 `apix-dialog-in` 为 160ms，仅对话框正文用 320，遮罩用 180） |
| `--ease-in` | `cubic-bezier(.2, 0, 0, 1)` | 入场 |
| `--ease-out` | `cubic-bezier(.4, 0, 1, 1)` | 出场 |
| `--ease-standard` | `ease` | 颜色过渡（与现有默认一致） |

规则：出场 = 入场 × 0.65（240 → 156ms）；列表项错峰 32ms，最多 6 项；`prefers-reduced-motion: reduce` 下全部归 0 且取消错峰（现有媒体查询已存在，需把新令牌纳入）。

## 3.9 令牌 → 组件 → 页面 收敛路径

| 阶段 | 动作 | 文件范围 | 硬编码目标 | 验证命令 |
|---|---|---|---|---|
| P0 冻结（B1） | 新增 `tokens.css`；`design-system.css` 顶部引入；既变量改为引用令牌（值不变）；补空间/排版/动效/z-index 令牌；修 §3.2.1 两处对比度缺陷 | `web/styles/tokens.css`（新）、`web/styles/design-system.css` | 73（不变，仅两处色值微调） | `npm run build && npm run check && npm run test:ui:browser` |
| P1 组件层（B3） | 15 个组件只允许 `var(--…)` | `web/styles/components.css`（新）、`design-system.css` | ≤ 52 | 同上 + 下方扫描命令 |
| P2 页面层（B2/B4/B5/B6） | 逐页清零，`desktop.css` / `styles.css` 同步缩减 | 每批 2–3 个 css | 52 → 40 → 28 → 12 → 0 | 同上 |

扫描命令（PowerShell）：
`Get-ChildItem web, web/styles -Filter *.css | ForEach-Object { $t = Get-Content $_.FullName -Raw; "$($_.Name) $([regex]::Matches($t,'#[0-9a-fA-F]{3,8}\b').Count)" }`
基线值（本轮实测）：design-system 64（含令牌定义 42）、desktop 17、styles 15、assistant 11、knowledge 4、agent-workbench 2、director 1、workflow-graph 1，合计 115。

> 与题面 89 处的差异说明：89 是较早基线；按当前代码实测为 115 个色值 / 73 个非令牌行。本文以可复现命令的结果为准，清零目标同为 0。

## 3.10 允许保留的非令牌值

| 位置 | 值 | 原因 |
|---|---|---|
| `--shadow*` 内部 | `#18213a08`、`#0002` 等 | 阴影叠加层，不进颜色语义表，仅定义处出现 |
| `dialog::backdrop` | `#131b2b66` | 遮罩，收敛为 `--overlay-backdrop` 后只出现一次 |
| 深色内高光 | `#ffffff0a` | 随层级微调 |
| SVG `fill="currentColor"` | 无十六进制 | 复用文本色 |

除此之外出现的十六进制一律视为缺陷。
