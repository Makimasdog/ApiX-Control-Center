# 08 · 明确不做

一条一行。标注「暂缓」的写清触发条件，避免被当成遗漏。

| # | 不做 | 原因 |
|---|---|---|
| 1 | 不引入前端框架（React/Vue/Svelte）、CSS 框架、打包器 | 底座是 tsc 直出 + 原生 ES module（`index.html` 逐条 `<script type="module" src="./dist/web/*.js">`），引入会推翻 29 个 `web/*.ts` 与整条 `npm run build`。 |
| 2 | 不引入图标字体或外部图标库 | Electron 离线 + CSP；现有内联 SVG `symbol`（`#icon-grid`、`#icon-terminal`…）已覆盖，只补缺口。 |
| 3 | 不引入外部字体 | 中文可变字体让安装包 +2–8MB，且与 Segoe UI / 微软雅黑的系统渲染差异会造成同字号视觉不一致。 |
| 4 | 不引入路由库、不改多页应用 | 页面切换已由 `agent-os.js` 的 `activatePage` 完成；hash 深链足够，路由库会引入与 `inert`/焦点管理的第二个状态源。 |
| 5 | 不做页面级转场动画 | 桌面工具高频切换，转场拖慢感知；动效只保留在抽屉、对话框、折叠三处。 |
| 6 | 不做自定义主题色编辑器 | 换主色需重算全部语义色对比度（本文已实测 14 组），收益不抵成本。 |
| 7 | 不做 Run 事件火焰图 / 甘特图 / 持久化分析视图 | 需要后端补时间戳聚合与查询接口；硬约束是不改后端契约。 |
| 8 | 不做虚拟滚动 | 本地单人场景任务量 <500；先"分页 50 + 分段加载"，避免自研虚拟列表带来的焦点与读屏问题。 |
| 9 | 不做 Markdown → HTML 富文本注入 | `html.ts` 模板 + ESLint 插值禁令要求走白名单解析器；设计上改为"结构化段落数组"，不引入解析依赖。 |
| 10 | 不给旧页面留兼容别名（保留 `page-*` 双 id） | 双 id 会让 `aria-current`、深链、`verify-ui.mjs` 三处各有一份事实源；旧页面一次删净更便宜。 |
| 11 | 不做第二套深色品牌色 | 深色只做同语义映射，避免两套色相各自漂移；对比度仍独立校验。 |
| 12 | 不动 16 个 ≤620px 的组件级 `max-width` | 属于卡片内部最小宽度，不是页面断点；本轮只收敛页面级 17 个阈值。改用 container query 会引入仓库未使用的新特性。 |
| 13 | 不做移动端手势（抽屉下滑关闭、列表左滑） | 目标平台是 Windows 桌面 + 同源浏览器；手势与文本选择/滚动冲突且不可键盘复现。 |
| 14 | 不改后端契约、API 形状、任务/审批/预算语义 | 硬约束。所有状态只读既有字段；"等待时长""重试次数"由事件时间差派生。 |
| 15 | 不新增独立页面 | 硬约束。新需求优先做任务页标签、抽屉或知识页分段。 |
| 16 | 不做全局跨实体搜索 | 知识库已有搜索、任务列表已有筛选，覆盖多数场景。触发条件：任务数 >500 且出现跨实体查询需求。 |
| 17 | 不做桌面通知 / 声音 | 已存在员工请求桌面通知（`test:desktop` 验收），本设计不扩展；待办条 + 抽屉已保证非当前页可见。 |
| 18 | 不做 73 处硬编码的一次性大扫除提交 | 单次巨型 diff 无法定位回归；按 06 的 6 批收敛，每批独立过门禁。 |
| 19 | 不追求 100% 组件化（例如拆到每个表格单元格） | 无框架项目里模板函数比直接模板更难读；只抽出现 ≥3 次且状态 ≥4 种的组件。 |
| 20 | 不在本轮替换原生 `<dialog>` | 现有 `::backdrop`、18px 圆角、`apix-dialog-in` 160ms 已工作，替换只增加风险。 |

## 最优方案不可行的说明

**目标**：等待输入在任意页面实时可见，且不打断当前工作。
**理想**：全局通知中心 + WebSocket 推送 + 系统级通知。
**不可行**：不改后端契约；且系统通知在 Playwright 中不可断言（现有桌面通知靠独立脚本与人工确认）。
**次优（本方案采用）**：待办条复用既有员工提问/审批查询，10s 轮询、页面隐藏（`visibilitychange`）时暂停；新增项用 300ms 轻提示、不抢焦点。代价是最多 10s 延迟，可接受因为待处理交互本身以分钟为有效期。
