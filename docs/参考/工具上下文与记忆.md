# 工具、MCP、上下文、监督与记忆

更新：2026-10-18；包含 Windows Coding MVP 开发分支新增能力，实际验证见[总报告](../../协作/20261018-P1-Coding-MVP交付与自审.md)。主循环和摘要使用本对话模型；子流程继承配置。当前全局及旧对话引用的管理者密钥和同值别名继续从 MCP/员工环境隔离。

本轮参考本机 `E:/Projects/wyy/Mewcode` 的工具注册、分层压缩、邮箱通知和记忆召回机制，在 ApiX 现有 Node/TypeScript 主循环中实现；没有修改 MewCode，也没有更换 ApiX 的执行与验收引擎。

## 使用入口

1. 在“Skills 与 MCP → MCP 服务”选择项目，添加服务配置。stdio 使用可执行文件或 JS 入口的绝对路径；HTTP 使用 Streamable HTTP URL。
2. 勾选启用并批准服务连接/服务器程序执行后保存，再点击“连接并发现”。服务程序使用本机账户权限，目录提示不是操作系统沙箱；请只启用可信服务。
3. 与 ApiX 对话。主循环可以通过 `search_tools` 按用途发现外部工具，工具的完整 Schema 才加入当前会话目录。调用经过现有项目权限和按次审批，远程 `readOnlyHint` 不授予只读放行。
4. 大工具结果在对话中显示预览和引用，可点击“分段查看完整内容”；模型使用 `read_context` 读取同一份完整数据，不重新执行原工具。
5. Agent 通过 `remember` 提炼的记忆为“待确认”。在对话右侧确认后才自动召回；用户直接填写的记忆立即生效。删除、修改和确认使用版本校验。

stdio 配置示例（替换为实际路径）：

```json
{
  "id": "my-service",
  "name": "我的服务",
  "transport": "stdio",
  "command": "C:/path/to/node.exe",
  "args": ["C:/path/to/mcp-server.mjs"],
  "env": ["SERVICE_API_KEY"],
  "headerEnv": {},
  "enabled": false,
  "version": 0
}
```

HTTP 配置使用 `"transport":"http"`、`"url":"https://service.example/mcp"` 和 `"headerEnv":{"Authorization":"SERVICE_AUTH_HEADER"}`。环境变量值应是服务实际要求的完整请求头值。环境变量映射只保存变量名称，不保存变量值；凭据请通过变量提供，不要粘贴到 command、args 或 URL。管理者凭据和旧员工身份不会传给 MCP。

## 模块与契约

| 模块 | 职责及约束 |
|---|---|
| `src/assistant/tool-registry.ts` | 统一名称、描述、JSON Schema、只读属性与版本；参数先校验再执行；格式错误作为可修正观察返回主循环 |
| `src/assistant/mcp-manager.ts` | 官方 SDK 1.32.1 的 stdio/Streamable HTTP 客户端；项目配置、工具发现、凭据环境变量引用、取消与关闭 |
| `src/assistant/assistant-context.ts` | 大结果/大工具参数完整保存在 SQLite，提供 SHA-256 引用和会话归属校验；压缩边界不拆开工具开始与结果 |
| `src/assistant/assistant-memory.ts` | 当前项目已确认记忆的相关性排序，中文二元词与英文关键词，用户偏好/反馈优先，最多 5 条和 6000 字符，标记过期观察 |
| `src/assistant/assistant-loop.ts` | 接入注册表、发现、引用、分层压缩、记忆召回和持久化监督计数；继续执行审批、文件指纹、费用与完成门槛 |
| `src/coordination/coordinator.ts` / `control-plane.mjs` | 员工事件通知主循环，快照包含任务、进度报告、验收和修复状态；MCP 装配不向模型暴露配置写接口 |
| `web/mcp-settings.ts` / `web/assistant.ts` | 项目服务配置与工具发现；带服务描述/版本的批准请求、记忆确认、完整结果分页 |

模型仍使用 ApiX 的 JSON 动作契约。注册表提供实际参数 Schema，但本轮没有改用供应商原生 function calling，也没有引入第二套主 Agent 引擎。

## 上下文预算与证据

默认声明窗口为 32768 Token，可通过 `.env` 的 `APIX_ASSISTANT_CONTEXT_TOKENS` 调整，不应超过模型实际窗口。估算采用 UTF-8 字节数除以三，输入目标为窗口的 72%，其余预留给输出和估算误差；不是精确 Token 计数或费用测量。

先把超过 8000 字符的工具结果、工具参数和委派报告转换为预览及引用，完整原文仍保留。然后在输入预算不足时分批摘要旧事件，保留近期完整工具执行组、初始请求、最新请求、文件/结果引用和当前宿主状态。一次最多处理四个摘要批次，单条输入或工具目录无法容纳时明确暂停，不静默删除约束。摘要调用仍经过原管理者预算预留与取消机制。

模型对大结果的读取是按需进行的，不能将“拿到引用”表述成“已经看完”。实际验证是否成功和交付文件指纹仍由宿主保存和检查，不依赖摘要中的声明。

## 监督的实际行为

关键协作事件通知主循环；30 ms 内合并通知，另保留原每秒检查作为恢复与去抖后的兜底。员工任务状态、报告和验收证据快照摘要未变化时，不触发模型推理。普通变化至少间隔 30 秒，阻塞可立即唤醒；每次委派最多六次监督唤醒，计数和最后快照持久化，重启不会清零。

被唤醒的 ApiX 可检查员工、发送指导或请求用户决定。员工尚在执行时禁止主循环并行写文件、执行命令或重复委派；确定性的排队、改派、检查和返工仍由宿主管理。主 Agent 选择继续等待不会把整个任务标记完成。停止、权限撤销和状态未知的恢复规则继续生效。

## 安全和能力边界

- MCP 连接/发现超时 10 秒，工具调用超时 30 秒；传输取消或错误后的外部副作用可能已发生，记录不确定状态并暂停，不自动重放。`isError` 结果不会显示为成功。
- MCP 配置变化使缓存目录和旧批准失效；必须重新发现工具。一个服务失败不会阻止其他服务发现，但失败服务的旧工具会移出目录。外部 Schema 不下载引用文档。
- HTTP 仅支持 HTTPS 或本机 HTTP，拒绝 URL 内凭据、查询参数和跨地址重定向；凭据通过环境变量映射提供。暂未提供 OAuth 登录界面、旧 SSE、采样或交互式 elicitation。
- MCP 服务并不是受 ApiX 文件工具路径检查约束的 OS 沙箱。外部服务的行为、外部收费及远程写入验收仍需对应服务和实际检查支持，不能用本地文件验证来证明任意远程操作正确。
- 记忆只在当前项目内自动召回；没有跨项目全局偏好或额外 LLM/向量检索。候选记忆不自动生效，记忆不是授权。用户更新记忆会使正在推理的旧决策失效。
- 没有实现自动重写冻结架构、无限循环或全部故障的透明恢复。完整上下文与历史持续保存在本地，暂未增加自动清理历史的策略。

SDK 接口参考：[MCP 官方 TypeScript SDK 客户端](https://ts.sdk.modelcontextprotocol.io/client)。

## 编码工具与评估

Windows 单 Agent MVP 使用 ApiX 自己的工具，不要求 Codex、Claude 或 Pi CLI。项目权限和逐次审批继续生效；只读权限可搜索、读取、看差异和日志。其他平台禁用托管命令与可信检查并解释原因，文件工具仍可用；这不是 OS 沙箱。

| 工具输入示例 | 结果与范围 |
| --- | --- |
| `search_files {"query":"BUG","path":"src","contextLines":1,"maxMatches":20}` | 相对路径、行/列（UTF-16）、片段、`scanComplete`、`truncationReason`、游标。排除凭据、依赖、构建产物与链接；部分扫描不能推断全项目无匹配。 |
| `read_file {"path":"src/main.ts","startLine":7000,"endLine":7010,"maxBytes":8000}` | 实际行号、`sha256`、`bytesReturned`、`bytesScanned`、`fileBytes`、后续游标。旧小文件读取保持兼容；分页期间文件变化须重新读取。 |
| `edit_file {"path":"src/main.ts","expectedSha256":"读取所得 SHA","edits":[{"oldText":"a-b","newText":"a+b"}]}` | 唯一匹配、全部编辑预校验，记录修改前后 SHA 与差异；版本不符拒绝，不猜位置。受控小文件创建继续使用 `write_file`。 |
| `get_diff {}` | 只展示本会话文件工具的实际编辑/创建，不包含用户原有改动或命令产生的修改。非 Git 项目可用；100 条操作一页，用 `nextBeforeEventId` 继续。 |
| `read_output {"operationId":"实际操作 ID","channel":"stderr","mode":"tail"}` | 读取持久化、已脱敏日志。也接受本会话 `outputRef`；分页沿用返回的 `nextOffset`。不接受任意文件路径，不跨会话读取。 |

读取上限为源文件 8 MiB、单次返回 16,000 字节；使用固定缓冲区流式计算全文件 SHA，`bytesScanned` 如实反映读取量。编辑限单文件 2 MiB、1–8 个不重叠替换、每段 20,000 字符。搜索限 400 文件、累计 2 MiB、单文件 256 KiB、软耗时 1.5 秒，超限明确报告部分扫描；软期限不能中断阻塞的文件系统调用。

日志在预览截断前采集，stdout/stderr 分开存于工作区外既有 SQLite `assistant_outputs`。每操作头部合计 256 KiB，另保留各 8 KiB 尾部；日志工件合计 8 MiB、7 天可读期，下一次采集时按容量/时间清理，空闲时不承诺立即物理删除。额度不是整个 SQLite 数据库上限。超限、过期或采集失败会返回不完整及原因；预览截断本身不等于检查失败。

在对话工具卡中展开文件范围、实际变更、可信检查或命令，可看操作 ID、结果和日志头尾。日志“继续读取”按片段翻页；刷新后仍使用持久化证据。交付卡显示修改文件、检查契约、代码指纹和未验证项；`verified` 表示技术验证，`not_accepted` 表示尚未正式验收。没有可信检查不能以 `verify` 或任意退出码 0 代替验收。

运行 `npm run test:coding:mvp` 可生成五个隔离场景及 `.tmp-p0-p2/p1-mvp/<运行ID>/scenario-*/index.html`、`evidence.json`、项目副本。固定决策序列证明宿主工程闭环，不证明真实模型自主能力；首次失败与完整回归见[交付报告](../../协作/20261018-P1-Coding-MVP交付与自审.md)。

真实模型入口先执行 `npm run eval:coding:real -- --inspect`，只读现有设置数据库并输出模型配置摘要/哈希，不打印密钥、不发请求。可用 `--settings-db <路径>` 或 `--session-id <主对话ID>` 指定现有配置。批准后执行 `npm run eval:coding:real -- --approval <manifest.json>`，保持同样配置参数。

授权清单需要 `approveSpend`、`approveWorkspace`、`approveChecks`、`providerBudgetConfirmed` 全为 `true`，填写 inspect 返回的 `settingsSha256`、`currency`、`maxMinor`、`perRequestUpperBoundMinor`、`maxRequests`（1–24）、`maxMinutes`（1–30）。仅授权隔离样例的 `src/add.cjs` 编辑和固定 `unit/check.cjs/5000ms` 检查，其他审批拒绝。模型可自行失败；报告保留真实状态。费用是按次预留上界，实际用量/费用未知保留 `null`，不能代替服务商账单或强制服务商限额；必须先在服务商侧确认预算限制。不传清单不调用模型。本轮未执行收费真实模型评估。

当前验收仍受 3,000 项/8 MiB 指纹上限和冻结依赖约束；本轮范围读取不代表已支持大型仓库验收。文件替换采用同目录临时文件、版本复查和改名，不能承诺与外部不配合写入者之间的原子比较交换，也未新增通用回滚。
