# 工具安全、意图澄清、循环控制与知识库：接口和使用

本轮基于现有单用户本机架构实现；对应设计见 `20261024-工具与意图循环知识库实施方案.md`，验证与自审见同日审查记录。本轮没有新增账号系统或宣称支持恶意多租户部署。

## 1. 统一工具访问

实现入口：`src/assistant/tool-governance.ts`、`tool-registry.ts`、`assistant-loop.ts`；外部员工的受限入口为 `control-plane.mjs:invokeAgentTool`。普通管理 API 现在需要所有者能力凭据，不能仅靠本机 Host 绕过授权。`owner-access.mjs` 保存/验证随机令牌，Electron 使用请求头引导 HttpOnly、SameSite=Strict Cookie，刷新/后端重启沿用同一身份。令牌与 Cookie 不进入 URL 或日志，员工环境移除令牌及同值别名。

授权交集：身份限定的项目 → 安全角色 → allow/deny 工具清单 → 原有项目模式和员工授权 → 操作审批/文件边界/预算。deny 优先；allow 为空表示角色范围内工具均可用。角色不能通过工具参数指定，员工岗位文字不参与安全判定。默认 ApiX 为 coordinator；员工宿主工具身份默认为 planner。executor 可以使用实现类工具但不能配置协作/验收或委派；coordinator 仍不能绕过原有审批。员工 RPC 首版只开放文件读取/搜索/目录诊断与知识库读取，不提供写入或管理 API。

| 接口 | 输入/作用 |
| --- | --- |
| GET `/api/projects/:projectId/tool-access?subject=apix或员工ID` | `{role,allow,deny,version}` |
| POST 同路径 | `{subject,role,allow:string[],deny:string[],version}`；版本冲突 409 |
| GET `/api/projects/:projectId/tool-access/audit` | 最近 100 项审计，包含授权/拒绝/完成/策略变更与脱敏摘要 |
| POST `/api/agent/tools/:tool` | Bearer 使用运行令牌，body 仅工具参数；主体、项目及运行 ID 从认证结果推导 |

Builtin 对象拒绝未知字段；检查必填、类型、数组数目、字符串/请求大小、NUL、原型键、深度及行范围/游标互斥；保留已注册 MCP 自身声明的 Schema 兼容性。`configure_agents.profiles.reasoningLevel` 与原实现一致为 1–5 整数或 null；上下文容量允许未知 null。

错误：`{code,message,retryable,action,details}`，HTTP 同时保留旧前端使用的 `error` 字段；如 INVALID_ARGUMENTS / TOOL_FORBIDDEN / VERSION_CONFLICT。主循环将拒绝转换为工具观察，允许改正工具或参数；不会把参数错误当成传输故障盲试。调用前保存授权审计，结果保存完成/失败记录；参数日志隐藏凭据字段、已知环境密钥和内容载荷，审批预览保留可核对的普通参数并隐藏识别出的秘密。

**边界**：具有相同 OS 用户文件权限的任意外部 CLI 不是沙箱。它自己的 shell/文件工具不经过 ApiX 宿主网关，无法用本轮角色清单拦截它的所有本地操作；这些行为仍受现有工作区、运行监督和显式授权边界约束。

## 2. 意图澄清

模型动作：

```json
{"action":"clarify","question":"希望优先改善哪一项？","candidates":["调整已有页面布局","提高页面加载速度","完善键盘操作"],"preparation":[{"tool":"list_files","args":{}}]}
```

宿主严格检查恰好三个非空、归一化后互异的候选，添加固定第四项“以上都不是，我来补充”。提示明确要求基于原话与上下文，关键歧义才澄清，不能借候选请求扩大权限。该判断和候选语义由当前模型生成，宿主不宣称能机械证明其完全符合用户真实意图。

`pending.kind=intent` 复用既有 requestId/version。宿主先持久化等待状态，再执行最多三个本地只读准备操作（list_files/read_file/search_files/get_diff），禁止远程工具、写入、费用与委派。准备期间拒绝过早答复，前端禁用提交按钮；完成后保留输入等待用户。等待不启动依赖答案的执行。

用户可单选、单选后补充修正、或只输入文字。选第四项必须补充文本。答复和 intent_confirmed/新的用户指令在同一保存点事务内写入；过期版本、重复选项、错误 requestId 均拒绝。重启保留等待内容，后续模型上下文包含确认结果。选择不会改变权限或操作批准。

## 3. 循环检测与恢复

实现：`tool-progress.ts`。`tool_observations` 按 session/本轮用户消息或恢复事件保存规范化调用摘要、结果散列、错误代码、字节数、阻断状态和时间；员工宿主 RPC 按 run ID 隔离。已有 `assistant-effects.ts` 继续负责副作用收据、结果复用与未知结果门禁。

区分方式：保留分页 cursor/offset；忽略结果中的执行 ID、输出引用和时间戳；变化的真实结果视为进展；文件工具产生不同文件哈希时更新工作进展标记，因此合理修改过程可以重复读取同一参考资料。固定参数和结果无变化、确定性错误不改参数、以及多个调用组成的短周期回路分别检测。inspect_agents/inspect_quota 使用单独轮询限次与指数延时；轮询状态变化不会被同一工具的 A/B 状态变化误报为多个工具回路。

首次重复路径返回 TOOL_PATH_BLOCKED，要求换工具、修正原因或询问用户；继续相同路径则 TOOL_LOOP_STOPPED，保留对话/收据并暂停。调用、连续失败、结果字节或时间预算都有终止原因；运行时共享计时器会请求中断模型/工具，而不仅在下一步检查。时间中断后不能确认的写入继续进入副作用待核对状态。

GET/POST `/api/projects/:id/tool-limits` 使用乐观版本，字段默认值及硬上限：

| 字段 | 默认 | 上限 |
| --- | ---: | ---: |
| maxCalls | 24 | 100 |
| maxFailures | 3 | 10 |
| maxNoProgress | 3 | 10 |
| maxPolls | 6 | 30 |
| maxMs | 1800000 | 3600000 |
| maxBytes | 2000000 | 10000000 |
| pollMs | 1000 | 30000 |

maxCalls 计宿主逻辑调用；模型步骤另受相同上限限制。本地纯只读工具的 EBUSY/EAGAIN/ETIMEDOUT/EMFILE 可在单次逻辑调用内最多尝试三次，退避且可取消。模型请求沿用既有有限退避；MCP 的远程副作用未知和任何写入不按错误字符串自动重放。配置只由所有者保存，模型无法放宽。外部 CLI 原生工具的重复调用未纳入这个检测器，不能将宿主工具日志描述成整个 CLI 的全量行为追踪。

## 4. 本地知识库

实现：`knowledge-base.ts`、`web/knowledge.ts`、`web/styles/knowledge.css`。入口：更多设置 → 知识库与工具安全。可创建/编辑/删除库、设置 ApiX/员工读取权限、上传/替换/删除文档、查看 processing/ready/failed、检索和打开来源。

选择本地 SQLite FTS5 关键词检索，英文词与中文单字/双字辅助索引；不新增模型、嵌入依赖、向量服务或基础设施。适合本机项目的小型资料集，召回对字面术语敏感，不保证语义改写召回或引用与结论的自动语义验证。

支持 UTF-8 TXT/Markdown/HTML/JSON/CSV，每份文档 1 MiB，最多 700 个块，每块约 1800 字符、重叠约 180 字符。HTML 去除脚本/样式与标签；JSON 检查合法性并格式化；行号均以解析后文本为准。PDF、DOCX、扫描件和 OCR 首版不支持，会明确拒绝，不作为已完成格式宣传。

| 接口（前缀 `/api/projects/:id/knowledge`） | 输入/输出 |
| --- | --- |
| GET 根路径 | 库及文档元信息/状态/版本，不返回完整原文 |
| POST `/spaces/save` | `{id?,name,description?,grants:string[],version?}` |
| POST `/spaces/remove` | `{id,version}`，原文、授权和索引一并清理 |
| POST `/documents/upload` | `{spaceId,id?,version?,filename,title?,base64}`，返回 processing 和版本 |
| POST `/documents/remove` | `{id,version}` |
| POST `/search` | `{query,spaceId?,limit?}`，最多 10 项、默认 6 项 |
| GET `/source?citation=...` | 核验项目、版本和来源有效性，返回片段及文件/行号/哈希 |

持久化：kb_spaces、kb_grants、kb_documents、kb_chunks、kb_fts、kb_receipts、kb_queries。`source` 为本机 UTF-8 原文，digest 为上传字节 SHA256。更新先在事务中撤下旧索引、增加版本、标记 processing；后台 setImmediate 处理纯本地解析，发布前复查文档和版本，以保存点原子发布所有分块与 FTS。异常回滚全部分块后标 failed；处理中的删除/更新不能由旧工作复活。启动时重建未完成 processing，不涉及重放外部操作。

检索 SQL 先限定项目与 grants，引用读取再核验。两个更新同一版本的并发请求只有一个成功，另一个 409；引用格式 `[KB:库ID:文档ID:版本:块序号]`。search_knowledge 与 read_knowledge 都记录会话实际观察收据；回答不能引用未观察/过期/撤权来源。检索无结果会明确附加证据不足说明；获得资料却不给来源的完成声明会被拒绝。模型需继续根据来源本身判断支持力度。

如果本对话观察过的来源已更新、删除或撤权，会在再次组装模型上下文、处理模型决定和派发工具前阻断，避免通过历史片段或 read_context 间接复用失效资料；所有者仍可回看原始审计记录。首版采用保守策略：新建对话重新检索，不自动删除审计或声称已清除供应商端接收过的数据。

资料始终标记 reference_only，不能更改宿主规则或授予工具。ApiX 在接触知识库资料后，后续有副作用的操作需要绑定参数的用户批准，原有全项目权限也不能被文档用来直接触发这些操作。这个保守门禁持续作用于该对话，新的独立任务可另开对话。

**数据流向与费用**：上传、解析、分块和检索在本机 SQLite 完成，不产生嵌入/向量服务费用。Agent 使用资料时，返回的片段及来源会进入当前已配置模型的上下文，因此可能发送到该模型供应商，并消耗原有推理额度；不是“所有资料永不离开设备”。原文不会自动整库外传。外部员工主动读取后，其 CLI 供应商同样会接收所用片段。

## 部署与回滚

1. 停止正在执行的任务；备份当前实例数据目录的 SQLite 及现有凭据文件。先停止实例再复制，或用 SQLite backup，不能单独复制活跃 WAL 的主文件当完整备份。
2. Node >=22.19（本轮用 24.22.1），运行 `npm run build`；开发版运行 `npm run desktop:dev`。已打包 exe 不会自动加载源码，分发版仍需原有 desktop:dist 流程，本轮未生成新的安装包。
3. 表和索引以 CREATE IF NOT EXISTS 增量创建，不删除原有数据。没有新服务、API Key 或环境变量必填项。`APIX_OWNER_TOKEN` 可由操作者显式提供；否则在实例数据目录自动建立 owner-access.json，保留在本机。
4. Electron 自动认证。独立浏览器访问普通 Web 地址后，在本机连接页输入该数据目录的 token；curl 等管理调用改为 `Authorization: Bearer <所有者令牌>`。员工使用原有 APIX_AGENT_TOKEN，不能使用所有者令牌。
5. 回滚先停服务、回退已提交代码；新表可以保留。没有自动降级或删除业务数据操作。旧版本不具备本轮能力认证边界，不应对不受信任的访问开放。

本轮验证使用隔离数据目录与免费本地模型协议夹具，没有迁移或更改用户现有生产数据，没有调用付费模型，也没有自动启动真实业务任务。
