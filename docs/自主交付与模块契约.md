# 自主交付与模块契约

真实验收脚本 `scripts/verify-real-autonomy.mjs` 和 `scripts/verify-real-collaboration.mjs` 的 ApiX 管理者测试模型按用户指定固定为 `qwen3.8-27b`，结果记录 `managerModel`。沿用已有阿里兼容端点及密钥环境变量，不再从 `ali_model_name` 读取测试模型；生产模型设置及 Codex/Claude 员工模型不随此修改。`--self-check` 不调用模型；实际调用仍需 `--approve-cost`。

2026-10-14 开发版本。自主交付是项目级可选策略，沿用既有权限、预算、消息和 Git worktree，不将历史目标自动转换为自主任务。

项目可以是普通目录，也可以是尚无提交的 Git 目录。首次任务在 ApiX 数据目录建立该计划的托管 Git 输入快照，后续任务共享同一基线，仍各自使用独立 worktree。原项目不被初始化或提交；后续源目录修改进入新计划，不改变已有基线。快照遵守 `.gitignore`，跳过 `node_modules`、`.git`、ApiX 数据目录、`.env` 系列及常见私钥文件；链接、超过 10000 个文件、20000 个条目或 100 MiB 的输入会明确拒绝。需要这些被排除的文件时，应维护明确的 Git 输入基线。交付和集成成果保存在托管工作区，检查后导出，不能将集成变更写回输入快照。

计划输出的 JSON、员工引用或依赖未通过校验时，ApiX 会携带具体校验错误请求纠正一次，每次分别接受原有预算准入。连接失败不自动重试；两次计划仍无效时，普通协作保留待审规则草案，自主架构模式停止派发并显示原因。模型响应无效不会再被统一标成“推理后端不可用”。

## 开启与使用

1. 配置项目、管理者和员工，开启项目自动协作。
2. 在“均衡调度 · 能力与预算”维护推理能力（1–5）及上下文容量。需要费用预测时提供对应模型的输入/输出费率、币种及费率版本；额度和账户分别维护。
3. 在工作详情的“自主交付”设置检查脚本、修复次数、目标/员工最长运行时间、检查点和是否允许换人，明确授权后保存。
4. 新对话描述目标。需求明确后先校验并冻结架构，再生成模块实现计划，最后安排依赖全部模块的集成任务。
5. 查看契约、实际检查、自审结论和修复记录。上限、证据不足、权限/预算变化或未知进程会转为“需要处理”。

检查配置：

```json
[{"id":"tests","args":["scripts/verify.mjs"],"timeoutMs":60000}]
```

宿主使用当前 Node 和 argv 运行项目内脚本，不经过 shell，不接受模型生成的命令。脚本应已纳入项目 Git 基线或非 Git 项目的托管输入快照，验证真实功能、接口及错误路径，退出码非零表示失败。其他语言/npm/集成测试可由已授权 Node 脚本组织，并关闭自己的子进程。检查不得修改交付源码；修改会使指纹失效。验证进程不继承邮箱凭据和名称含 KEY/TOKEN/SECRET/PASSWORD 的环境变量，需要外部凭据的检查须另行设计配置入口。

## 架构门槛

模块必须声明唯一 ID、文件边界、前置模块、风险、推理难度、估计工作量、接口消费者及 request/response schema、数据结构 schema、验收条件和已授权检查 ID。消费者只能是已有模块或 external。边界不得重叠，依赖不得成环。

接口与数据结构在冻结前使用 Ajv 校验并编译，默认 JSON Schema 2020-12；显式 `$schema` 也支持 `http://json-schema.org/draft-07/schema#`。非法关键字类型、未知关键字/格式、不可解析的引用和未支持的方言会被拒绝。已安装常见 format 校验，不自动下载外部 schema，不借用其他模块的 schema 缓存。旧计划在执行/恢复前重新校验并核对摘要。契约有效仍不等于实现正确，实际功能和接口必须由验收脚本验证。

宿主保存契约版本与 SHA-256。每个模块恰好一个实现负责人，任务不得超出边界，必须满足契约依赖，计划须覆盖所有模块。所有员工收到同一完整契约，属于必需上下文，不能静默截断。接口、边界或需求变更须重新确认并生成新计划。

最终集成任务接收全部模块的冻结 Git 交付；审查看到当前真实模块文件，不只前置文字报告或空集成差异。当前最多 24 个模块、32 个计划步骤，完整契约最多 18,000 字符；超过范围需拆分目标。

## 自动质量闭环

实现完成 → 宿主执行实际检查 → 校验指纹 → ApiX 对照测试、代码、差异及契约自审 → 再校验指纹 → 冻结验收 → 推进依赖。

失败保存检查 ID、退出码、超时、输出及审查问题，并生成 `autonomy_repairs` 修复任务记录。修复在原任务节点工作区继续，创建新 Run 和启动审批，保留原始任务及每轮指令，不重放旧运行指导。所有轮次遵守同一契约。运行失败或反复修复可以换到另一位满足质量、额度和授权条件的员工。修复上限按模块计算，整个目标另有时间上限。

ApiX 自审不能称为独立审查或人工批准。代码差异、当前文件或二进制内容超出完整自动审查范围时转人工检查，不依据截断内容通过。差异上限为 12,000 字符，当前代码上下文最多 100 个文件、70,000 字节。

质量、权限及预算条件满足，但员工暂时受并发、暂停或资源限制时，修复记录进入“等待执行资源”。重复监督不会重复创建记录或消耗修复次数；资源恢复后重新检查条件再派发。依赖该修复且从未执行的干净任务继续等待。未知进程、交接冲突、人工拒绝和能力/预算不满足仍需处理，不自动绕过。等待时间计入目标总时间上限；后续人工运行不会继承旧运行的等待返工。

所有模块和最终集成验收后才完成目标。完成表示托管工作区交付满足已授权检查及 ApiX 自审；不自动应用源仓库、发布、推送或合并 GitHub PR。

## 难度与成本路由

难度独立于工作量。难度决定声明的推理能力是否满足门槛；工作量为每次调用的预计输入/输出 Token 和预计调用次数。通过能力、权限及额度筛选后，优先比较同币种预测费用，再考虑可用性、验收历史和队列。

```text
预测最小币种单位 = ceil((输入Token × 输入费率 + 输出Token × 输出费率) × 调用次数 / 1,000,000)
```

费率单位为币种最小单位/百万 Token，必须匹配声明模型，来源和费率版本随候选结果记录。未知保持未知，不隐式换汇。例如难度 2 的大量格式处理可交给能力 2 且费率低的员工；难度 5 的短小并发问题会先排除能力不足者，再比较费用。

这是基于模型估计工作量、用户能力档案和费率的可解释路由，尚非自动能力评测或供应商价表/账单同步。预测不授予费用上界；执行与每次返工仍经过预算预留，经理架构和审查推理也沿用经理预算。历史费用未知不会为了重试结算为零，不能保证供应商账单硬封顶。

难度路由会显式选择声明模型，当前接入 Pi/Codex/Claude 的 `--model` 参数。传统任务沿用 CLI 配置；其他适配器的显式模型选择尚未验证，会被排除，不用默认模型冒充所选价格版本。认证账户仍由用户配置。

## 监督、重规划与恢复

高风险检查间隔为设置值的一半，普通风险使用设置值，低风险为两倍。检查点持续发送并绑定当前 Run，要求员工报告及完成确认。两个过期未完成的检查点、员工阻塞或运行超时会请求停止已知运行。

只有服务收到原员工结束状态后才修复或换人。未运行的排队任务遇到员工不可用、额度暂停或资源等待，可在原模块和依赖范围内调整负责人。已运行任务保留工作区及证据后重新审批。调度不改变需求、增设模块或批准新账户。

未知进程、未解决交接冲突和人工拒绝不会自动重试。重启中的验收记录转为 interrupted，保存可用的 PID、入口及目录；用户检查原进程并确认停止后，用最新恢复指纹继续。系统不会依据可能复用的 PID 自动杀进程。

关闭自主交付停止后续检查、验收和返工；运行员工可通过“停止工作”停止。重新授权不静默继续旧版本计划，既有人工恢复和需求修订入口仍保留。

## API 与持久化

- `GET/POST /api/projects/:id/autonomy`：策略读写，开启需要 approved=true、版本一致和项目自动协作；当前有工作时不能扩大策略，关闭立即生效。
- `POST /api/coordination/sessions/:id/autonomy/resume`：传最新 revision、fingerprint、reviewed；中断验证另需 confirmedStopped。
- 会话详情包含 autonomyPolicy、autonomy（契约/状态/检查/修复）和 autonomyRecoveryFingerprint。
- SQLite 新增 autonomy_policies/plans/tasks/checks/repairs，不重置已有数据；消息和审计沿用既有账本/mailbox。
