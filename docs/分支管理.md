# 分支管理

本仓库是独立的 ApiX Control Center 仓库，默认分支为 `main`。稳定变更合入 `main`；开发工作使用短期 `codex/<主题>` 分支，完成后通过合并请求合入并删除该短期分支。不要将 Pi 的 `main` 直接合并进本仓库；Pi 是外部运行时，接口适配器应单独验证和更新。

第一次独立版本来自旧仓库 `Makimasdog/ApiX` 的 `codex/agent-os-messaging`，源提交为 `44fb039de`。旧仓库是 `earendil-works/pi` 的 fork，其 `main` 仍保留 Pi 基线，`codex/agent-os-mvp`、`codex/agent-os-phase3`、`codex/agent-os-phase4`、`codex/agent-os-director`、`codex/agent-os-messaging` 记录 ApiX 各阶段工作。它们只作为迁移历史，不是新仓库需要合并的功能分支。

迁移期间不删除旧仓库的分支或工作树：旧本地仓库有未完成的其他工作，贸然清理会丢失状态。新功能统一提交到本仓库。

## 协调系统重构分支

`codex/agent-coordinator` 基于 `codex/control-plane-modules` 的 `7b18690` 开发，包含 mailbox/调度拆分和本次 TypeScript 协调系统。前置模块拆分 PR 尚未合并时，协调系统 PR 以前置分支为目标，避免重复审查。先合并模块拆分，再将协调 PR 改为 main；确认两个 PR 均已合并后再清理短期分支。开发中不重写 main 或历史分支。
