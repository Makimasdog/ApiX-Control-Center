# ApiX 界面设计规范

适用：Windows Electron 桌面版与浏览器界面。目标是让对话、项目、员工和待处理事项清楚可见；复用现有前后端，不改变模型、审批、预算或任务执行契约。

## 依据与适用边界

查阅日期：2026-10-21。依据 Apple 官方 [Layout](https://developer.apple.com/design/human-interface-guidelines/layout)、[Typography](https://developer.apple.com/design/human-interface-guidelines/typography)、[Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility)、[Sidebars](https://developer.apple.com/design/human-interface-guidelines/sidebars)、[Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons) 与 [Dark Mode](https://developer.apple.com/design/human-interface-guidelines/dark-mode)。

采用清晰层级、相关内容分组、渐进展开、语义颜色、系统字体、可见焦点和随可用空间调整布局等原则。Windows 继续使用原生窗口、菜单和系统字体，不仿制 macOS 窗口按钮，也不捆绑 Apple 字体。本项目不宣称通过 Apple 或 WCAG 认证。

本机安装的辅助技能：

| 技能 | 来源 | 用途 |
| --- | --- | --- |
| apple-design | [dickwu/apple-design-skill](https://github.com/dickwu/apple-design-skill) | HIG 参考及跨平台设计审查 |
| ui-ux-pro-max | [nextlevelbuilder/ui-ux-pro-max-skill](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill) | 可访问性、交互、配色与布局建议 |

它们是社区技能，不是 Apple 官方技能。安装在用户的 Codex skills 目录，不修改其他项目。已检查入口和参考内容；ui-ux-pro-max 搜索脚本只读取本地设计数据。其设计系统搜索两次返回营销落地页结构，与本产品不符，未采用或持久化该布局；本次采用 HIG 基础原则、搜索到的简洁工具界面方向和键盘焦点建议，并自行确定适合控制台的语义配色。

## 视觉基础

全局令牌位于 `web/styles/design-system.css`，作为最后加载的共享样式；已有模块的常用硬编码颜色改用同一组令牌。

| 角色 | 浅色 | 深色 |
| --- | --- | --- |
| 背景 | `#f5f5f7` | `#17191d` |
| 侧栏 | `#eceef2` | `#1c1f24` |
| 内容表面 | `#ffffff` | `#24272d` |
| 主文字 | `#1d1d1f` | `#f4f5f7` |
| 次要文字 | `#515967` | `#bdc4cf` |
| 操作强调 | `#0066cc` | `#8cbeff` |

- 跟随系统明暗主题，当前没有另设应用外观开关。
- 使用系统字体栈，Windows 优先 Segoe UI 与微软雅黑；取消 Google Fonts 网络导入，离线和 Electron CSP 下均能正常显示。
- 桌面正文约 14px，表单 13px，窄屏输入 16px；元信息保持可辨认，代码使用等宽字体。
- 统一按钮、输入框、边框、圆角和间距；蓝色用于主要操作和选中状态，成功、警告、错误继续有文字说明。
- 常态内容采用不透明表面，只对浮层使用较明显的阴影，避免装饰干扰任务内容。

## 布局与交互

- 主侧栏统一显示工作区、项目与历史；当前页面使用 `aria-current="page"`。
- 760px 及以下改为抽屉导航。关闭后侧栏 inert；打开时背景主体 inert，Tab/Shift+Tab 在导航内循环，Escape 或遮罩可关闭并恢复焦点。原生模态框打开时仍由模态框管理键盘操作。
- 对话默认聚焦消息区，“交付与详情”按需展开；宽屏为旁栏，窄屏为覆盖式面板。
- 总览宽度限定在内容区，统计卡和详情分组在窄屏重新排列；看板允许自身水平滚动，不扩大整页宽度。
- 所有交互控件保留可见键盘焦点；支持跳过导航，模态框具有可访问名称。
- 遵循 `prefers-reduced-motion`，减少动画；高对比与减少透明度设置有相应样式。
- 保留既有服务配置、费用批准、任务审阅、错误状态和危险操作确认流程。

## 验证入口

```powershell
npm run build
npm run check
# 需要可用的 Playwright 模块及其 Chromium；不加入应用运行时依赖。
npm run test:ui:browser
```

若 Playwright 不在项目模块搜索路径，可通过 `APIX_PLAYWRIGHT_MODULE` 指定已安装的 `playwright/index.mjs` 绝对路径。验证创建隔离的本地协议夹具，不使用个人应用数据、不调用真实模型；截图及报告写入被 Git 忽略的 `.tmp-ui-review/`。

自动检查覆盖 9 个页面 × 1440/1024/768/390px × 明暗主题；检查页面宽度、可见按钮/输入名称、导航关闭与焦点恢复、详情开合、JavaScript 错误及主要语义配色对比度。长列表、真实任务和第三方 MCP 内容仍需按使用情况继续验证；自动结果不能替代屏幕阅读器人工验收。

0.2.0 将应用与协作设置分离为独立页面，以“与 ApiX 对话”为主任务入口；旧协调器保留为“多 Agent 任务（高级）”。交互与执行取舍见 [重构决策](../归档/设计/20261022-ApiX交互与执行重构决策.md)。
