## 总览行为

「ApiX 等待你的决定」汇总当前项目的协作流程和主对话。每个主对话自身最多一条，按以下优先级判断。

1. 会话需要检查或存在未持久化的安全异常时显示「对话需要检查」。
2. 会话正在等待用户决定时，按请求类型显示「操作等待审批」或「对话等待回答」。点击后在原对话打开现有请求。
3. 会话本轮完成且空闲时，若当前任务最新的冻结版本是尚无审阅决定的代码交付，显示「代码交付等待审阅」。点击后打开原对话的交付详情。审阅页按现有规则复核证据与版本，过期的交付可能仍有待办，需要检查其详情。

员工原生提问和单次审批各按一条请求列出，可与同一对话的其他待办并存。列表显示原对话标题、员工名和请求类型。点击后返回原对话，滚动并聚焦该交互 ID 的卡片。若请求在导航前已处理或失效，对话显示提示。回答、批准、拒绝或请求失效后，待办随下一次读取自动移除。

验收或保存修改意见会移除该版本的待办。重新提交代码会按最新版本计算。归档、删除的对话从列表排除，恢复后重新按当前状态计算。只读说明仍可在原对话查看。两个来源在总览打开期间随快照刷新，其中一个读取失败时保留另一个的结果并提示重试。

## 接口与边界

`GET /api/assistant/sessions?projectId=<id>&view=attention` 在现有所有者访问边界内返回待办列表。会话自身的待办项为 `{id,title,action}`，动作包括 `inspect`、`approve`、`answer` 和 `review`。员工请求的动作是 `worker_answer` 或 `worker_approve`，另含 `interactionId` 和 `employee`。员工请求复用原对话的有效请求查询，仅覆盖当前关联的同项目子流程。待办查询无需扫描工作区，普通会话列表沿用原响应。提交仍由原 Run 或会话入口校验。

协作流程继续使用宿主派生状态。若主对话和子流程分别需要检查，它们可分别列出。员工原生提问和单次审批可在发起对话或 Run 面板处理。 [工作台实施契约](../设计/2026-10-30-外部Agent运行与协作工作台实施.md)

## 后续可对照验证的设计

- 可继续验证在发起对话提示员工停止未知，并定位该 Run 的停止证据。
- 若要验证主动工作，先用单个明确授权的 GitHub 事件源跑通事件入站、规则命中、去重、派发、原线程回报。先用本地事件回放验证同一事件只产生一个任务、越权或不匹配事件零派发，再评估常驻部署。该路径涉及新的外部写入和凭据边界。
