# 工具、MCP、上下文、监督与记忆

本轮参考本机 `E:/Projects/wyy/Mewcode` 的工具注册、分层压缩、邮箱通知和记忆召回机制，在 ApiX 现有 Node/TypeScript 主循环中实现；没有修改 MewCode，也没有更换 ApiX 的执行与验收引擎。

## 使用入口

1. 在“Skills 与 MCP → MCP 服务”选择项目，添加服务配置。stdio 使用可执行文件或 JS 入口的绝对路径；HTTP 使用 Streamable HTTP URL。
2. 勾选启用并批准服务连接/服务器程序执行后保存，再点击“连接并发现”。服务程序使用本机账户权限，目录提示不是操作系统沙箱；请只启用可信服务。
3. 与 ApiX 对话。主循环可以通过 `search_tools` 按用途发现外部工具，工具的完整 Schema 才加入当前会话目录。调用经过现有项目权限和按次审批，远程 `readOnlyHint` 不授予只读放行。
4. 大工具结果在对话中显示预览和引用，可点击“分段查看完整内容”；模型使用 `read_context` 读取同一份完整数据，不重新执行原工具。
5. Agent 通过 `remember` 提炼的记忆为“待确认”。在对话右侧确认后才自动召回；用户直接填写的记忆立即生效。删除、修改和确认使用版本校验。

stdio 配置示例（替换为实际路径）：

```json
{
  "id": "my-service",
  "name": "我的服务",
  "transport": "stdio",
  "command": "C:/path/to/node.exe",
  "args": ["C:/path/to/mcp-server.mjs"],
  "env": ["SERVICE_API_KEY"],
  "headerEnv": {},
  "enabled": false,
  "version": 0
}
```

HTTP 配置使用 `"transport":"http"`、`"url":"https://service.example/mcp"` 和 `"headerEnv":{"Authorization":"SERVICE_AUTH_HEADER"}`。环境变量值应是服务实际要求的完整请求头值。环境变量映射只保存变量名称，不保存变量值；凭据请通过变量提供，不要粘贴到 command、args 或 URL。管理者凭据和旧员工身份不会传给 MCP。

## 模块与契约

| 模块 | 职责及约束 |
|---|---|
| `src/tool-registry.ts` | 统一名称、描述、JSON Schema、只读属性与版本；参数先校验再执行；格式错误作为可修正观察返回主循环 |
| `src/mcp-manager.ts` | 官方 SDK 1.32.1 的 stdio/Streamable HTTP 客户端；项目配置、工具发现、凭据环境变量引用、取消与关闭 |
| `src/assistant-context.ts` | 大结果/大工具参数完整保存在 SQLite，提供 SHA-256 引用和会话归属校验；压缩边界不拆开工具开始与结果 |
| `src/assistant-memory.ts` | 当前项目已确认记忆的相关性排序，中文二元词与英文关键词，用户偏好/反馈优先，最多 5 条和 6000 字符，标记过期观察 |
| `src/assistant-loop.ts` | 接入注册表、发现、引用、分层压缩、记忆召回和持久化监督计数；继续执行审批、文件指纹、费用与完成门槛 |
| `src/coordinator.ts` / `control-plane.mjs` | 员工事件通知主循环，快照包含任务、进度报告、验收和修复状态；MCP 装配不向模型暴露配置写接口 |
| `web/mcp-settings.ts` / `web/assistant.ts` | 项目服务配置与工具发现；带服务描述/版本的批准请求、记忆确认、完整结果分页 |

模型仍使用 ApiX 的 JSON 动作契约。注册表提供实际参数 Schema，但本轮没有改用供应商原生 function calling，也没有引入第二套主 Agent 引擎。

## 上下文预算与证据

默认声明窗口为 32768 Token，可通过 `.env` 的 `APIX_ASSISTANT_CONTEXT_TOKENS` 调整，不应超过模型实际窗口。估算采用 UTF-8 字节数除以三，输入目标为窗口的 72%，其余预留给输出和估算误差；不是精确 Token 计数或费用测量。

先把超过 8000 字符的工具结果、工具参数和委派报告转换为预览及引用，完整原文仍保留。然后在输入预算不足时分批摘要旧事件，保留近期完整工具执行组、初始请求、最新请求、文件/结果引用和当前宿主状态。一次最多处理四个摘要批次，单条输入或工具目录无法容纳时明确暂停，不静默删除约束。摘要调用仍经过原管理者预算预留与取消机制。

模型对大结果的读取是按需进行的，不能将“拿到引用”表述成“已经看完”。实际验证是否成功和交付文件指纹仍由宿主保存和检查，不依赖摘要中的声明。

## 监督的实际行为

关键协作事件通知主循环；30 ms 内合并通知，另保留原每秒检查作为恢复与去抖后的兜底。员工任务状态、报告和验收证据快照摘要未变化时，不触发模型推理。普通变化至少间隔 30 秒，阻塞可立即唤醒；每次委派最多六次监督唤醒，计数和最后快照持久化，重启不会清零。

被唤醒的 ApiX 可检查员工、发送指导或请求用户决定。员工尚在执行时禁止主循环并行写文件、执行命令或重复委派；确定性的排队、改派、检查和返工仍由宿主管理。主 Agent 选择继续等待不会把整个任务标记完成。停止、权限撤销和状态未知的恢复规则继续生效。

## 安全和能力边界

- MCP 连接/发现超时 10 秒，工具调用超时 30 秒；传输取消或错误后的外部副作用可能已发生，记录不确定状态并暂停，不自动重放。`isError` 结果不会显示为成功。
- MCP 配置变化使缓存目录和旧批准失效；必须重新发现工具。一个服务失败不会阻止其他服务发现，但失败服务的旧工具会移出目录。外部 Schema 不下载引用文档。
- HTTP 仅支持 HTTPS 或本机 HTTP，拒绝 URL 内凭据、查询参数和跨地址重定向；凭据通过环境变量映射提供。暂未提供 OAuth 登录界面、旧 SSE、采样或交互式 elicitation。
- MCP 服务并不是受 ApiX 文件工具路径检查约束的 OS 沙箱。外部服务的行为、外部收费及远程写入验收仍需对应服务和实际检查支持，不能用本地文件验证来证明任意远程操作正确。
- 记忆只在当前项目内自动召回；没有跨项目全局偏好或额外 LLM/向量检索。候选记忆不自动生效，记忆不是授权。用户更新记忆会使正在推理的旧决策失效。
- 没有实现自动重写冻结架构、无限循环或全部故障的透明恢复。完整上下文与历史持续保存在本地，暂未增加自动清理历史的策略。
