# 使用指南

更新：2026-10-18；基础功能基线 08bf165，另含本轮主 Agent 可信验收 P0，证据见[变更回顾](变更回顾.md)。安装入口见[项目 README](../README.md)，文档选择见[阅读导航](README.md)。

## 启动与升级

需要 Node.js ≥ 22.19.0（SQLite 支持 FTS5）和 Git；CLI 员工仅在委派任务时需要。

```powershell
npm ci
npm start
```

打开 http://127.0.0.1:4173/ 。默认数据在用户目录 .apix-agent-os/，数据库为 apix.sqlite。升级代码或修改环境变量后重启服务，不删除原数据库或托管工作区；升级前备份数据目录。

| 配置 | 用途 |
| --- | --- |
| PORT / APIX_DATA_DIR | 服务端口 / 数据目录 |
| APIX_ASSISTANT_CONTEXT_TOKENS | 声明上下文窗口，默认 32768，不应超过实际模型窗口 |
| APIX_PI_ENTRY / APIX_CODEX_ENTRY 等 | 可选员工 CLI 的绝对 JS/原生入口；不是目录、命令名或 Windows 脚本包装器 |
| APIX_MANAGER_PI_ENTRY | 已停用，主 Agent 不依赖 Pi |

根目录 .env 自动加载，进程已有同名变量优先。密钥仅放在本地；供应商中心可直接保存 API Key，已有环境变量引用继续兼容。URL/模型示例变量不会自动配置到界面。阿里别名规则见项目 README。

## 项目与对话

1. 添加项目可浏览服务所在电脑的文件夹或手工输入；Windows 路径别名不能重复创建项目。
2. 选择“与 ApiX 对话”，描述目标。ApiX 可直接用项目工具执行或委派复杂任务，普通问答无需先建员工计划。
3. 需要批准或选择时，在弹窗核对并回答；用户拒绝不会扩大权限。停止后先检查已有结果再继续。
4. “协作进度”用于查看已有流程的员工执行、计划、恢复与验收，不再提供新建目标聊天框。当前流程补充保留在展开项中；新的需求统一在“与 ApiX 对话”中提出。
   任务协作图按真实依赖展示执行步骤与并行分支；点击目标或任务节点进入详情，通过“返回协作图”回到全局。节点详情包含完整目标、员工、前后步骤、运行报告和代码检查/验收/恢复入口。图支持缩放与滚动；状态未知、失败或阻塞不代表可以直接重试，原确认与验收规则继续生效。
5. 侧栏按项目显示主对话和协作流程，已归档、最近删除可恢复。活动、排队、待批准或未知任务须先处理，不销毁执行证据。

非 Git 或无首次提交项目可建立托管快照和 worktree，仍须安装 Git，不强行初始化原目录。快照的排除项、容量及链接限制见[自主交付参考](参考/自主交付与模块契约.md)。

## 模型与思考强度

在“应用与协作设置 → Agent 供应商中心”新建供应商，填写 Base URL、模型 ID、协议和 API Key，再应用到 ApiX；本地回环服务可免密钥，Codex 与 Claude Code 员工也在同一页面绑定供应商。ApiX 直接调用 Chat Completions、Responses 或 Anthropic Messages，不生成管理者 Pi 配置。

输入框上方按对话选择模型和强度；已有对话保留供应商连接快照，刷新、重启后保留。全局设置提供新对话默认值，切换模型重置强度。运行、委派或等待批准时先处理当前工作再更改。

已核验 DeepSeek Flash/V4 Pro 的默认、关闭、低、高、最高，未知供应商/网关使用默认。规划、摘要、监督和验收继承对话配置，员工模型单独维护。保存不证明模型访问权限，连接测试须批准费用，成功仅证明本次推理。

## 员工、额度与自动协作

Pi/Codex/Claude/Gemini/OpenCode/Kimi 有内置适配器，安装认证后直接注册员工，不将保留 ID 注册为自定义适配器。桌面应用发现不等于可托管 CLI，自定义接入需真实非交互入口。

Codex 支持时可只读查询额度窗口和模型目录；没有接口的运行时显示未知。人工账户快照与实际额度分开，订阅百分比不换算金额，未知费用保留预留。预算不是供应商硬封顶。

员工档案可指定模型。Codex 强度支持 auto/low/medium/high/xhigh，auto 按任务难度映射，区别于主模型的供应商参数。

复杂任务先准备员工、持续授权及实际验收脚本；冻结模块边界、接口/schema、数据结构、依赖和验收后再分派。实测和 ApiX 自审均通过才冻结交付，失败在已授权次数、时间和费用内返工，最终集成也须验收。自审不是独立审查。

## 查看结果与排障

直接主 Agent 修改代码后，普通 `run_command` / `verify` 的零退出码仅表示命令执行结束。可信验证须先用 `configure_verification` 请求用户批准固定 Node 检查和 `writablePaths`，再用 `run_check {checkId}` 运行全部检查；不需要安装员工或开启多 Agent。批准前应核对真实检查脚本和可修改范围，不能批准空洞测试。只读问答及无待验证修改、进程结果明确且前后代码指纹相同的诊断无需代码验收，也不获得可信通过状态。

契约冻结可修改范围以外的项目文件，包括检查脚本、配置和本地依赖。冻结文件、Node 运行时或契约变化须重新批准；再次写入或当前代码变化须重验。证据保存在会话事件与输出引用中，重启后仍可核对。全部必要检查通过只得到 `verified`，不代表正式 `accepted`；缺配置或契约失效显示待审查，中断/未知结果须检查后恢复，不自动重放。

P0 仅支持项目内 Node 脚本，单次 100–120000 毫秒；完整扫描限 3000 项、8 MiB，冻结扫描包含通常忽略的依赖/临时目录（Git 元数据除外）。超限拒绝授信，不能缩小冻结范围来掩盖检查依赖。大型项目仍需人工审查或使用现有委派流程；本轮未改写委派的自主验收机制。

| 情况 | 处理 |
| --- | --- |
| 查看事件 | 按类型筛选、搜索最近最多 100 条已加载记录，展开原始日志；不是全历史搜索 |
| 确认验收 | 先核对真实差异和指纹，多个候选须指定任务编号；口头回复不改变实际状态 |
| 一直排队 | 确认前置已 accepted，再查暂停、额度、预算、并发和权限；队列每五秒复核 |
| 状态未知 | 检查原进程确已停止、工作区当前指纹，再显式恢复或换人，不自动接管未知进程 |
| 更改授权被拦截 | 扩大权限前先处理冲突任务；已有充分权限可复用，开关不恢复旧任务或解除运行时暂停 |
| 中文变成问号 | 核对 CLI 版本和原始事件；UTF-8 解码不能还原原始输出已丢失的文字 |

Git 冻结交付不等于应用源仓库、合并、推送或部署，导出/应用前仍须检查目标和差异。

### 主对话的任务交付审阅

打开“交付与详情 → 本任务交付”，核对净变更、未归属变化、冻结文件、可信检查及日志，再“确认验收此版本”。验收绑定任务、交付与会话版本；口头确认和模型输出不替代此动作。查看历史交付不修改当前验收。工作区、契约、必要证据或安全状态变化时，当前版本显示过期，历史验收记录保留。

“保存修改意见”持久化意见并使本轮检查失效；不会回滚文件、扩大权限、增加预算或自动启动模型。确认后可用“按意见继续”修复重验，生成同任务的新版本。独立工作请点“开始下一任务并发送”；普通追问、审批、停止和恢复仍属于原任务。旧会话缺少初始基线时不补造历史，请明确开始下一任务。

净差异从任务开始时的实际文件字节计算，Git 未提交修改也作为基线保留。命令生成文件和外部修改会被检测，无法证明来源时显示未归属。基线/最终快照保存到现有 SQLite，工作目录不新增审阅文件。扫描限 3000 项、8 MiB，文本限 256 KiB/文件；二进制、大文本显示哈希元数据，差异有截断提示。审阅资料最长 30 天、合计 128 MiB，容量淘汰后只能回看元数据，不能据此验收；日志沿用 7 天保留期。可信契约原有完整冻结范围没有缩小。

## MCP、上下文与记忆

「交付与详情 → Token 用量与优化」可刷新当前任务、会话及项目的供应商实际用量，区分未知字段与上下文估算。空闲时可为当前对话启用「节省」模式，按需加载工具参数并更早折叠旧工具结果；完整记录继续可回读。费用及外部 CLI 内部用量仍未知，细节见 [Token 用量与优化](专题/Token用量与优化.md)。

在“Skills 与 MCP”按项目配置可信服务，批准启用后连接发现。服务描述和只读提示不授予权限。大结果完整保存，引用可分段读取，不重复执行工具。

上下文按声明窗口估算并压缩。用户记忆立即生效，Agent 候选确认后才自动召回；记忆限当前项目，不是跨项目无限上下文。配置详见[工具上下文与记忆](参考/工具上下文与记忆.md)。

## 能力边界

循环和返工都有上限，不承诺任意规模系统无感完成，也不自动重写全部冻结契约。CLI 必须主动读取 mailbox 才能采纳指导，未确认不能声称已采纳。

管理 API 信任本机用户，没有公网多用户认证或 OS 沙箱。路径、worktree 与写入范围不是系统隔离，停止不能撤销已发生副作用。

真实模型权限、费用、限流、CLI 版本及业务验收覆盖须在目标设备验证。历史测试不代表当前完整回归，证据见[变更回顾](变更回顾.md)。默认主对话轮询持久化事件，协作目标另有 SSE。


## 本机项目记忆与上下文（2026-10-23）

“更多设置 → 项目记忆”统一管理 ApiX、协调器和员工可用的主题记忆。手工添加或确认的记忆为 active；Agent 提出的内容默认是 candidate，确认后才召回。可筛选状态、来源、作用范围、更新日期，编辑、停用、删除，并查看会话使用记录。删除停止召回，审计版本仍保留。结构化项目档案保留在同页独立区域，不是第二套自动记忆。

“查看记忆设置与来源”可关闭本项目自动记忆、显式开启自动确认，或调整自动压缩阈值（50%–90%，默认 75%）。自动确认只影响后续候选，不追认旧候选，任何模式均不能覆盖用户确认的同名内容。普通聊天不保存；Agent 需要引用明确约定、偏好或纠正的原话，或已观察工具结果中的可复用经验。常见凭据、密码、令牌、邮箱/手机号与进程环境中的已知密钥被拦截；请勿把其他私密资料作为记忆提交，启发式检测不等于通用隐私识别。

MEMORY.md 是 SQLite 主题记忆生成的索引视图，不会向项目写入同名文件。索引最多 200 行或 25,000 UTF-8 字节，不含所有主题正文；主 Agent 用 read_memory 按需读取，相关正文还会在预算内召回。任务范围记忆只属于该任务，不沿整条旧对话传播。执行员工不会收到主对话全文，批准任务和需求始终优先，参考资料继续受 30,000 字符预算限制。

指令顺序：显式选定的管理级文件、用户私有文件、项目根目录、逐级子目录；同目录按 AGENTS.md、CLAUDE.md、APIX.md、本地私有文件、路径规则加载。支持 APIX.local.md / CLAUDE.local.md；根及已访问目录的 .apix/rules 与 .claude/rules 中 Markdown 支持 `paths: ["src/**/*.ts"]` 或 YAML 列表，glob 支持 *、**、?。子目录规则由最近访问的文件/目录激活；同层按文件名排序，后加载的具体规则优先。指令仍只是参考，不改变宿主审批、预算和验收。

导入语法为单独一行 `@relative/path.md`，含空格可写 `@"relative path.md"`。相对于导入文件解析，导入内容先于引用它的文件加载，最多 5 层，循环报错。项目外导入需在记忆页确认具体文件版本；内容变化会重新要求确认。用户/管理级文件也必须在当前项目显式选择，不会默认注入其他项目。凭据文件和越界链接仍被 projectPath 拒绝。单文件硬上限 16,000 字节，总加载量 64,000 字节；建议每文件 200 行以内，超出硬上限报错而不静默截断。页面展示路径、层级、行数、字节数和阻塞原因；编辑指令文件请使用项目编辑器，再刷新来源。

“与 ApiX 对话 → 交付与详情 → 上下文占用”展示窗口、估算已用/剩余及十类占用。优先使用本会话冻结的供应商窗口声明，其次内置模型目录，最后 APIX_ASSISTANT_CONTEXT_TOKENS（默认 32768）。可在已有供应商编辑表单填写窗口；现有对话仍保留旧快照，需明确使用当前应用配置。更换会话模型会清除旧模型的窗口声明。估算按 UTF-8 字节 / 3，不是服务端真实 tokenizer 计费值。

压缩前先裁剪旧活动提示等低价值事件、将旧工具输出折叠为引用，再对完整工具执行组进行摘要。手动压缩可填写重点保留内容，调用当前模型并沿用费用预算；运行中、待处理或安全状态未知的会话不能手动压缩。摘要及前后估算、原因、保留重点持久化；根指令、记忆索引和任务状态重新注入。assistant_events / assistant_outputs 不清除，read_context / read_output 引用保持可读。大到无法在窗口内保留完整执行组或静态指令的输入会明确报错。

### 数据迁移与回退

启动时幂等迁移 memories 到 assistant_notes，记录 migration-v1。旧 memories、memory_revisions 与 project_profiles 不删除；同名主题加旧 ID 后缀，不覆盖现有笔记。后续旧 HTTP 路径只适配统一服务，不再写旧 memories。敏感旧记忆保留数据库原值用于审计，但公共视图隔离且不召回；备份数据库也应按私有资料保管。

回退前先关闭 ApiX，备份数据目录中的 apix.sqlite 及仍存在的 WAL/SHM 文件（最好在正常关闭后复制整个数据目录）。旧程序可读迁移前旧表，但**不会自动包含新版新增/编辑的记忆**；新版数据仍留在 assistant_notes / assistant_note_versions 中。需要完全回到升级前状态时恢复升级前备份；需要保留升级后的编辑时，应先导出并人工核对规范表，不能声称降级自动回写旧表。不要在程序运行中替换数据库。


### 为外部 Agent 应用供应商（2026-10-23）

供应商记录与员工绑定是两步操作。“保存供应商”只保存配置，已绑定员工后续执行使用更新内容；未绑定员工继续沿用本机 CLI。员工卡片会显示当前来源和支持的协议，不兼容供应商以禁用选项显示原因。可点击“为此员工配置供应商”，填写控制台提供的真实地址、模型和密钥，再点击“保存并应用”；或先保存，再在员工卡片选择并应用。

Codex API 通道使用 OpenAI Responses，官方订阅登录选择 Codex 登录类型；Claude Code 使用 Anthropic Messages 并按服务要求选择 x-api-key 或 Bearer。一个仅提供 Chat Completions 的地址不能通过修改下拉框变成这两种接口。应由供应商提供对应接口与模型；当前实现不执行协议转换。参考 [Codex 配置文档](https://developers.openai.com/codex/config-reference/) 与 [Claude Code 网关文档](https://code.claude.com/docs/en/llm-gateway)。

地址仍含 `{workspaceid}` 等占位符时拒绝保存，请使用实际 Base URL。保存并应用时，如果员工运行状态或版本变化导致应用失败，配置仍已保存，页面会明确说明并显示当前真实绑定；处理后从员工卡片重新应用即可。切换只影响后续执行，不会替换已运行任务或自动重试失败任务。配置仅作用于 ApiX 启动的进程，不改写 CLI 全局文件。


### Electron 开发模式与自动更新（2026-10-23）

在 Windows 使用 Node >=22.19（建议当前已验证的 Node 24），安装依赖后执行 `npm run desktop:dev`。启动时只编译 TypeScript，直接运行仓库内桌面主进程与后端，不再复制全套分发资源或生成安装包。

保存 web 下 CSS/HTML/JavaScript 后自动刷新；前端 TypeScript 编译通过后刷新。保存 src 下源码或 server.mjs、control-plane.mjs、agent-discovery.mjs、tsconfig.json 后，必要时先编译，再停止旧后端进程树、重启并重新加载页面。连续保存会合并并按序处理。TypeScript 编译失败不重启，修复并保存后继续。Node 后端语法或启动错误记录到开发日志，修复后再次保存可触发重试。Electron 主进程、监听脚本、依赖或环境配置变更需退出并重新运行开发命令。

窗口标题带“开发版”，默认数据目录为 `%APPDATA%/ApiX-Control-Center-Dev`，与正式版 `%APPDATA%/ApiX-Control-Center` 分开；首次启动默认创建空开发数据，本轮测试已单独复制现有数据库与必要配置到开发目录，复制数据库使用 SQLite 一致性备份。两份配置后续不会自动同步。项目路径仍指向真实项目，数据库分离不等于项目文件副本；不要同时在两个版本对同一项目执行写任务。

后端自动重启会停止正在运行的任务，重启后遵循原有中断恢复检查；页面完整刷新也可能丢失尚未发送的表单草稿，请先保存。开发日志在开发数据目录 desktop.log。正式交付仍使用 desktop:dist；开发热更新仅对未打包且由开发命令启动的实例启用。


### 故障分类与恢复（2026-10-23）

主循环、模型通道与员工恢复统一使用带 schema:1 的故障分类。认证、地址/模型配置、欠费、速率限制、临时服务故障、超时、参数/版本冲突、协议错误、执行失败、存储异常和未知副作用分别处理；HTTP 错误正文只用于提取标准错误码，不回显供应商原始正文。

模型 HTTP 429、500、502、503、504，以及确认尚未连接的临时网络错误，最多请求 3 次，默认约 0.5 秒、1 秒指数退避并附加抖动；尊重 Retry-After，所有尝试共用原请求的超时预算。欠费码 insufficient_quota / quota_exceeded、402、401/403、404、部分输出后的断流、已发送但无结果的超时、传输清理不确定不自动重试。退避期间停止或撤销权限会中止后续请求。对话中显示重试次数和等待时间；这是模型推理请求重试，不会执行模型原生工具。上游账单仍由供应商决定，不宣称失败请求免费。

Agent 默认每 15 秒检查一次：60 秒无实际活动发送进度探测，至少两次探测后仍累计静默 5 分钟则请求停止；连续输出或当前运行的受认证邮箱收件/确认/回报均刷新活动。主持者发出询问本身不算 Agent 活动，探测未送达不计作漏答。即使持续输出，默认单次运行最长 30 分钟。可在当前数据目录 .env 中设置 APIX_AGENT_PROBE_MS、APIX_AGENT_SILENCE_MS、APIX_AGENT_MAX_RUN_MS，重启开发命令生效；静默时限至少为探测间隔两倍，总时限不少于静默时限。长时间无输出的合法工具任务也可能被判定为疑似失联，必要时增大时限。

失联停止后将原执行保留为 unknown，不能把进程退出等同于外部副作用已撤销；不会自动重跑。停止请求无确认超过 10 秒也转为未知；只操作本实例持有的进程，不按旧 PID 随意终止其他进程。服务重启后的旧运行仍使用原有 unknown/attention 与显式核对流程。

普通协作只对可修复且原运行已明确结束的失败，沿用既有原需求、授权、预算和工作区核对，在授权员工中最多修复 2 次或 30 分钟。认证、配置、欠费、速率限制、未知结果和代码交接冲突不进入盲目修复。自主交付使用项目设置的有限返工次数；准备派发时崩溃的修复记录会被隔离，核对原操作后确认恢复。前置任务通过验收后才释放后续依赖。

有副作用的主循环工具在派发前持久化 assistant_effects 凭据，保存操作 ID、输入范围摘要、状态和结果事件引用，不复制工具正文。同一用户轮次/任务/工具版本/参数与相关工作区状态下，重复决策复用已完成结果，页面提示“未再次执行”。远程 MCP 操作不因无关本地文件变化而重新派发。只有宿主在写入/命令启动前确认的预检失败（例如文件版本冲突、参数校验）可以交给模型修正后再试；开始后没有可信结果、凭据结算失败或崩溃时阻止自动重放；检查后继续会事务性记录人工核对，并允许新的后续决策。普通新消息不能绕过未知副作用。

这提供的是宿主管理操作的去重和保守恢复，不是整个系统的严格 Event Sourcing 或全局 exactly-once。Codex/Claude 等外部 CLI 自己调用的工具，及外部服务是否真正接受某次请求，不能仅凭 ApiX 本地日志完整判定；不确定时保留记录并请求核对，不自动补偿外部写入，也不自动退款、撤销发布或恢复被工具修改的文件。
