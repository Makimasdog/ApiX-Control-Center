# Phase 4：记忆与长期工作

## 使用流程

1. 在工作台选择项目，点击“新对话”。一个项目可以建立多个对话，各对话独立保存多轮普通任务、审批、结果和 Agent 事件。
2. 选择员工并提交任务。启动审批显示员工与项目目录。同一对话有待审批或运行中的任务时，先处理该任务；其他对话可以继续派发。
3. 在“项目记忆”维护项目概述、目标、约束和已确认决策，也可添加项目记忆或关联具体任务的记忆。ApiX 主对话会自动整理有用户原话依据的项目记忆；用户仍可编辑与删除。搜索仅返回当前项目记录。
4. 对失败、取消、状态未知或未通过验收的普通任务，点击“从此任务继续”，核对补充要求并新建续接任务，再单独审批启动。
5. 在“任务与员工”中可删除员工。员工仍是部门经理时，先到 Director 的“团队与仓库”更换经理；仍有活动任务时，先完成、拒绝或停止任务。

## 数据与运行边界

- SQLite v6 增加 `conversations`、`project_profiles`、`memories`、`memory_revisions` 与全文索引；旧普通任务会迁移为各自独立的对话。计划任务仍归属原有计划，不自动混入普通对话。
- 项目档案和项目记忆可在本项目后续任务中提供给 Agent；任务记忆只在同一对话中提供。上下文有数量和长度上限，Agent 仍须核对文件与运行状态。ApiX 只从主对话中的用户原话整理自动记忆，不自动采纳员工 Agent 输出，也不静默覆盖结构化项目档案。
- 全文检索使用 SQLite FTS5 trigram，短于三个字符的查询使用子串匹配。语义检索属可选项，当前未实现。
- 删除记忆会清除其修订记录和全文索引；删除员工采用软删除，以保留 Task、Run 等审计记录与历史姓名。
- 续接会创建新任务与新审批，记录其来源任务。服务重启后未完成的 Run 标记为“状态未知”，ApiX 不会自动接管或重放旧进程。旧进程可能已产生副作用，继续前须检查项目目录。

## 验证

`npm run test --prefix web` 覆盖多对话并行、上下文隔离、记忆检索和生命周期、员工删除、续接、重启恢复及旧版迁移。代码检查使用仓库根目录的 `npm run check`。
