# ApiX 功能与限制

## 本版已实现

- ApiX 管理者 Agent 与 Pi 推理底座、Pi 员工严格分离；自然沟通和带原话证据的需求提取。
- 每个项目多个目标会话；五项需求完整且无待处理冲突，用户确认版本后才进入计划。
- 结构化计划、员工和依赖校验、不可变计划版本、用户编辑与中途调整。
- ApiX/员工分别选择完全访问、请求批准、只读规划；任务授权绑定双方权限版本，收回权限使旧授权失效。
- Pi RPC、Codex JSONL、Claude/Gemini/Kimi stream-json、OpenCode JSON 和自定义 CLI 管理；Git worktree 隔离计划工作区，真实事件、输出和验收。
- 独立 SQLite 事件账本持久化用户交互、需求、计划、授权、任务、消息和交付物；事件序号回放、关键词检索、已确认历史需求的跨目标参考。
- 员工持 Run 凭据调用项目 mailbox；请求/回复关联、幂等冲突检查、超时/重试、交付物引用、监督拦截和租约锁。
- ApiX 对运行中的员工进行监督：无报告时主动请求进度，收到进度后在已批准范围内选择指导重点，发送 mailbox 消息或把阻塞提交给用户；用户可补充当前任务说明。
- 每个目标可选约束模式或对话模式；目标对话通过 SSE 输出澄清问题，最终以已校验、入库的会话状态为准。
- 对话模式可持续自然沟通，回复随真实模型增量输出；单轮正式回复上限 10,000 字符，非法或超限输出标明规则降级，已确认需求和审批门槛保持不变。
- 管理者模型平台目录通过只读 API 统一提供；自定义远程配置须提供合法 Key 环境变量名，保存前校验失败不覆盖原配置。保存成功不代表模型连通性已经验证。
- 员工详情页汇总当前任务、历史、真实进度报告和已采集的 Pi/Codex/Claude/Gemini/OpenCode/Kimi Token 用量；ApiX 可使用独立的自定义兼容模型 URL。
- 原有项目/员工/记忆管理保留；无活动任务员工可删除。重启后活动 Run 标为 unknown，不会自动重放。

## 需要准确理解的边界

1. 完整度是五项字段覆盖率，不能证明需求语义绝对完整；模型冲突检查也可能遗漏，用户确认仍是必要环节。
2. ApiX 不执行任务成果生成，但会生成沟通、需求摘要与任务规划内容。模型失败时退回规则引导，草案必须人工批准，绝不自动执行。
3. 请求批准发生在计划/任务启动层面，不逐个拦截外部 CLI 的工具调用。Pi 与自定义 CLI 没有新增系统沙箱；Claude 的批准后工具集合也不是文件或网络隔离。Gemini 普通模式使用 `auto_edit`，完全访问使用 `--yolo`；OpenCode 与 Kimi 的工具权限取决于各自 CLI 配置。完全访问模式会启用所支持 CLI 的跳过权限参数。
4. /api/agent/* 有运行凭据；管理 API 仍假设本机用户可信。知道本地管理端口的进程可以调用管理接口，本版本不构成恶意本机程序的安全边界。
5. 独立账本从本版启用后记录；历史数据仍在旧表中，不虚构升级前任意时刻的事件。快照重建最近一次已提交状态，未持久化的模型中间推理无法回放。记忆未提供向量检索或自动长期压缩。
6. 历史已确认需求和项目记忆作为非可信参考进入后续沟通，不能自动补齐当前需求。新沟通自动保存到独立账本，不自动覆盖用户维护的结构化项目档案。
7. 超时在消息查询/变更及事件流读取时检查；不是独立后台定时任务。租约锁不能阻止外部程序直接修改文件。消息拦截不能撤销已经发生的执行动作。
8. Agent 发现与执行分开。Gemini CLI、OpenCode、Kimi Code 有内置非交互适配器，仍需各自安装、认证与实际版本联调。Qoder 可通过用户验证的 CLI/包装器登记；Trae/WorkBuddy 暂无原生托管适配器。自定义命令有待处理任务时禁止替换。
9. 默认协调计划要求 Git 仓库；并行任务采用独立 worktree。不会强行删除工作区或合并员工成果，集成仍需检查。重启后的 unknown 需检查外部进程及工作区，当前没有重新连接能力。
10. 原生运行事件与消息流持久化；目标对话使用 POST SSE 输出澄清问题，消息监督使用独立 SSE。其他目标面板仍通过快照刷新。全量快照、账本关键词检索尚未针对超大历史优化。
11. Skills/MCP 与旧模型偏好页仍只保存浏览器配置。顶部 ApiX 推理模型设置实际作用于管理者 Pi；自定义 URL 使用独立 Pi 模型目录和环境变量中的密钥。员工模型沿用其 CLI 配置。
12. 新核心和工作台使用 TypeScript；旧 HTTP 服务、数据库迁移、mailbox、调度与部分管理 UI 保留 JavaScript。尚无桌面安装包、操作系统沙箱、任意第三方原生会话恢复。
13. 运行中指导取决于员工是否会读取 mailbox。通用 Codex/Claude/Pi CLI 目前只是从任务提示获知协作协议；不能保证其在单次 CLI 调用期间轮询 mailbox。ApiX 的进度请求和指导均保留记录，但未收到员工确认时不能宣称指导已被采纳。页面已区分送达、确认接收和员工报告处理，并显示当前运行是否真正领取过消息；自定义适配器可声明 mailbox 支持。
14. 员工 Token 数据依赖运行时是否报告用量；未报告的 Run 显示未知。新适配器按其结构化事件采集，第三方版本变更可能需要更新解析器。任务进度展示真实状态和员工报告，不编造百分比。SSE 中的临时文本仅供即时预览，完成后由已验证的正式消息替换。
15. 对话客户端断流不取消后端模型调用，用户应先同步正式会话再决定是否重发。前端已完成隔离假 Pi 浏览器验收，记录见 `协作/单Agent修复与验收结果.md`；前端回归直接导入实际模块，假 CLI 及自动化结果仍不能代替真实模型联调。
16. 本地模型目录通过用户点击读取，仅支持本机回环 HTTP/HTTPS OpenAI 兼容 `/models` 接口；5 秒超时、最大 1MB/1000 项，不跟随重定向。读取不写设置、不加载模型、不发送推理请求；目录可包含未加载或非聊天模型，需要另外验证对话能力。局域网/远程目录、原生 Anthropic 目录和后台自动发现尚未支持。

17. ApiX 目标计划和协作计划均要求前置任务验收通过后推进后续依赖；验收拒绝会阻塞下游。必需任务与需求上下文超过 30,000 字符时在启动进程前拒绝，参考资料按剩余预算截断并保留来源。消息领取只标记返回批次，未确认消息可重投；员工需正确确认并去重。凭据接口现按任务和运行隔离消息；同计划同事交接需指定目标任务。自动代码交接仍在下一批开发。

## 验证

npm ci → npm run check → npm test。自动化使用隔离数据库、临时 Git 仓库和假 Pi/Codex/Claude/Gemini/OpenCode/Kimi/自定义子进程；不替代真实安装版本的 CLI 联调。实际模型质量、第三方版本差异和授权参数仍应在真实环境验收。
