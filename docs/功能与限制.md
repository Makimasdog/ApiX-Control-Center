# ApiX Control Center · 功能与限制

需要 Node.js 22.19 或更新版本。无需前端依赖，默认只监听 `127.0.0.1:4173`。

```powershell
npm start
```

也可用 `PORT` 选择端口，用 `APIX_DATA_DIR` 指定 SQLite 数据目录。默认数据库位于用户主目录的 `.apix-agent-os/apix.sqlite`。打开后先添加已有项目目录、注册 Pi 或 Codex 员工，然后在首页与 ApiX 主 Agent 讨论目标。检查并编辑其提案后创建计划，再审查启动审批。

## 实际能力与边界

- Pi 通过 RPC JSONL 接入，托管运行默认关闭扩展以避免无法在工作台处理的交互；Codex CLI 通过 `codex exec --json` 接入。运行事件注明来源。未安装的 Agent 显示为不可用。
- ApiX 主 Agent 使用 Pi 的无工具 RPC 推理，结合项目、员工、近期对话与实际计划状态生成答复和结构化提案。Pi 缺失、未认证或输出格式无效时，界面明确显示规则型草案；这不代表 LLM 推理成功。
- 提案可修改目标、步骤、员工和依赖。创建计划后，用户可逐项审批，也可检查整份计划后一次批准所有预定步骤。ApiX 按依赖调度；未启动的步骤可修改并重新审批，也可统一取消。运行中的任务须先请求停止，再创建调整方案。询问进度不会自动生成另一份计划。
- Windows 上还会从开始菜单发现 Trae、Qoder、WorkBuddy。发现只表示检测到桌面应用；目前没有验证其外部会话和执行接口，因此不能将它们注册为可托管员工，也不会显示为可观察的 Run。
- ApiX 启动并管理的进程可请求停止；界面等待进程退出后才确认最终状态。服务重启后，未完成的 Run 标记为“状态未知”，不会自动重放任务或假称重新接管进程。
- 员工档案与 Task、Run、Approval、事件和交付物写入 SQLite。已完成任务可人工验收；点击任务可读取完整事件历史。
- 每个项目可建立多个对话。同一对话保留多轮任务和事件；有待审批或运行中的任务时，该对话暂不能提交下一轮，其他对话可并行。旧版普通任务迁移为各自独立的对话。
- 可删除无活动任务的员工；若该员工是部门经理，先在 Director 的“团队与仓库”中更换经理。删除后员工不再可分配，但历史任务仍保留员工姓名和运行记录。
- “项目记忆”页提供结构化项目档案、项目和任务记忆的维护、全文搜索、编辑与删除。ApiX 主 Agent 可从用户对话自动整理有原话证据的项目记忆，并标明来源；用户仍可修改或删除。不会自动采纳员工 Agent 输出，也不会自动覆盖结构化项目档案。档案和项目记忆会提供给本项目后续任务；任务记忆只提供给所属对话的后续任务。语义检索尚未提供。
- 失败、取消、状态未知或未通过验收的普通对话任务可显式“从此任务继续”。ApiX 会创建新的待审批任务并附上同一对话的历史；这不是连接到旧进程或原生会话，也不会自动重放旧操作。继续前应检查工作区实际状态。
- Director 页面支持确定性目标拆分、岗位匹配和依赖 DAG。每个计划步骤仍需单次审批；后置步骤会在前置任务完成后自动启动。
- 两个 Codex 逻辑员工可在同一项目的不同对话中并行启动独立进程；工作台提供“并行新对话派发”。普通任务直接共享项目目录，可能改动同一文件；需要独立工作区和集成审查时应使用 Director 协作计划。
- 计划任务在 Git 项目中使用独立 detached worktree，路径保存在 SQLite；非 Git 项目不会伪装成已隔离环境，因此 Director 计划会拒绝执行并提示无法创建 worktree。
- 普通 Codex 任务可在已选择、已审批的非 Git 项目目录中运行；此时 ApiX 仅附加 Codex CLI 的 `--skip-git-repo-check`，仍保留 `workspace-write` 沙箱。计划任务仍要求 Git 仓库。
- CLI 在生成 Agent 回复前失败时，任务结果会显示 stderr，完整记录也保留在事件中。
- 本机 Agent 进程可能访问项目外资源。审批表示允许 ApiX 启动该进程，并不构成系统级文件或网络隔离。
- 模型、Skills 与 MCP 页当前保存浏览器偏好和配置，不会改变 Agent 的真实运行配置，也不会启动 MCP 服务。运行时使用各 Agent 自身的认证和模型设置。
- 目前是本地 Web 工作台；尚未提供 Windows 安装包和自动更新。

运行 `npm test` 可用本地假 Agent 验证审批、执行、停止、失败、验收、迁移、主 Agent 提案、记忆整理、Codex 角色并行与重启恢复，不调用真实模型。

如果全局 CLI 的 Node 入口不在常规 npm 安装位置，可用 `APIX_PI_ENTRY` 或 `APIX_CODEX_ENTRY` 指向对应 JavaScript 入口文件。
