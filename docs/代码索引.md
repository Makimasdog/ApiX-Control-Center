# ApiX Control Center 代码索引

本仓库是 ApiX 控制中心自身的实现。Pi 与 Codex CLI 是外部运行时，代码通过子进程调用它们；Trae、Qoder、WorkBuddy 目前仅支持发现，尚无托管执行适配器。项目使用 JavaScript ES modules（`.mjs`、`.js`），没有 TypeScript 源码。

## 从用户目标到员工执行

| 环节 | 入口与实现 |
| --- | --- |
| Web 工作台 | `index.html`、`agent-os.js` |
| HTTP 路由 | `server.mjs` 的 `/api/director/messages`、`/api/director/proposals/:id/approve`、`/api/director/plans/:id/approve`、`/api/approvals/:id` |
| Director 对话与提案 | `control-plane.mjs` 的 `sendDirectorMessage`、`saveDirectorProposal`、`approveDirectorProposal` |
| 计划创建与审批 | `control-plane.mjs` 的 `createDirectorPlan`、`createCollaborativePlan`、`approveDirectorPlan`、`resolveApproval` |
| 依赖任务调度 | `src/task-scheduler.mjs` 的 `scheduleDependents`；由 `control-plane.mjs` 的 `setRun`、`acceptTask` 和 `resolveApproval` 触发 |
| 独立工作区与运行 | `control-plane.mjs` 的 `workspaceFor`、`launch`、`handleNative`、`recordOutput`；`launch` 启动 Pi RPC 或 Codex CLI 子进程 |

路径：`server.mjs` → `control-plane.mjs` 的 Director / 审批函数 → `src/task-scheduler.mjs` → `control-plane.mjs` 的 `launch` → 外部 CLI。前置任务完成或被接受后，调度器检查依赖与审批，再启动可运行的后置任务；失败等状态会阻塞后置任务。无依赖的已批准任务可分别启动。计划任务通过 `workspaceFor` 创建 Git worktree。

## 消息协议与监督

| 能力 | 实现 |
| --- | --- |
| SQLite 表 | `control-plane.mjs` 的 v8 migration：`agent_mailboxes`、`agent_messages`、`agent_message_attempts`、`agent_message_events`、`agent_message_artifacts`、`agent_locks` |
| Mailbox 注册与身份 | `src/mailbox.mjs` 的 `ensureMailbox`、`registerMailbox`、`assertActor` |
| 发送、关联、幂等 | `src/mailbox.mjs` 的 `sendMessage`，含 `replyTo`、`correlationId`、`idempotencyKey` 检查 |
| 收取与状态变化 | `src/mailbox.mjs` 的 `receiveMessages`、`ackMessage`、`completeMessage`、`nackMessage`、`expireMessages` |
| 权限与 Director 拦截 | `src/mailbox.mjs` 的 `assertActor`、`ensureMessageAccess`、`blockedByDirector`、`rejectMessage` |
| 交付物引用 | `src/mailbox.mjs` 的 `attachMessageArtifact`；运行结果由 `control-plane.mjs` 的 `recordOutput` 保存并回传 |
| 文件和资源租约 | `src/mailbox.mjs` 的 `acquireLock`、`renewLock`、`releaseLock`、`listLocks` |
| 实时事件流 | `src/mailbox.mjs` 的 `appendMessageEvent`、`messageEventsSince`；`server.mjs` 的 `/api/events/stream` 将事件以 SSE 推送 |

路径：`server.mjs` 的 `/api/messages` → `src/mailbox.mjs` 的消息函数 → SQLite 消息及事件表 → `server.mjs` 的 SSE 路由。任务启动时，`launch` 创建 Director 派发消息并确认收取；进程结束时，`recordOutput` 保存 artifact、发送关联回复并附加引用。完整指令直接送到外部 CLI，mailbox 负责记录和协调，不是 CLI 的传输协议。

## 当前边界

- `src/mailbox.mjs` 实现的是本机 Control Plane 的业务权限；HTTP API 没有独立 Agent 身份认证，不能将请求中的 `agentId` 当作可信身份。
- 资源锁是协作租约，不会拦截 Pi、Codex 或其他程序直接修改文件。
- Director 的计划与拦截包括确定性规则；复杂的自主重规划和第三方桌面 Agent 托管执行尚未实现。
- 数据库迁移和进程执行适配器仍在 `control-plane.mjs`；该文件仍较大，可在后续迭代继续拆分。

消息字段与 API 细节参见 [统一 Agent 消息协议](agent-message-protocol.md)。
