# ApiX Control Center

ApiX 是用户的管理者 Agent：通过对话理解需求、检查项目、规划和分派任务、监督员工、收集真实交付物。Pi 提供 ApiX 的推理和工具底座；执行员工使用独立 CLI 进程和权限。默认进入桌面对话工作区，左侧管理项目与对话，中间流式交流，右侧按需展开工作详情；管理总览和任务与员工页面保留。

本文对应 `codex/agent-provider-adapters` 分支截至 2026-10-13 的实现。代码基线 `93595d9` 已通过 [PR #6](https://github.com/Makimasdog/ApiX-Control-Center/pull/6) 合入 `main`；合入表示通过当前审查和 CI，不代表所有真实 CLI 都已联调或已发布稳定版本。

## 启动

需要 Node.js 22.19 或更新版本、Git，以及已安装并认证的 Pi（管理者推理）。执行员工可使用 Pi、Codex CLI、Claude Code、Gemini CLI、OpenCode、Kimi Code 或显式注册的自定义 CLI；每种 CLI 都需单独安装和认证。

```powershell
cd E:\Projects\wyy\ApiX-Control-Center
npm ci
npm start
```

打开 http://127.0.0.1:4173/ 。npm start 自动编译 TypeScript；升级代码后请重启原服务。默认 SQLite 位于用户目录 .apix-agent-os/apix.sqlite，可设置 APIX_DATA_DIR 和 PORT。

运行时须满足上面的 Node 版本要求，并支持 SQLite FTS5。可在启动前执行以下探测；若报 `no such module: fts5`，请切换到满足要求的 Node，避免在旧版本下误判数据库或测试故障：

```powershell
node --input-type=module -e "import {DatabaseSync} from 'node:sqlite'; const db = new DatabaseSync(':memory:'); db.exec('CREATE VIRTUAL TABLE probe USING fts5(content)'); db.close();"
```

1. 添加已有 Git 项目，在“任务与员工”注册已安装、认证并可运行的员工。项目须有 Git 提交，员工任务才能创建独立工作区。
2. 在对话工作区选择项目，配置“ApiX 推理模型”后直接输入问题或工作请求。工作详情中可切换“对话模式”与“约束模式”，两种模式都校验目标、范围、约束、交付物、验收标准。
3. 默认“请求批准”下审查需求与计划，再批准启动。需要持续自动安排时，按项目选择员工并“授权并开启自动协作”；明确工作请求可使用通用需求默认值生成计划，满足权限、依赖、费用与并发条件后启动。普通问题不启动员工任务，验收仍由用户完成。
4. 点击员工姓名进入详情页，查看当前任务、进度报告、历史任务和已采集的 Token 用量；查看交付物、消息监督并验收。没有运行时用量数据的 Run 明确显示“未知”。

ApiX 目标计划按依赖安排并行执行：前置交付物通过验收后才启动后续步骤，拒绝验收会阻塞下游。任务卡显示尚未验收的前置编号与代码交接结果。查看代码差异后通过验收会冻结 Git 交付，后续任务在独立工作区接收该版本；冲突会阻止启动并保留工作区，源仓库仍由单独集成审查后应用。已确认需求与协作协议不会因参考资料过大而被静默丢弃。

目标工作台可设置项目并发（默认 4）和每位员工在本项目的并发（默认 1），以及暂停新任务。排队原因显示等待依赖、并发已满或运行时暂停。员工报告额度或速率限制后，该项目的对应运行时暂停新启动；检查额度后明确恢复，或在“检查代码与恢复”中重新分配给可用员工。降低并发和暂停不会中断已经运行的进程。

失败、待修改和重启中断的任务可先检查运行记录、工作区差异与验收要求，再重新批准。状态未知时还须人工确认原进程已经停止；PID 探测仅作线索，服务不自动重新连接或杀死未知进程。冲突需先在保留的工作区解决并暂存，再重新检查。恢复保留部分成果并产生新运行，旧凭据及旧指导消息不重放；检查后代码变化将拒绝旧审批。所有任务验收后目标才显示“已验收”。

ApiX 对话使用独立的 POST SSE 流，发送 `start`、`delta`、`tool`、`complete` 或 `error` 事件，逐步展示回复与真实工具活动。工具活动只展示工具名、开始/结束及错误标记；流结束后以经过校验并保存的正式会话记录为准。Agent mailbox 使用另一条事件流更新消息状态。

对话模式下，管理者可返回自然回复、需求解释或真实任务状态说明；可见回复上限为 10,000 字符，超限或非法模型输出明确退回规则引导。聊天不会修改已确认需求或绕过计划审批。流式客户端断开不代表模型已停止；恢复后先读取正式会话，避免自动重发重复消息。

任务进行中，ApiX 会在员工长时间未报告时主动请求进度；员工上报进度后，ApiX 根据已确认的需求选择指导重点并发送 mailbox 消息。用户也可以在目标工作台向运行中的员工补充当前任务说明。运行凭据的消息领取、确认与回复绑定当前任务和运行；同计划同事交接须指定 targetTaskId，目标运行由服务端校验。指导状态区分送达、确认接收和员工报告处理。自定义适配器可显式声明 mailbox 支持，声明本身不证明已领取。员工运行时须主动读取 mailbox，才能在执行过程中收到这些消息；无法读取的第三方 CLI 会保留指导记录，不能保证进程内即时采纳。

“ApiX 推理模型”保存到后端并用于管理者 Pi 调用。可选择 Pi 已配置的 Provider/模型，或填写 OpenAI/Anthropic 兼容 API URL、模型 ID 与 API 类型。自定义 URL 使用 ApiX 数据目录下的独立 Pi 模型目录，不覆盖用户的 Pi 配置。远程接口需填写 API Key 的环境变量名并在启动服务前设置该环境变量；本地回环地址可无 Key。密钥不通过页面保存。侧栏“模型偏好”和 Skills/MCP 仍是浏览器配置，不能替代真实运行配置。

选择 Ollama、LM Studio 或填写本机 OpenAI 兼容 URL 后，可点击“读取本地模型”获取服务的模型目录。读取使用当前表单中的地址，不会自动保存、加载模型或生成回复；失败或空目录保留手动输入。需要认证的本地服务可在自定义配置中填写 Key 环境变量名。目录不保证模型已加载、支持对话或能成功推理，选择后仍需保存并进行实际对话验收。

## 能力、规划会议与预算

默认进入桌面对话工作区：选择项目后直接输入任务，左侧保存项目与对话，右侧查看工作详情。每个项目可一次“授权并开启自动协作”，选择执行员工；以后明确工作请求会自动整理通用需求、生成计划并按现有权限调度。一般问题不启动工作，严格费用上界仍需批准，成果仍需代码审查与验收。暂停自动安排只影响后续自动规划；停止当前工作会取消排队任务并请求停止员工。详见 [桌面对话与自动协作开发审查](协作/桌面对话与自动协作开发审查.md)。

服务启动自动读取项目根目录 `.env`，已有进程环境变量优先。阿里配置可参照 [.env.example](.env.example)：`ali_api_key` 在进程内映射为 `APIX_ALI_API_KEY`；在 ApiX 模型设置选择自定义 URL，填写 `ali_url`、`ali_model_name`，协议选 `openai-completions`，密钥环境变量填 `APIX_ALI_API_KEY`。保存模型设置不会保存密钥；修改 `.env` 后重启服务。管理者推理仍需要可用的 Pi CLI，未加入 PATH 时可配置 `APIX_PI_ENTRY` 的绝对入口路径。

目标工作台新增“均衡调度 · 能力与预算”：先维护员工的模型版本声明、能力标签、工具、熟悉项目和共享账户，再审查每步的调度约束与候选原因。必要标签、工具、上下文及用户指定员工先作筛选；可比的已验收历史、项目熟悉度、人工费用/时间估计和队列用于排序。运行时未报告模型的样本不冒充已验证的模型表现。声明不会替你切换执行 CLI 的模型或账户。

任务调度约束可填写类型、必要标签/工具、相对文件或目录、上下文 Token 量、指定员工、费用上界及预计分钟；`estimates` 可为不同 employeeId 填写各自的 estimateMinor/minutes。费用均为所声明币种的最小单位整数，未知留 null。模型不会替用户批准费用；严格预算下需人工补上界。已声明写入范围重叠的并行任务会被拒绝，空范围会提示未知；这些声明不构成文件系统沙箱。

在待审计划中，选择最多三位参与者并单独批准本次会议费用。第一轮独立提出可领取的步骤、依据、输入和风险；有分歧时可进行第二轮，每个计划最多两次。当前接入 Pi 与支持 bare/restricted 模式的 Claude CLI；会议在数据目录的独立位置运行，移除执行邮箱凭据及项目工具，不能复用完全访问执行参数。失败、中断与过期提案保留真实状态。应用建议创建新待审计划，用户仍须再次批准执行；主持纪要由规则整理，无额外主持模型调用。

账户支持人工额度快照、保留线、观测/重置时间和费用预算。订阅百分比不换算金额；API 账户声明币种。未知和过期快照明确标记，严格模式会等待更新。项目与共享账户预算同时检查已用、预留和本次批准上界；指定 ApiX 推理账户后，聊天、计划及监督推理也纳入预留。额度或速率错误会暂停绑定的共享账户，核对后须明确恢复。未指定推理账户时普通模式不跟踪 ApiX 费用，严格模式会拒绝推理。

运行/会议没有供应商费用数据时保留预留，不把未知当零；核对账单后可人工结算。重启遗留记录还须确认原进程已停止，活动运行不能结算。预算是本应用的新任务准入限制，不是供应商账单硬封顶，外部应用用量可能未记录。排队任务也可“检查代码与恢复”后换员工；前置必须已验收，旧指纹、旧权限和旧运行凭据不能复用。

本轮采用人工快照与已批准费用上界，不读取真实账户、自动同步价表或模拟供应商账单。完整实现、接口、验证与后续增强见 [能力会议预算开发与审查](协作/能力会议预算开发与审查.md)。

## 身份和权限

- ApiX：独立的管理者 Agent，通过 Pi 推理；对话工具由项目权限控制，任务派发由服务端协调器执行。
- 员工：独立 CLI 进程，在计划工作区执行任务。不会从管理者继承完全访问权限。
- 权限按项目及主体设置：`ask_approval`、`full_access`、`read_only`。默认请求批准；自动协作的首次授权明确设置 ApiX 与所选员工完全访问权限，并记录版本。
- 无严格预算/额度策略且执行员工未绑定账户时，仅当 ApiX 与所有被安排员工均有完全访问权限、计划通过校验且由推理模型生成，才自动派发；会议建议始终生成新待审计划。
- 请求批准是计划/任务启动授权，不是每个工具调用的批准机制；本版本不提供操作系统沙箱。完全访问允许所支持的 CLI 关闭自身审批/沙箱。

| ApiX 权限 | 对话中的管理者工具 | 计划推理中的管理者工具 |
| --- | --- | --- |
| `ask_approval` | 无工具 | 无工具 |
| `read_only` | `read`、`grep`、`find`、`ls` | 同左 |
| `full_access` | `read`、`bash`、`edit`、`write`、`grep`、`find`、`ls` | 仅只读工具 |

工具以项目目录为工作目录；管理者直接写入该目录，员工在独立 Git worktree 中执行。目录与写入范围声明都不构成文件系统沙箱。权限变化会请求中止在途管理者工具调用并使旧执行授权失效，但不撤销已完成的操作，也不保证所有外部子进程停止。Windows 上 Pi 子进程会优先使用已安装 Git 的 Bash。会议和输出格式修复调用不开放这些工具；格式修复可能额外调用一次模型。

“工具待授权”表示管理者当前没有原生工具，不妨碍生成待审计划。无工具时也可由协调器在用户批准后派发员工任务；聊天中声称“已安排”不能替代真实任务、运行记录和交付物。

## 运行时配置

可用 APIX_PI_ENTRY、APIX_CODEX_ENTRY、APIX_CLAUDE_ENTRY、APIX_GEMINI_ENTRY、APIX_OPENCODE_ENTRY、APIX_KIMI_ENTRY 指定对应 CLI 入口；APIX_MANAGER_PI_ENTRY 可单独指定管理者 Pi 入口。环境变量值为 JavaScript 入口或原生可执行文件的绝对路径，不接受 .cmd/.bat/.ps1。Windows 上全局 npm 安装的命令会根据包清单定位实际入口，找不到入口时显示为未安装。

Gemini 使用 stream-json，OpenCode 使用 `run --format json`，Kimi 使用 `--print --output-format=stream-json`。ApiX 通过标准输入传入任务，在统一 Run 中收集事件、结果和用量。请求批准指 ApiX 的任务启动审批；Gemini 的普通模式使用 `auto_edit`、完全访问使用 `--yolo`。OpenCode 与 Kimi 的工具权限仍由各自 CLI 配置决定，ApiX 不提供操作系统级隔离。首次使用请在终端分别完成 CLI 登录，并运行一个小任务验证版本、权限及工作目录行为。

自定义 CLI 在“任务与员工”登记可执行文件、参数数组及输出格式；Qoder 等需提供并验证非交互 CLI 或包装器。Trae、Qoder、WorkBuddy 的桌面应用发现不代表可托管执行。
