## ApiX 是什么？

> 当前开发分支已改为独立 ApiX 模型 API 后端，Pi 不再是管理者依赖；详见[独立后端契约与验收](协作/独立ApiX推理后端架构与验收.md)。此前验收文档中的 Pi 底座描述仅代表历史版本。

ApiX 是你的管理者 Agent。你提出目标，ApiX 理解需求、检查项目、拆分任务，再协调不同 CLI 员工执行；你可以随时查看进度、提出指导、审查代码并验收成果。

ApiX 自己管理主循环、工具、Skills、上下文与验收，直接通过模型 API 推理；Pi、Codex、Claude 等是使用独立身份和进程的可选执行员工。项目、对话、计划和运行记录保存在本机 SQLite；使用远程模型时，推理上下文仍会发送到所配置的供应商。

当前开发分支还支持项目 MCP 工具接入、完整工具结果引用、按预算分层压缩、员工事件唤醒监督，以及用户确认后的项目记忆召回。使用方法和边界见[工具、上下文、监督与记忆](docs/参考/工具上下文与记忆.md)。

Windows 主 Agent 可直接搜索源文件、按行读取、基于 SHA 精确编辑、核对本会话差异，并读取命令日志头尾、修复后重跑已批准的可信检查，无需安装员工 CLI。代码版本与检查契约共同决定 `verified`，正式验收仍由用户决定；MVP 工具上限、用法与离线/真实模型评测入口见[编码工具与评估](docs/参考/工具上下文与记忆.md#编码工具与评估)。

- **从对话开始**：选择项目后直接输入工作请求，流式查看回复与真实工具活动。
- **按能力分工**：结合任务要求、员工能力、可比历史、费用估计和队列安排工作。
- **把过程看清楚**：计划、会议建议、审批、消息、工作区与交付物都有记录。
- **保留你的决定权**：自动协作须先授权，预算准入与代码验收继续生效。

> 当前为开发版本。本文更新至 `codex/readiness-p0-p2` 的 2026-10-18 Windows Coding MVP 开发阶段。开发分支与 main 的功能范围不同；本地提交、历史 CI 或小任务验收不代表已发布或全面高度可用。版本演进与验证范围见[变更回顾](docs/变更回顾.md)。

## 核心功能

| 功能 | 当前实现 |
| --- | --- |
| 流式对话 | 项目与会话管理，逐步显示回复、工具开始/结束及错误状态 |
| 项目工具 | 宿主按权限执行文件读写、直接进程调用和验证，不隐式使用 shell |
| 自动协作 | 按项目首次授权所选员工；明确工作请求可整理需求、生成计划并按准入规则调度 |
| 能力调度 | 必要标签、工具、上下文与指定员工先筛选，再兼顾质量依据、费用和速度 |
| 规划会议 | 最多三位参与者、两轮提案；保留分歧与失败，应用后生成新待审计划 |
| 额度与预算 | 人工额度快照、项目及共享账户预算、费用预留、额度错误暂停与人工结算 |
| 并行执行 | 依赖验收门槛、项目/员工并发限制、暂停新任务与排队原因 |
| 执行监督 | 收集真实运行记录、交付物和已报告 Token 用量；通过 mailbox 请求进度与指导 |
| Git 代码交接 | 独立 worktree、差异与指纹审查、冻结已验收交付、冲突阻止下游启动 |
| 失败恢复 | 保留部分成果，检查运行与工作区后重新批准或更换员工 |
| 模型配置 | 独立模型 API、每对话模型/思考强度、供应商连接快照及本机模型目录读取 |
| 历史追踪 | 项目统一侧栏、可恢复归档/删除、完整输出引用、日志筛选与运行证据 |

## 快速开始

### 1. 准备环境

| 工具 | 要求 |
| --- | --- |
| Node.js | ≥ 22.19.0，内置 SQLite 支持 FTS5 |
| Git | 已安装；未初始化 Git 或尚无首次提交的项目会建立托管快照 |
| 模型 API | 配置可用的 API URL、模型 ID、协议与密钥（本机服务可免密钥） |
| 执行员工 CLI | 可选；委派任务时安装并登录所选的 Pi、Codex 或 Claude 等 CLI |

### 2. 安装并启动

ApiX 的对话与工具循环无需安装 Pi、Codex 或 Claude CLI。安装项目依赖并启动后，在“ApiX 推理模型”配置模型服务：

```powershell
git clone https://github.com/Makimasdog/ApiX-Control-Center.git
cd ApiX-Control-Center
npm ci
npm start
```

打开 **[http://127.0.0.1:4173/](http://127.0.0.1:4173/)**。已有本地仓库可直接在根目录执行 `npm ci` 与 `npm start`。

`npm start` 自动编译 TypeScript。升级代码或修改 `.env` 后须重启原服务。默认数据位于用户目录 `.apix-agent-os/`，数据库为 `apix.sqlite`；可通过 `APIX_DATA_DIR` 与 `PORT` 调整数据目录和端口。

<details>
<summary>启动报 FTS5 错误？检查 Node 的 SQLite 支持</summary>

```powershell
node --input-type=module -e "import {DatabaseSync} from 'node:sqlite'; const db = new DatabaseSync(':memory:'); db.exec('CREATE VIRTUAL TABLE probe USING fts5(content)'); db.close();"
```

若报 `no such module: fts5`，切换到满足要求且支持 FTS5 的 Node，再启动服务。

</details>

### 3. 配置项目与模型

1. 普通对话可直接开始，工具任务选择本机项目目录；需要委派时再在“任务与员工”注册可运行的员工。非 Git 项目使用计划级托管快照和隔离 worktree，原目录保持不变。
2. 配置“ApiX 推理模型”：选择模型平台，或填写兼容 API 的 URL、模型 ID、协议与 Key 环境变量名。
3. 在对话工作区选择项目并提出一个小任务，例如“检查这个项目的 README，提出改进并安排文档任务”。
4. 主循环按需要申请本次工具批准或用户选择。复杂委派先确认员工、持续项目授权和实际验收脚本；协作目标工作台保留需求与计划审查。

协作目标工作台的工作详情可切换“对话模式”与“约束模式”，两者都检查目标、范围、约束、交付物和验收标准。普通问题不启动员工；明确工作请求可补齐通用默认值，用户已提出的要求保留。

### 4. 审查与验收

查看工作详情、员工进度及交付差异。普通自动协作等待用户验收；另行开启自主交付后，ApiX 按已授权检查实测、自审、有限返工并冻结交付，资源暂时不足时等待后续准入。前置成果验收后依赖任务才会启动，全部模块及最终集成验收后才完成目标。不自动合并源仓库。

已开启自动协作的当前计划，员工执行失败后会自动检查恢复条件，并优先安排已授权的其他可用员工接手。每个任务最多自动重试 2 次，恢复窗口为 30 分钟；并发占满时等待，不消耗重试次数。后续步骤等待修复和验收后继续。取消任务、未知进程、代码交接冲突、授权或额度不足，以及达到恢复上限时保留停止并记录原因。普通协作的交付仍需验收，自主交付沿用已批准的自动实测和自审流程。

## Agent 接入

管理者由 ApiX 直接调用模型 API。Pi、Codex、Claude 等处于同一可选执行层，使用各自 CLI 的模型、账户及权限配置，彼此独立。仅在需要委派时安装所选 CLI；例如 Pi 可按[官方说明](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/README.md)执行 `npm install -g --ignore-scripts @earendil-works/pi-coding-agent`。

| 执行运行时 | 入口环境变量 | 接入方式 |
| --- | --- | --- |
| Pi | `APIX_PI_ENTRY` | JSONL RPC |
| Codex CLI | `APIX_CODEX_ENTRY` | 原生 JSONL 事件 |
| Claude Code | `APIX_CLAUDE_ENTRY` | stream-json |
| Gemini CLI | `APIX_GEMINI_ENTRY` | stream-json |
| OpenCode | `APIX_OPENCODE_ENTRY` | `run --format json` |
| Kimi Code | `APIX_KIMI_ENTRY` | `--print --output-format=stream-json` |
| 自定义 CLI | 在“任务与员工”登记 | 显式可执行文件、参数数组及输出格式 |

未加入 PATH 时，可在项目根目录 `.env` 填写 JavaScript 入口或原生可执行文件的**绝对路径**；不接受目录、命令名、`.cmd`、`.bat`、`.ps1`。例如 `APIX_PI_ENTRY=C:/Users/你的用户名/AppData/Roaming/npm/node_modules/@earendil-works/pi-coding-agent/dist/cli.js`，实际路径应以 `npm root -g` 和已安装包的 `package.json` 中 `bin.pi` 为准，不照抄示例。Windows 全局 npm 命令会按包清单定位实际入口，Pi 兼容新包名与旧的 `@mariozechner/pi-coding-agent`。`APIX_MANAGER_PI_ENTRY` 已停用，管理者只读取模型 API 配置；显式配置无效时会报告不可用，不会静默切换到另一个 Pi。修改后重启服务。Pi 子进程会优先使用已安装 Git 的 Bash，不修改全局 PATH。

每种 CLI 都须在终端单独完成安装和认证，再用小任务检查版本、权限与工作目录行为。Trae、Qoder、WorkBuddy 的桌面应用发现不代表可托管执行；需要可用的非交互 CLI 或包装器。

<details>
<summary>第三方 CLI 的权限与消息支持</summary>

任务经标准输入传入，宿主收集事件、结果和已报告用量。Gemini 普通模式使用 `auto_edit`，完全访问使用 `--yolo`；OpenCode、Kimi 的工具权限仍取决于原生 CLI 配置。ApiX 不提供操作系统级隔离。

员工须主动读取 mailbox 才能在执行过程中收到指导。自定义适配器可声明支持，但声明不证明已领取或采纳；不轮询的第三方 CLI 仅保留指导记录。同计划交接须指定 `targetTaskId`，运行凭据绑定项目、员工、任务和运行，旧凭据与旧指导不在恢复时重放。

</details>

## 配置指南

### 管理者模型与阿里百炼

服务自动读取项目根目录 `.env`，已有进程环境变量优先。阿里配置参照 [.env.example](.env.example)，仅在本地填写密钥：

```dotenv
ali_url=https://dashscope.aliyuncs.com/compatible-mode/v1
ali_api_key=<你的本地密钥>
ali_model_name=<你的模型 ID>
```

`ali_api_key` 映射为进程内的 `APIX_ALI_API_KEY`。在“ApiX 推理模型”选择自定义 URL，手动填写 `.env` 中的 URL 和模型 ID，协议选 `openai-completions`，Key 环境变量名填 `APIX_ALI_API_KEY`；这些 URL/模型变量不会自动应用到页面设置。

管理者通过 HTTP 直接推理，无需 Pi CLI，也不生成管理者 Pi 配置。支持 openai-completions、openai-responses、anthropic-messages；远程接口需要 Key 环境变量，本机回环服务可无 Key。URL/模型变量只是配置参考，需在页面填写并保存。

保存后可勾选一次费用批准，点击“测试已保存的模型连接”。测试使用当前项目的推理预算，不开放项目工具、不派发员工，显示实际推理是否成功及耗时；未保存或过期配置会被拒绝。测试期间不能重复测试或保存配置，90 秒后请求终止，离开页面不会取消调用。成功仅证明本次推理连接，不证明工具、员工或真实多 Agent 协作可用；未测得费用仍保留预留。

### 每个对话的模型与思考强度

全局设置提供新对话默认供应商；已有对话保存自己的连接快照。输入框上方可从目录选择或输入该供应商模型 ID，刷新、切换和重启后保留。尚无对话时可先点击模型选择入口。运行、委派和等待批准期间先处理当前工作，再更改配置。切换模型重置强度；规划、监督、摘要和验收沿用对话配置，员工 CLI 的模型单独维护。

目前已核验 DeepSeek Flash / V4 Pro 的默认、关闭、低、高、最高；未知供应商/网关仅使用默认，不猜测参数。保存配置不触发付费推理，也不证明账户具备模型权限。

### 项目、历史与任务事件

添加项目可浏览服务所在电脑的目录，也可手工输入。侧栏统一显示当前项目的主对话和协作目标，通过当前对话、已归档、最近删除筛选；删除为可恢复标记，活动或未知任务须先处理。任务事件面板支持类型筛选、内容搜索和原始日志展开，最近最多 100 条。

[模型选择截图](协作/20261017-对话模型选择.png) · [事件面板截图](协作/20261017-事件面板.png)，均为隔离验证数据。

### 本地模型

选择 Ollama、LM Studio 或本机 OpenAI 兼容 URL 后，点击“读取本地模型”获取目录。它使用当前表单地址，不会自动保存、加载模型或生成回复；失败或空目录可继续手动输入。需要认证的服务仍须配置 Key 环境变量。

模型目录不保证模型已加载或能推理，保存后应进行实际对话验证。侧栏模型收藏与手工 Skill 草稿是浏览器配置；MCP 在能力中心按项目保存并启用，不能替代管理者后端模型设置或员工原生配置。

### 能力、会议与预算

工作详情增加“自主交付”：授权检查脚本和循环边界后，新目标先生成模块契约，再派发实现，最后进行系统集成检查。实际检查和 ApiX 自审均通过后冻结交付；失败保存修复任务并重试，超时、未知进程或达到上限会停下。不自动应用源仓库、发布或合并。设置见 [自主交付与模块契约](docs/参考/自主交付与模块契约.md)。

在“均衡调度 · 能力与预算”维护员工标签、工具、模型版本、熟悉项目和共享账户。新增推理能力与版本化费率，任务难度和工作量独立估计，满足质量门槛后比较费用。传统任务沿用 CLI 配置；难度路由对 Pi/Codex/Claude 显式指定声明模型，不切换认证账户，未观测模型的样本不冒充验证结果，预测不会授予费用上界。

任务可声明类型、相对写入范围、上下文量、指定员工与费用上界。`estimates` 可按 `employeeId` 设置 `estimateMinor`/`minutes`；金额为声明币种的最小单位整数，未知留 `null`。写入范围重叠的并行任务被拒绝，空范围标记未知；模型不能替用户批准费用。

待审计划可单独批准会议费用并邀请最多三位参与者。第一轮独立提出可领取工作、依据与风险，有分歧可再讨论一轮。当前会议接入 Pi 与支持 bare/restricted 模式的 Claude；独立目录不提供项目工具或执行邮箱凭据，纪要由规则整理。应用建议生成新待审计划，不直接执行。

额度有两个来源：Codex 支持时可只读查询实际剩余窗口和模型目录，缺少接口的运行时明确显示未知；账户快照人工维护，支持保留线、观测/重置时间与共享账户预算。订阅百分比不换算金额，未知/过期快照在严格模式下阻止准入。指定管理者账户后，聊天、计划与监督也进入费用预留；未指定时普通模式不跟踪管理者费用，严格模式拒绝推理。无实际费用的运行/会议保留预留，核对账单后人工结算，活动运行不可结算。

### 并发、暂停与恢复

默认项目并发 **4**、每位员工在本项目并发 **1**。降低并发或暂停新任务不停止已运行进程；暂停自动安排也不撤销已有权限或批准。停止当前工作会取消排队任务并请求停止受托管员工。

额度或速率错误会暂停对应运行时或绑定账户，核对后明确恢复。失败、待修改或排队任务可检查工作区后重新批准、换员工；依赖必须已验收。重启遗留的未知任务继续占用并发，须人工确认原进程停止，系统不自动重连或杀死未知 PID。指纹变化拒绝旧审批，冲突解决并暂存后需重新检查。

## 权限与边界

管理者和员工按项目分别授权，默认 `ask_approval`。自动协作首次授权明确设置 ApiX 与所选员工完全访问权限，并记录版本。

| ApiX 主循环权限 | 行为 |
| --- | --- |
| `ask_approval` | 只读工具按目录执行；需要批准的副作用展示本次参数并等待回答 |
| `read_only` | 只允许宿主标为只读的工具，拒绝非只读动作 |
| `full_access` | 在既定项目和工具边界内执行；持续协作配置仍须明确批准 |

模型 API 只返回结构化动作，文件、命令和 MCP 由宿主执行。管理者文件工具操作源项目，员工使用托管 worktree；员工内部工具审批由 CLI 原生模式和适配器管理。路径和 worktree 不是 OS 沙箱；停止或撤销权限不能撤销已发生的副作用。

在无严格预算/额度策略、执行员工未绑定账户等条件满足时，有效模型计划可按双方完全访问权限派发；协作目标自动安排还要求开启自动协作。无工具也能生成待审计划，并在批准后由协调器派发。已确认需求不能通过聊天扩大范围，须调整需求或新建会话。

服务仅监听本机，管理 API 信任本机用户，**不能直接暴露到网络**。费用预算只限制本应用的新任务准入，未同步供应商账单、价表或外部用量，不能保证供应商硬封顶。旧直接派发 API 默认关闭，`APIX_LEGACY_API=1` 仅用于兼容历史流程。

协作目标工作台对话使用 POST SSE，传送 `start`、`delta`、`tool`、`complete` 或 `error`；以校验保存后的正式会话为准，该 SSE 的工具活动记录名称、阶段及错误标记。默认主循环通过持久化事件与轮询展示过程，工具结果另有完整保存和分页引用。会议及格式修复不开放项目工具，格式修复可能额外调用一次模型。回复上限为 10,000 字符，协作目标非法输出按其流程处理；主循环动作 JSON 最多纠正一次，仍无效则暂停；断流不代表模型停止，应先读取正式记录，避免重发。

## 技术栈与开发

源码、文档和验证资料按目录分开维护：

| 内容 | 位置 |
| --- | --- |
| 后端业务 | `src/`；根目录保留服务与装配入口 |
| 页面、交互、样式 | `web/`、`web/styles/` |
| 自动测试、手工验证 | `test/`、`test/manual/` |
| 当前说明、历史补充 | [docs](docs/README.md)、[归档](docs/归档/历史补充/README.md) |
| 开发审查、验收证据 | [协作](协作/README.md) |

完整文件归属和维护规则见[目录结构](docs/目录结构.md)。

| 层次 | 技术 |
| --- | --- |
| 界面 | HTML、CSS、JavaScript 与严格 TypeScript 模块 |
| 服务 | Node.js 原生 HTTP、进程托管与 CLI 适配器 |
| 数据 | Node 内置 SQLite、FTS5、状态表与协调事件账本 |
| 状态与实时通信 | 主对话持久化事件轮询、协作 POST SSE 与独立 mailbox 事件流 |
| 代码交付 | Git detached worktree、差异指纹与冻结交付 |
| 检查 | TypeScript、`node --check`、Node Test Runner、Windows GitHub Actions |

```powershell
npm run check
npm test
```

编译产物 `dist/` 不入库。自动测试使用隔离数据库和假 CLI，不调用真实付费模型。

对话工作区会检查项目目录、模型 API 配置、模型密钥环境变量、员工入口和管理者预算，并提供修复入口。非 Git 项目在执行时建立托管基线；入口存在不证明认证、额度或推理可用，实际模型连接需要单独测试。“模型设置”进入真实管理者配置，浏览器模型收藏及手工 Skill 草稿不会改变模型运行时；MCP 明确启用后接入主循环工具目录。计划格式或依赖无效时，在预算检查下纠正一次；仍无效则保留待审草案，错误原因与连接失败分开显示。

交付差异查询在独立线程执行，最多并行两次；检查期间任务状态变化需要重查。历史每页最多 200 条，可查看更早记录；记忆检索最多返回最近 50 个匹配项。验收与恢复仍会再次检查指纹。

真实协作验收使用隔离 Git 项目，会调用已配置的阿里模型及真实 Codex/Claude CLI，可能产生费用。确认所选员工 CLI 登录及模型 API 服务后，显式运行：

```powershell
# 管理者无需 CLI；Pi 员工才需要 APIX_PI_ENTRY（或加入 PATH）
npm run build
node scripts/verification/verify-real-collaboration.mjs --approve-cost
```

验收记录保存在 `.tmp-real-collaboration/run-*/result.json` 和隔离工作区，不纳入 Git。失败不会算作闭环通过；如果记录中 `workersStopped` 为 false，应检查保留的运行状态及进程。
