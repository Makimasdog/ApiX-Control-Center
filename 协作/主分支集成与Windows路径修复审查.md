# 主分支集成与 Windows 路径修复

日期：2026-10-13。实施与审查：Codex 自审。用户授权按“推送、PR、CI、合并 main”管理开发主线。PR：https://github.com/Makimasdog/ApiX-Control-Center/pull/6。

首次 CI 在 Windows runner 上静态检查通过，但完整测试 77/99，首个工作区错误为“工作区路径已变化”，随后工作区依赖流程超时。没有绕过 CI 合并。

代码中工作区位置、Git 根目录、Git 公共目录和 worktree 登记路径存在不同规范化方式及直接字符串比较。修复使用 `realpathSync.native` 取得原生真实路径；同样规范化持久化的历史公共目录及登记的 .git 文件路径，使路径别名指向同一文件/目录时可通过检查。源项目的公共 Git 目录创建、重用路径也使用同一种规范化。

保留托管目录、任务路径、Git 根目录、公共目录与 worktree 登记的全部检查。不直接放宽到字符串前缀匹配或无条件忽略大小写；不存在路径或不同仓库仍拒绝。

新增回归使用真实 Git worktree 与目录别名，调用生产 `createCodeHandoffs.workspace`，验证历史公共目录别名可用、替换为不同仓库拒绝、改变托管路径拒绝。临时清理先验证绝对路径在临时目录内。

范围：`src/code-handoffs.mjs`、`control-plane.mjs`、`test/coordinator.test.mjs` 与本记录。

验证：静态检查通过；路径别名、自动任务与冻结代码交接测试 3/3 通过；既有 Phase 3 和 Director 相关测试 2/2 通过；差异空白检查通过。最终代码、自测和访问边界经 Codex 自审，可提交此修复；暂存区按明确清单与审查 blob 核对。GitHub 完整 CI 仍需重新执行，只有通过后才合并，不将本地验证冒称远端通过。

此次仅修复工作区路径兼容性。未改审批、预算、模型、数据库结构或用户工作区内容；不新增稳定发布标签。main 原有历史为此开发分支祖先，合并采用保留提交历史方式，保留开发分支及用户未提交文件。
