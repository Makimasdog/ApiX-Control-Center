这是方案的首版可用闭环，不冒称所有扩展条目均已实现。每个项目当前使用均衡规则：必要能力、工具、上下文、固定员工及资源约束先筛选，再参考可比验收证据、熟悉度、同币种费用上界、时间和队列。未知值明确显示；币种不可比较时不隐式换汇。任务费用可用公共上界，也可在 estimates 中给不同员工填写人工上界。

只把实际运行时报告的模型与档案声明一致、且由用户明确验收/要求返工的 Run 纳入对应模型/任务类型的统计。exit=0、额度/环境故障不算通过或能力失败。反馈取原 Run 的用户审查事件，重试不会抹掉原返工记录。样本数显示在候选详情，未知模型无可比统计。独立审查按已声明被审查依赖选择另一员工；自审及独立性未验证均明确标记。

文件范围接受项目内相对文件/目录，拒绝越界、通配符并处理 Windows 大小写。检查已声明的并行范围；空范围提示未知，不能据此保证无重叠，也不是 OS 沙箱。实际代码交接继续依赖已验收的冻结 Git 交付与冲突检查。

## 接口与数据

- `GET/POST /api/employees/:id/capabilities`：model、tags、tools、languages、projectIds、accountId、contextTokens、version。model 是声明，不改变执行 CLI 登录或默认模型。
- `POST /api/scheduling/accounts`：id/alias、subscription 或 api、API currency/limitMinor、remainingPercent/reservePercent、observedAt/resetsAt、version；API 需声明币种，订阅不能填写费用预算。
- `POST /api/scheduling/accounts/resume`：id/version/reviewed=true；明确恢复被运行时额度或速率错误暂停的共享账户，不自动解除项目运行时暂停。
- `GET/POST /api/projects/:id/scheduling`：requireFreshQuota、quotaMaxAgeMinutes、limitMinor/currency、managerAccountId/managerEstimateMinor、version；返回档案、快照、暂停原因、已记录预留与账本。
- `POST /api/projects/:id/scheduling/settle`：id/actualMinor/reviewed=true。普通未测量记录可核对结算；重启遗留 reserved 还需 confirmedStopped=true，活动 Run/会议/经理推理会拒绝。此确认不会自动停止未知进程。结算为用户核对数据，非供应商自动账单。
- 计划 steps 可附 scheduling：kind、tags、tools、writePaths、contextTokens、fixedEmployeeId、estimateMinor、minutes、estimates。ApiX 自主生成时清除费用授权及固定员工字段，用户在待审计划明确填写并批准。
- `POST /api/coordination/sessions/:id/planning-meetings`：revision/planVersion、approved=true、participants[{employeeId,estimateMinor}]、previousId?。`.../planning-meetings/apply` 接收 meetingId 创建新待审计划。
- 沿用 `GET /api/tasks/:id/delivery` 与 `POST .../recovery`；queued 新增到恢复范围，仍需最新指纹、reviewed、准确 runId、当前需求/计划及已验收依赖。

SQLite 新表由模块创建，保留原数据。预算准入和 Run 创建使用事务/savepoint；同一共享账户跨项目计算已记录支出和预留，拒绝重复预留。没有供应商费用时转 unmeasured 并保留上界，不能自动释放或当作零。未启动的工作区/同步 spawn 失败释放未使用预留；已经启动或停止的未知费用继续保留。重启未知 Run 经用户确认停止后转为可核对费用，不能遗失旧预留。

配置指纹绑定已选员工、相关账户和项目策略。相关配置变更后旧任务必须检查重批；无关员工变更不会使所有项目计划失效。权限 grant、当前需求版本、恢复工作区指纹、任务依赖及执行限额继续由原机制校验。规划会议和执行 Run 使用不同记录/身份；规划进程不获得执行 token/mailbox，不进入项目工作区。

严格策略要求先设置 ApiX 推理账户和单次上界，避免只限制员工而漏掉管理者费用。普通模式未配置管理者账户时不跟踪这些推理费用。账本只汇总可归属的已记录费用/预留；此前没有账户或币种的调用及外部应用费用仍未跟踪，不代表供应商零费用。多币种不合成一个金额。实际模型价格版本、缓存读写独立定价、自动额度同步及账单校准留待真实平台接入。

## 自审范围与修复

审查类型：**Codex 自审**，不是独立审查、Claude 审查或人工批准。

范围：新增 scheduling/planning-meetings/consultation 后端、现有 coordinator/HTTP/进程生命周期/usage 及调用方；scheduling-view、coordinator 与 employee 页面；实际模块和隔离 HTTP/CLI 测试、package 脚本、使用/协作记录与截图。核对输入边界、模型不可授权费用、scope/权限/版本一致性、事务和幂等、异常/重启/旧数据、UI 项目切换、文件归属及测试隔离。

自审发现并修复：

1. 早期迁移任务无 employee_id 被新准入卡住；仅保留显式 legacy 兼容且无严格策略的旧流程，严格预算要求重新安排。
2. 模型可能编造费用/固定员工；确认计划时清除这些授权字段，后端准入独立校验。
3. 预算预留、Run 与任务更新可能部分成功；统一事务，重复预留拒绝，未测量金额不自动清零。
4. 经理、会议与员工可能共用账户；统一费用/额度门槛，经理自身错误也暂停共享账户，先预留会议整体费用再启动参与者。
5. 订阅记录不能混入 API 金额，API 需币种，历史币种不可隐式改变；同币种才比较费用。
6. 重试可能抹掉原返工证据或混淆声明/实际模型；统计使用原 Run 用户审查事件及运行时模型报告。
7. 只读 ApiX 应能生成草案，但不得启动员工/会议；区分草案候选与执行准入。
8. Windows 大小写和通配符可能漏掉范围冲突；规范已声明路径及比较。
9. 重启遗留预留不可永久卡死或在活动推理中释放；明确停止确认与活动状态检查，保留未知费用。
10. 会议展开状态被周期刷新关闭，成功提交的焦点阻止结果刷新或可能影响另一视图；保留展开状态、按原项目/目标/焦点收尾。
11. 自定义运行时可能名为 `user` 并输出类似验收的原生事件；统计额外校验用户审查载荷结构，原生事件不能增加用户验收样本，已有模块测试覆盖。

未引入新依赖；沿用原审批、邮箱隔离、独立 worktree、冻结验收及错误暂停机制。无 OS 沙箱、自动换账户/购买额度、真实额度/价格/账单或真实 CLI 成功声明。
