## Claude 的实施要求

### R1：使每轮对话正确结束和恢复

1. 按实际 `user` / `apix` 角色读取 complete。以 complete 的正式会话、消息与 revision 替换本轮预览，移除临时节点；连续发送两轮后仍只有正式历史，刷新前后数量一致。
2. 请求上下文绑定原 sessionId。切换或新建目标后，旧流事件、错误、finally 和表单 reset 不影响新目标；切换时清理旧目标预览。保留现有生成期间的切换限制也必须保证所有目标变更入口安全。
3. 进入和退出等待/生成状态立即更新按钮及输入状态；拦截重复提交；Enter、Shift+Enter 和中文输入法行为符合需求。
4. error/意外 EOF 保留已生成片段并单独提示错误，保留草稿；重新读取正式会话，更新 revision 和已入库用户消息。客户端断开不代表后端取消；读取期间后端仍 busy 时不自动重发，待状态恢复后再允许下一轮。
5. SSE 支持跨 chunk、UTF-8、LF/CRLF 和多行 data；终态只处理一次。若提取模块，只提取页面实际使用的最小逻辑。
6. 改造 `test/conversation-ui.test.mjs`，导入实际模块或验证实际 DOM；删除测试中独立重写的理想实现，fixture 使用真实 `apix` 角色。保存修复前失败、修复后通过的证据。

### R2：统一目录并保留用户配置

1. 接入 `GET /api/manager/providers`，响应为 `{providers: ProviderConfig[]}`，环境变量字段是 `defaultApiKeyEnv`；不继续维护前端硬编码目录。
2. 无 baseUrl 的旧 Pi 设置再次保存时保留原 provider/model，不转换为 `apix-custom`。目录或设置加载失败时不允许无意覆盖原设置。
3. 验证平台切换清除旧自定义模型名，URL 与 API 类型共同决定回填平台；本地 Key 显示一致；自定义协议、模型及 Key 环境变量名保存后再打开不变。
4. 改造 `test/model-settings-ui.test.mjs`，测试页面实际使用的配置转换函数及请求 payload；不得在测试里维护另一套提供商表或转换逻辑。

## Codex 的复验安排

V1 复用假 Pi 延迟分片、独立数据目录、临时 Git 项目及空闲端口，准备可重复的验收数据，不操作用户实际模型设置。确认 fixture 与实际协议一致，审查测试依赖实际模块；仅在发现未覆盖的后端缺陷时补相关回归，不重做已完成的后端任务。

V2 在 Claude READY 且暂停写入后执行。运行 bundled Node 24.19.0 下的 `npm run check` 和 `npm test`；新增前端模块或测试入口需要脚本调整时由 Codex 修改 `package.json`。然后使用实际页面逐项验证：

| 场景 | 通过标准 |
| --- | --- |
| 等待与增量 | 用户消息立即出现；首个 delta 在 complete 前可见；只有一条累积中的 ApiX 预览；生成控件立即禁用 |
| 完成与连续两轮 | 正式角色正确，临时节点清零，无重复；第二轮可发送，刷新前后正式历史一致 |
| 目标切换/新建 | 不显示旧目标临时消息；旧请求终态不清空新目标草稿或改写其历史 |
| 错误、EOF 与继续发送 | 保留片段和草稿；同步正式会话与 revision；不自动重发，busy 解除后可继续 |
| 解析边界与输入 | 实际解析模块通过 UTF-8/跨 chunk/CRLF/多行 data 用例；实际页面键盘与中文组合输入正常 |
| 配置目录与往返 | 只有后端目录来源；平台切换、Responses 协议、自定义值和本地字段正确；旧 Pi provider/model 不丢失 |
| 加载失败与回归 | 失败不覆盖原设置；构建及完整回归通过；需求确认和审批门槛无回退 |

此前 43/43 只作为上一轮基线；其中 17 项模拟 UI 测试不构成实际页面通过证据。新结果记录执行日期、运行时、场景及失败项，测试数量不作为完成门槛。
