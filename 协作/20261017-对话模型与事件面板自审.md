# 对话模型与事件面板（2026-10-17）

## 范围与验收标准

本轮由 Codex 实现前后端并自审，没有独立审查或人工批准。保留工作区已有的 `.gitignore` 和其他无关未跟踪文件，不推送、不合并。

| 用例 | 预期 |
| --- | --- |
| 为两个对话选择不同模型 | 按对话保存，切换、刷新和服务重启后仍独立 |
| 修改全局模型 | 作为新对话默认值，不覆盖已有对话的配置 |
| 无供应商配置时选择模型 | 明确提示先配置模型 API，不保存无法连接的对话配置 |
| DeepSeek Flash / V4 Pro | 提供默认、关闭、低、高、最高；发送真实协议参数 |
| 未声明能力的供应商、网关或模型 | 允许输入模型 ID；强度使用供应商默认，不猜测支持的参数 |
| 过期版本、无效模型、无效强度 | 拒绝修改并保留原配置 |
| 执行、委派、等待批准时切换模型 | 拒绝；保存中的前端配置阻止立即发送消息 |
| 委派与监督 | 主循环、摘要压缩、格式纠正、子流程规划、指导、修复与验收沿用对话配置 |
| 旧供应商密钥 | 更换全局配置后，旧对话密钥及同值别名仍不能进入员工、命令或 MCP 进程 |
| 长日志与恶意 HTML | 宽面板、可折叠、换行、筛选、搜索、显示计数；内容转义，不执行 HTML |

## 实现与自审

- SQLite 增量增加 `conversation_models`，以对话类型和 ID 联合隔离，不删除原对话、项目或日志。新对话保存默认供应商连接快照，旧对话首次读取或推理时补齐。尚未配置模型的对话不会冻结空配置。
- 主对话和协作目标共用选择器，模型可从目录选择或输入当前供应商的模型 ID。切换模型重置强度，更新使用独立版本校验；运行期间服务端仍检查状态，不能仅靠前端禁用。
- 配置接口先验证原对话存在且可访问；客户端只能改模型和强度，不能通过该接口更改地址、协议、密钥环境变量或权限。存储的是环境变量名称，不是密钥值。
- 子流程继承主对话配置。员工模型和思考强度仍由员工能力档案管理，不把 ApiX 的 API 模型错误地传给 CLI。
- 思考参数映射依据 [DeepSeek 思考模式文档](https://api-docs.deepseek.com/guides/thinking_mode/)（2026-10-17 核对）：Chat Completions 使用 `thinking` / `reasoning_effort`，Responses 使用 `reasoning.effort`，Anthropic 兼容协议使用 `thinking` / `output_config.effort`。
- 未核验的供应商与自定义网关只使用默认强度，不把其他供应商的能力套用到同名模型。此次没有增加自动探测或额外付费调用。
- 事件查看保留最近 100 条的原有范围，提供原始 payload、事件类型、时间、搜索和筛选。原始日志使用转义后的 `pre`；弹窗固定标题、内容区滚动，桌面和窄屏分别检查。
- 浏览器验证发现新控件 ID 与原全局配置表单重名，已改为独立 ID，并增加回归检查。
- 每个对话保存供应商快照后，相应密钥须持续从所有子进程环境中排除；支持多个管理者密钥和别名过滤，保留员工独立登录凭据，发现凭据共用仍拒绝启动。

## 使用与限制

输入框上方选择本对话的模型和强度，保存成功后发送。尚未创建对话时，可点击“选择本对话模型与思考强度”先建立空对话再选择。全局模型设置提供新对话默认供应商；已有对话保留原连接配置。

浏览器验证使用隔离数据目录和合成任务，不改变实际项目或任务状态。未在用户另一台电脑上部署，也未验证真实账户的模型权限、费用、限流和推理质量。
