# P1 Coding MVP — B 项目代码工具链与自审

基线 e557afd，前置 A 本地提交 ddfa6fb。Codex 自审；用户原有改动保留；不 push/merge/部署。本变更交付实际工具，不只文档。

新增 coding-files.ts：search_files 为字面搜索、稳定路径排序、UTF16 行列定位、0–3 行上下文和版本游标。最大 400 文件、总内容 2 MiB、单文件 256 KiB、1500ms 检查预算，默认排除凭据、Git、依赖、构建目录及链接。超预算/非文本明确 scanComplete=false，不将局部无匹配称作全项目无匹配；缩小 path 后重搜。游标绑定查询、范围、目录状态与已扫描内容，变化即过期。

read_file 保留小于 20,000 字节完整读取，增加 startLine/endLine/maxBytes/cursor/expectedSha256；固定 64 KiB 流式缓冲，返回实际范围、UTF-8 字节预算、SHA256、扫描字节和后续游标。单页最多 16,000 字节、源文件最多 8 MiB；为获得完整文件哈希仍扫描整份有界文件，不声称 I/O 只读目标行。UTF-8、CRLF、长单行和无末尾换行可分页；变化拒绝旧游标。未放宽验收 3,000 项/8 MiB 限制。

edit_file 接受 path + expectedSha256 + 1–8 edits[{oldText,newText}]。最多 2 MiB 的 UTF-8 文件，全部唯一、互不重叠、版本一致后才写；先写同目录临时文件、fsync、再次核对版本再 rename，核对写后哈希。保留未替换字节与换行，不使用 reset/checkout 修复。不能把跨进程最后一次核对与 rename 称作文件系统 CAS 事务；不协作外部写入者的极短竞争窗口未由本轮 OS 锁解决。写入/证据异常明确进入人工核对，不伪装原子事务或自动重放。

新增 assistant-coding.ts 实际生产桥接：先准备/冲突检查，再 file_edit_intent，成功后 file_edit_result 记录路径、前后哈希、增加/删除摘要及最多 24,000 字符的差异。无需 Git，记录位于工作区外的现有 SQLite 事件，不创建检查点平台。get_diff 只返回本会话文件工具的实际替换/新建记录，不把工作区原有改动或 run_command 的改动归给 Agent；每页最多 100 条，可 beforeEventId 继续，当前文件漂移另报。长工具/文件事件沿用上下文引用，不把整份大文件塞进模型。

tool-registry、assistant-tools、assistant-loop、control-plane 联通模型目录、只读/逐次审批、互斥、停止/撤权、指纹失效及交付摘要。文件证据失败与同项目写入/重启门槛贯通；纯准入拒绝不会制造另一个未启动会话的虚假未知事件。扩大真实未知的恢复能力没有降低原命令门槛。UI 现有工具卡片可看实际返回结构，详细卡片/日志入口在 C。

修改文件：上述两个新模块；assistant-tools、assistant-commands（安全错误资源分类和未启动准入拒绝）、assistant-result/context（文件摘要/长结果引用）、assistant-loop、tool-registry、control-plane；coding-files/bridge 测试、共用离线 coding-harness；标准测试清单和本报告。
