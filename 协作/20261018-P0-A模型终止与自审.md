## 已确认与未确认的根因

确认的确定性问题：原 SSE 解析已识别协议结束，但读循环仍等待传输 EOF；完整协议答复且服务端不关闭响应体时会错误超时。原 finally 在清除请求定时器后无界等待 Web reader.cancel()；没有清理期限或连接释放确认。取消与超时共用 AbortController，catch 按外部 signal 的最终状态判断原因，无法保证第一次终止原因不被后续取消改变。超时文案固定写成 90 秒，与实际配置不一致。原 EOF 还会解析未由空行结束的 SSE 尾帧。

新测试在基线构建上实际运行：12 项中 7 通过、5 失败。其中 3 个协议的完整终止但连接不关闭用例失败，2 个超时配置文案断言失败，日志 `.tmp-p0-p2/p0a-before.log`。

**尚未确认**：此前完整 npm test 中 40ms 响应体超时的间歇阻塞，本轮没有稳定复现。上述结构性风险及确定性缺陷已修复，但不能声称它们已被证明是原间歇阻塞的唯一根因。历史报告及公开 CI 曾通过的事实保持原样。

## 实现及接口

`inferModel(settings,prompt,onDelta?,{signal?,timeoutMs?})` 签名和配置/认证/请求参数保持兼容，不改变调用签名；调用方仅补齐下述清理未知错误传播。内部用 Node HTTP/HTTPS 请求替换 fetch/Web reader，独占连接（agent:false），以便实际销毁传输并等待 socket close 确认，不依赖可能无界的 reader.cancel()。

- 请求从发起到协议结束共用配置期限，默认仍为 90000ms；拒绝非法/溢出定时值。错误包含实际毫秒配置及 connection/headers/body/protocol 阶段，不记录密钥、URL 或响应正文。
- 单一 finish 闩锁确定一次结果；超时、用户取消、网络故障、协议成功都先移除取消监听、清除请求定时器并销毁 response/request/socket。结束后不再分发文本，迟到事件和重复取消不改变结果，不自动重试。
- Chat 必须 stop + [DONE]；Responses 必须合法 response.completed；Anthropic 必须合法停止原因 + message_stop。完整 SSE 帧终止后立即结束，不等 EOF；缺失/非法结束、截断、服务错误仍拒绝。JSON 响应仍要求完整 HTTP body 和协议成功字段。
- 清理单独最多等待 1000ms 的连接关闭确认；这里的 Promise.race 只限制已发起 destroy 后的确认等待，不用于遗弃仍运行的请求。未确认时抛“资源状态未知，请人工核对”，不能返回成功。确认关闭后移除请求/响应监听器；清理计时器始终移除。
- 主循环原有 stopped/revision 检查继续阻止迟到决策产生副作用；新增真实 HTTP 停止测试确认 busy 能释放。清理未确认抛带 `MODEL_CLEANUP_UNKNOWN` 的错误，权限撤销不覆盖它；即使主循环已 stopped，也记录 `process_unknown` 并转 attention，复用原人工恢复门槛，不重放动作。

## 兼容性、风险与未执行项

- 无数据库迁移、无新任务状态；模型 API、独立模型底座和员工运行时接口保留。严格拒绝缺少空行结束的 SSE 终止帧，以及错误协议的 [DONE]，可能暴露非标准网关行为。
- HTTP 连接不复用，增加每次请求的建连/TLS 成本，换取可确认的请求资源归属。Node 原生 HTTP 不使用自定义全局 fetch dispatcher；代理和证书部署应另行验证，不声称覆盖所有网关。未实现压缩流扩展。
- 有界期限依赖 Node 事件循环能运行，不承诺在进程/OS 卡死或同步回调阻塞时按墙钟硬中断。socket close 是本机传输释放证据，不证明远端取消模型计费或远程服务任务。
- 清理未确认路径明确报告未知；OS 级网络故障及长期运行尚无覆盖，不把故障注入等同真实平台故障复现。
- 清理未知由后端故障注入及主循环错误传播分别验证；权限撤销与 close 确认丢失同时发生的真实端到端故障未注入，control-plane 的错误码保留分支经过源码自审。正常权限撤销有现有 HTTP 回归覆盖。
- 本轮不执行真实收费模型、真实 Codex/Claude CLI、多系统验收或远程 GitHub CI；CI 配置修改仅本地检查。原间歇阻塞归因仍未确认。
- 后续独立任务：进程树与重启后的资源身份治理；代理/TLS/压缩网关协议矩阵和长期压力测试。原生 Tool Calling、代码工具链另行设计，不扩展本轮范围。
