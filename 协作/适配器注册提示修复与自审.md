# 适配器注册提示修复与自审

日期：2026-10-16。分支：`codex/readiness-p0-p2`；基线：`ef5a300`。
本轮由 Codex 开发并自审，未启动其他 Agent；这是自审，不是独立审查或人工批准。

## 问题与处理范围

用户反馈“适配器 ID 无效或属于内置运行时”。已定位到 `src/runtime-adapters.ts` 的注册校验：该提示同时覆盖格式不合法与尝试使用内置保留 ID 两种情况。反馈尚未提供具体填写的 ID，因此不声称已确认用户触发的是其中哪一种。

- 后端区分两类错误。格式错误说明小写字母、数字、连字符与长度要求；内置 ID 提示使用“任务与员工 → 注册员工”，不可用时检查相应 CLI 的安装和路径，再重新扫描。
- 前端自定义 CLI 表单补充填写规则、保留 ID、内置 Agent 的接入入口，并增加原生 pattern、maxlength 和可访问说明。
- 明确所有外部 CLI 都是可选员工，ApiX 自身通过模型 API 独立运行。
- 新增注册回归测试，覆盖非法 ID、全部六个内置 ID、拒绝后命令与表数据保持不变、自定义注册与更新，以及状态未知任务阻止覆盖命令。

## 最终差异自审

审查范围：`src/runtime-adapters.ts`、`web/coordinator.ts`、`test/coordinator.test.mjs` 及本记录。

1. 检查全部调用方：`registerRuntimeAdapter` 仅通过 `/api/adapters` 暴露；页面表单沿用该接口。响应和成功注册契约不变；错误仍走已有 HTTP 400 路径，前端用 textContent 显示。
2. 校验保持在服务端，客户端约束不能绕过保留 ID 保护。内置运行时的命令、参数和解析格式保持匹配，不允许通过自定义记录覆盖内置实现。
3. 拒绝发生在数据库写入之前，不改变已有员工、适配器或任务。活动及状态未知任务原有保护继续生效。未修改数据库结构、授权、环境变量和启动配置。
4. 客户端仅增加说明与原生格式校验，没有新增第三方依赖。HTML pattern 中连字符按 Unicode Sets 规则转义；TypeScript 模板字符串保留所需反斜杠。
5. 未改动用户原有 `.gitignore`、未跟踪 Skills 与其他文件；暂存使用明确文件清单。未切换分支、推送、合并或重启用户服务。

结论：本次范围自审通过，适合本地提交。提交前核对暂存区与上述审查内容一致。
