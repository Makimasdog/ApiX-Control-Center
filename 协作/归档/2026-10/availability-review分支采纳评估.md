## 阻止原样采纳的发现

### P1：质量证据被二次截断，但仍允许验收通过

位置：目标提交 `src/apix-agent.ts:89`，截断实现位于 `src/apix-agent.ts:10`；调用方 `src/autonomy.ts:113,124-128`，代码收集端 `src/code-handoffs.mjs:129`。

新 `promptJson(evidence, 24000)` 删除 JSON 字符串中间内容。原代码收集允许最多 70000 字节，宿主只检查收集阶段的 `context.truncated`，不知道提示词又被截断。若模型忽略截断标记返回 `{passed:true,findings:[]}`，审查函数直接接受，自动验收调用方也没有第二道完整性检查。这削弱了原先“证据不完整不能自动验收”的约束。

定向复现：使用目标分支实际构建后的 `createApiXAgent.review`，构造 50029 字节的单文件上下文，`truncated:false`，在文件中间放置唯一缺陷标记；mock 推理后端捕获提示并返回通过。结果：

```json
{
  "originalCodeBytes": 50029,
  "hostContextTruncated": false,
  "promptTruncated": true,
  "middleEvidenceLost": true,
  "acceptedModelPass": true
}
```

这证明宿主没有阻止不完整审查证据被批准，不代表真实模型必然批准该样例。不能依赖提示词要求模型自行拒绝来保证质量门禁。

修复要求：验收路径在发生任何截断时阻止通过并返回明确原因，或分块审查完整差异、代码和契约，收集全部审查结果后才能验收。历史对话可以压缩；冻结需求、契约和验收证据应明确保留完整性边界。增加超出 24000 字符但仍在宿主代码范围内的回归测试，断言缺失证据不能被模型的通过结果覆盖。

### P1：员工环境过滤遗漏既有密钥别名

位置：目标提交 `control-plane.mjs:320-328`；别名加载逻辑 `src/environment.mjs:6-7`。

`loadEnvironment` 兼容已有 `.env` 的 `ali_api_key`，并复制为 `APIX_ALI_API_KEY`。新过滤删除大写变量及配置中指定的管理者变量，但保留原始 `ali_api_key`。在项目既有配置路径下，员工仍继承同一个管理者密钥，不能认为该补丁已经解决管理者密钥隔离。

这是原有环境继承风险未被本补丁完整修复，不是该补丁新增了密钥泄露路径；应保留有效的过滤方向并补齐遗漏。

定向复现：提取目标提交实际 `workerEnvironment` 函数体，在 VM 中注入两种名称相同的虚构密钥，并将管理者配置设为 `APIX_ALI_API_KEY`；结果大写名称被删除、`ali_api_key` 仍存在。没有读取或打印真实密钥。

修复要求：覆盖加载层支持的别名及 Windows 环境变量大小写，明确管理员与员工凭据来源，并补充从环境加载到员工启动的回归测试。不要仅凭删除一个配置变量认定凭据隔离完成。

### P2：移除管理者变量可能破坏员工自身认证

位置：目标提交 `control-plane.mjs:326-327`。

如果管理者配置使用 `ANTHROPIC_API_KEY`，而 Claude 员工也依赖该变量，新逻辑无条件删除它，没有员工专属凭据注入或配置冲突提示。使用虚构环境和实际函数体复现后，员工环境中的 `ANTHROPIC_API_KEY` 不存在。

这是指定环境认证配置的兼容性风险；本轮未向真实 Claude 服务发请求，未声称已复现真实 CLI 登录失败。修复时应区分员工专属认证与管理者认证；对于无法安全分离的共用配置，在启动前给出明确诊断，不能静默移除后让任务失败。
