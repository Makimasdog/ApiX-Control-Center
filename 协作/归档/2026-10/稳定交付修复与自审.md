## 本轮判断与范围

先使已确认范围内的交付链可靠，而不是宣称覆盖所有复杂度。使用前提是项目/CLI 已配置、能力与预算已声明、实际检查已授权；用户描述需求后，ApiX 冻结契约、按模块派发、监督、实测、自审、有限返工和最终集成。未知进程、权限/预算变化、人工拒绝与范围扩大仍需明确处理。

上一轮发现非法 schema 被接受；进一步自审发现修复时没有空闲员工会立即进入 attention，并可能停止其他模块。两者直接影响正常交付，因此优先修复：

- 接入锁定版本 `ajv@8.20.0` 与 `ajv-formats@3.0.1`，冻结前校验并编译 schema。默认 2020-12，也支持显式 draft-07；拒绝非法字段类型、未知关键字/格式、未支持方言和无法解析的引用。编译后移除模型 schema 缓存，避免跨模块引用和积累。依据 [Ajv 的方言说明](https://ajv.js.org/json-schema.html)与[配置说明](https://ajv.js.org/options.html)，未配置远程加载或自定义执行关键字。
- 旧计划执行/恢复前重新检查契约并核对 digest；缓存只作用于该计划的同一 body，在进入需处理状态/完成时释放。非法旧契约进入待处理，不迁移成已批准的新契约。
- 在能力、预算、权限均满足但员工暂时等待资源时，保存 waiting 修复记录。重复 tick 不增加修复记录或次数；资源释放后重新准入、恢复工作区并重新授权执行。等待计入原目标时间上限。
- 等待绑定具体 `run_id`，不用时间戳推断新旧运行。后续人工运行/拒绝、时钟回拨不会让旧记录重新派发。数据库通过非破坏性加列保留历史记录；没有运行关联的旧等待记录不能自动附着到后来运行。
- 修复导致的干净、从未执行的依赖任务继续等待；已有运行、交接冲突、未知进程和人工拒绝不被跳过。既有调度器继续阻止未验收依赖启动，不修改该安全门槛。
- UI 将这种等待显示为排队/等待执行资源，自动实测时显示执行中/等待自动检查，不再在主对话提示人工验收；明确需要处理时保留相关入口。同步功能说明、README、Wiki 和架构文档；原始失败记录保留。

本轮没有启用实际项目授权、改变用户 CLI 模型/账户、自动生成或批准检查脚本，也没有部署或合并 main。

## 最终 diff 自审

审查实施为 Codex 自审，不称独立审查或人工批准。范围包含生产源码、调用方、前端状态文案、测试、依赖/lockfile、文档及探测 JSON。重点检查：

1. Schema 验证发生在派发前；合法 schema 有正例，非法 schema 有反例；配置只允许两个明确方言，原型属性不能当作验证器。错误有边界，不执行模型生成的代码或远程 schema。
2. 校验已有契约不会重写批准内容；重启、坏 schema、digest 不一致都有拒绝测试。仅缓存同一计划 body，不跳过权限/需求/策略版本检查。
3. waiting 仅在合格员工资源暂不可用时产生；质量门槛、费用、员工清单与授权失效仍暂停。每次派发仍走既有恢复、指纹、审批和费用准入。
4. 记录只匹配同一 Run；等待不消耗修复次数，不重复派发。数据库加列保留旧证据，不把无关联旧记录自动批准。
5. 下游保持验收门槛；只有没有历史运行/冲突且所有失败祖先都在合法等待返工的依赖链可继续等候。没有把 blocked 一律当作可恢复。
6. 前端使用已有转义逻辑，显示真实等待状态；文档将普通自动协作与自主验收分清。现有 API、默认权限和预算策略不变。
