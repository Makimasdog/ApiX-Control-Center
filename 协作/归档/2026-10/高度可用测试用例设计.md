# ApiX 高度可用测试用例设计

日期：2026-10-14。测试基线：`22cbcac`（核心自主交付实现 `99c7d01`）。先设计再执行；本文件的预期结果不是测试结论。Codex 单人执行与自审，不新增子 Agent。

## 测试原则与门槛

使用隔离 SQLite、临时 Git 项目和 worktree，不修改业务项目、模型全局配置或用户原有改动。自动化测试使用假模型响应，但脚本执行、Git 和 HTTP 使用真实宿主；不能据自动化通过宣称真实 Agent 交付成功。真实模型测试须获得本轮费用授权，最多两个隔离目标、总计 20 分钟；保留运行记录和实际成果，超时停止本轮已知运行。未经批准不合并、不部署。

每例至少检查状态、实际证据、是否错误验收/重复派发及恢复边界。安全与预算阻止路径应检查没有新增运行/验收。自动化门槛为静态检查及全套无失败；高度可用不能仅凭此门槛通过，真实系统及故障注入另行判定。测试发现问题记为失败/缺口，不修改预期使其通过。

## 用例清单

| ID | 场景与操作 | 预期与证据 | 执行层 |
|---|---|---|---|
| A01 | 模块边界重叠、依赖成环、依赖不存在、检查未授权 | 拒绝契约，不派发 | architecture |
| A02 | 两模块声明同名不同数据结构；步骤缺模块、缺依赖或越界 | 拒绝；正确契约追加依赖全部模块的集成任务 | architecture |
| A03 | 模型架构 JSON 截断/无效，质量结论矛盾或无问题说明 | 不产生合法契约/通过结论 | apix-agent，新增 |
| A04 | 多模块接口实现不符合 schema | 检查或审查发现，不能只靠结构校验通过；真实任务观察 | 真实验收 |
| A05 | 接口 schema 含非法 type；数据结构 schema 的 required 为字符串 | 拒绝非法契约。独立能力探测，失败不计成回归通过 | probe-architecture-schema |
| Q01 | 员工进程退出 0，但 a.txt 内容错误 | 实际脚本失败；修复一次后模块和集成均通过，保留三次检查 | HTTP 现有 |
| Q02 | 测试通过但 ApiX 审查失败 | 不验收；有明确修复记录，上限后暂停 | HTTP 现有 |
| Q03 | 差异/当前代码截断、二进制或冲突 | attention；不调用质量审查、不验收、不自动重试 | autonomy，新增 |
| Q04 | 修改冻结模块边界外文件 | 不验收，修复指令指出范围外文件 | autonomy，新增 |
| Q05 | 验收脚本修改交付代码/审查期间代码变化 | 指纹失效，暂停，不冻结 | autonomy，新增 |
| Q06 | 验收脚本缺失或运行抛错 | 错误持久化，不把成功进程/空输出当作通过 | autonomy，新增 |
| Q07 | 检查脚本无限等待 | 到超时停止实际进程，记录 timedOut，不调用模型审查，产生有限修复 | autonomy，新增 |
| Q08 | 同一目标同时触发两次 tick | 一次实测、一次审查、一次验收，不重复计费或返工 | autonomy，新增 |
| C01 | 大量简单任务与少量高难任务，能力/价格不同 | 简单任务优先可比低价；高难任务排除能力不足者；实际 argv 为所选模型 | scheduling + HTTP |
| C02 | 未知费率、不同币种、预测超过批准上界、严格预算不足 | 不虚构费用、不隐式换汇，超预算不启动；保留预留与账本 | scheduling + HTTP |
| S01 | 高风险员工不回应两个过期检查点 | 先停止原 Run，结束后换人；期间不并行重试 | autonomy 现有 |
| S02 | 员工报告 blocked=true / 超过运行上限 | 停止已知 Run，下一轮才修复或换人 | autonomy，新增 |
| S03 | 目标总时间超限或修复次数耗尽 | attention，停止已知运行，没有新增修复 | autonomy 新增 + HTTP |
| S04 | 验收/审查时撤权，策略/模型/账户版本变化 | 不通过、不重试，指明变化 | autonomy + HTTP |
| S05 | 排队尚未执行时员工不可用 | 只改派到已授权且可用员工，保持原模块和依赖 | autonomy + HTTP |
| R01 | 服务重启中断员工或验证；旧恢复指纹 | 状态未知/中断，不自动重放；须新指纹及明确停止确认 | autonomy + HTTP |
| R02 | 已完成目标再重启 | 保持 completed，不重复验收或重启循环 | autonomy + HTTP |
| M01 | 员工读取别的项目邮箱/重复消息/旧指导重放 | 项目隔离、幂等、旧 Run 不重放；消息有确认与事件证据 | messaging + HTTP |
| G01 | 冻结代码跨员工交接、输入冲突、慢 Git 检查 | 交接实际文件；冲突阻止启动；HTTP 不被慢检查阻塞 | collaboration + HTTP |
| U01 | 一句话派发、测试失败、修复、集成、最终通知 | 一次最终通知；页面显示证据；模型内容转义 | HTTP + UI 回归 |
| T01 | 真实两模块订单计算系统：纯函数模块 + Node HTTP 模块 | 无人工改计划/代写代码；真实员工实现，授权脚本测试正常/错误输入及接口，自动最终验收 | 真实模型，需费用批准 |
| T02 | 真实局部修改，保留前置模块；失败后恢复/返工 | 明确修复而非扩大范围；运行次数/人工介入/费用可观测，最终真实脚本通过 | 真实模型，需费用批准 |
| D01 | 文档/PR/CI 自动管理、自动生成完整验收脚本、能力价格校准 | 尚无完整实现，记录能力缺口；不计入自动化通过 | 能力边界检查 |

新增用例 Q03–Q08、S02–S03 使用真实 Node 检查及模拟 worker/reviewer，验证宿主决策而非真实模型能力。现有测试继续完整执行，不只挑成功用例。

## 结果记录
