# 自动协作开启拦截修复自审

日期：2026-10-15。Codex 实现、自审，无额外子 Agent。

## 原因与范围

只读检查本机状态发现 easyreader 项目有两条状态未知的旧任务；ApiX 和员工均已有 full_access，未保存项目自动协作开关。原实现无条件拒绝有活动/未知/排队任务的开启操作，而且再次保存相同权限会增加权限版本，使已有任务授权失效。

先验证明确批准、工作流版本、员工可用/唯一及所有权限版本。仅为尚未 full_access 的主体写入权限；不需要提升权限时允许开启/重新开启，不改变现有任务 grant。需要提升权限时继续阻止 running/starting/stopping/queued/unknown 项目任务，并返回任务 ID、状态及处理方向。旧任务、运行记录、生产授权和数据库没有被修改或清除。

接口结构不变，仍由原前端按钮调用原 workflow API；现有权限调用方继续依赖相同版本。保存通过原 SAVEPOINT 原子提交/回滚，不放宽费用、员工执行、未知进程恢复或并发规则。

## 用例与审查

- 全部五种活动状态在权限已完整时可开启，权限版本、任务 grant、状态和权限事件不变。
- 各状态下若需要提权，拒绝且没有权限、工作流和事件的部分写入。
- 空闲时只提升必要权限；其他项目的未知任务不阻止本项目。
- 已有完整权限仍校验版本、批准、员工可用性及重复员工。
- HTTP 真实隔离服务中，排队→暂停自动安排→模拟历史 unknown→重新开启，unknown 不被自动恢复；测试夹具恢复 queued 并释放暂停后，旧 grant 仍可启动并完成任务。
- 既有正常工作流、严格费用/暂停与在途撤销自动安排相关 HTTP 回归。

验证通过：Node 24.19.0 构建、npm run check、4/4 工作流单元测试、4/4 相关 HTTP 测试（23795.2652 ms），无跳过。HTTP 日志 `.tmp-p0-p2/workflow-enable-final-http.log`。初次 HTTP 测试误将 POST 的精简响应当作 GET 的完整权限视图，出现两项断言失败；修正测试为 GET 核对后复验通过。没有运行本轮无关的完整回归，不把定向结果表述为完整回归。自审范围包含最终 diff、新增文件、前端与服务端调用方、错误/回滚路径、授权版本和状态一致性；最终 diff 自审通过，允许仅提交本轮六个文件；暂存后核对清单与哈希一致。自审不代表独立审查或人工批准。

未验证：实际付费模型及生产界面重启后点击。修改未自动启用生产项目，历史 unknown 仍须核实其进程和交付；不能根据旧 PID 或记录自行确认已停止。
