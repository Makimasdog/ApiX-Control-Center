# 生产 Git 与扫描异步化及自审

日期：2026-10-25。分支：`Kimi/sqlite-ui-polish`；基于 `de8199f`。本记录为 Codex 自审，不是独立审查或人工批准。仅本地提交，不推送。

## 问题与范围

前轮已记录生产同步工作造成约 7–10 秒事件循环延迟，并触发空闲连接超时。本轮修复生产调用链：工作区准备、交付检查/冻结/冲突恢复、集成预览/应用、项目指纹与可信契约、审阅快照、npm 验证副本与容量扫描、只读文件工具/恢复扫描，以及热路径中的 CLI 发现。此前测试夹具默认关闭连接的设置保留；生产响应性专项显式使用 keep-alive，不依靠该夹具设置通过。

## 实现与一致性

- Git 调用统一异步执行。每个执行队列 4 个并发、64 个排队，排队计入原调用期限（默认 20 秒）；保留 stderr、补丁 stdin、原有超时与 Git 参数。索引和对象树的指纹算法保持原样。
- 项目 IO 使用固定白名单、2 个常驻 Worker、32 个排队、入队起 120 秒期限；超时/崩溃拒绝该项，不自动重放。Windows Worker 环境大小写别名显式归一，npm/PowerShell 能力与宿主一致。CLI 自动发现异步刷新缓存，显式重新扫描等待刷新结果。
- npm 副本容量核对和复制在后台串行准备，原有文件/字节/副本数量预算保持不变；命令期间的资源扫描不重叠，命令收尾等待在途扫描结果。所有者凭据不进入受管命令，源码/依赖/产物完整性仍在各阶段复核。
- SQLite 与单文件原子写入仍在主线程。没有跨 await 的数据库事务；IO 返回后复核任务/会话版本、授权、路径及指纹。异步冻结不能覆盖用户拒绝或只读策略；冲突和不确定工作区保留检查证据。
- 准备开始即占用执行槽；暂停时重新排队，取消时不启动 Agent，并保留已创建的托管工作区。集成应用按仓库互斥，应用前再查源 HEAD/脏状态、审查版本、路径及权限。
- 会话详情在状态变化时最多重读一次，仍变化则返回待刷新的保守结果；同次详情查询复用验证状态，正式验收仍重新核对。完成阶段扫描遇到停止或新消息时，旧完成结论不得发布。
- 已适配 API 路由、调度/自主协作、交付检查 Worker、CLI 评测和测试夹具的 Promise 调用。模型切换、归档等只用轻量忙态；评测预算到期立即取消，不等待详情扫描后才发取消信号。夹具等异步回调完成后再清理目录，轮询改用实际总时限，业务和速度断言保留。

## 最终 diff 自审

- 调用方：核对所有 createAssistantLoop、createCodeHandoffs、createTaskDelivery 与调度入口；内部异步接口均显式等待，门禁不用 Promise 属性判断。HTTP 成功响应继续由路由等待真实结果，不序列化未完成的 Promise。
- 错误路径：队列满、期限、Worker 崩溃、Git 失败、陈旧状态/指纹与权限撤销都拒绝相应操作；不会制造成功或自动重放不确定副作用。受管进程和副本继续沿用原有恢复门槛。
- 数据一致性：旧验收不覆盖新决定，停止不被迟到的完成结论覆盖，新消息重新参与主循环。数据库仍单线程提交，准备阶段执行槽防止重复派发；集成应用按仓库排他。
- 访问边界：只读文件工具返回时复核根路径与取消信号，丢弃迟到结果；对应真实 Worker 回归及文件桥接 9 项通过。原有 canonical 路径、仓库归属、私有索引、凭据排除、可信契约和实际命令证据校验保留。后台只读工具拒绝编辑；Worker 不直接提交业务 SQLite 状态。
- 新文件和脚本：新增业务文件均在 src，未新增根级业务 .mjs；Windows 桌面打包的 src/dist 整体复制规则覆盖新 Worker 与编译模块。评测脚本仍要求原有显式授权，固定协议验证不代表真实模型能力。
- 自审结论：通过。最终全量 507 / 507、静态检查 exit 0；完整 diff、新文件、调用方、错误路径、数据一致性与访问边界均已核对，33 个代码文件与自审留存哈希一致。以明确的 36 文件清单核对暂存区后本地提交，不推送。
