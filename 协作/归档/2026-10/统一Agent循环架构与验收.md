# ApiX 统一 Agent 循环：架构、契约与验收

日期：2026-10-16；开发基线：3394775；实施者：Codex（含前后端与自审，不额外启动 Agent）。

## 模块边界

1. `assistant-loop`：持久会话、模型决策、工具步骤、用户请求、预算与恢复；默认产品入口。模型决定下一步，宿主验证并执行；派发其他 Agent 是循环工具，不绕过循环。
2. `assistant-tools`：项目文件、命令、Skills、规则、笔记和验证指纹；路径必须位于项目真实目录；明确输出不完整情况。Skills 与记忆属于上下文，不授予权限。
3. 现有 coordinator/autonomy：作为委派工具的执行引擎，继续负责架构契约、难度成本路由、独立工作区、监督、实际检查、返工和验收。默认外层循环等待子流程后继续思考；有条件才请求人工。
4. `/api/assistant/*`：版本化请求、异步消息、轮询状态、用户选择、停止与显式恢复；不与员工 Bearer 邮箱接口混用。
5. `web/assistant`：左侧项目/会话、中间时间线与输入、右侧工具/员工/上下文；批准与多选在对话展示。默认进入新工作区，旧会话和配置继续可访问。

## 数据与接口

- Session：id、project_id、status、version、steps、summary、compacted_through、pending、child_session_id、needs_verification、verification、started_at、updated_at。
- Event：单调序号、session_id、role、kind、JSON 内容、时间；历史不删除。
- 工具调用先记录 tool_started，再执行，再记录 tool_result；命令另存 PID 与工作目录。重启发现未完成副作用时进入 attention，禁止自动重放。
- 状态：idle → running → waiting_user / waiting_agents → running → completed；任意活动状态可 stopped；异常进入 attention。
- 模型决策：tool（名称、结构化参数、公开说明）、ask（问题、选项、是否多选）、finish（用户可见结果）。不展示内部思维链，不把模型消息当宿主证据。
- 用户请求绑定 session/version/requestId/工具参数/权限版本；过期、重复或跨会话回复拒绝；拒绝后反馈模型，可选择其他方案。
- GET sessions?projectId、GET sessions/:id；POST sessions、sessions/:id/messages、reply、stop、resume。
- 会话摘要自动整理过往记录，原文保留；规则、长期笔记与最新用户输入重新注入。摘要、笔记和 Skill 不得覆盖授权。

## 验收标准（先于实现）

- 普通问答、只读探索和直接工具任务不要求先注册员工；复杂任务可在循环中委派现有 CLI Agent。
- 连续模型决策可多次调用工具；失败结果回送模型；修正后继续；不能仅因进程退出 0 就宣称交付。
- 修改文件后未运行实际验证不能完成；验证后再次改动使证据失效。委派未完成、未验收时不能结束父循环。
- 默认使用循环；旧流程显式可达，原会话、权限、工作区与费用账本不迁移为自动授权。
- 实际命令/写入遵守项目权限；需要批准时展示确切参数，不擅自提高全局权限；只读策略拒绝副作用。
- 对话、工具观察、请求和摘要可跨刷新恢复；重启不自动重复写入、命令或委派；失联子任务保留状态并要求检查。
- 多选/自由输入/批准/拒绝可在 UI 回复；停止后模型迟到响应不能继续派发。
- 测试覆盖上述状态机、权限与路径边界、摘要和项目隔离，以及浏览器真实消息/批准交互；已有回归仍应通过。

设计参考：[Claude Code memory](https://code.claude.com/docs/en/memory)、[Skills](https://code.claude.com/docs/en/skills)。采用持久规则、项目笔记与上下文整理的原则，不声称复制其内部实现。

## 最终实现与边界

- 无项目也可发起对话：宿主建立隔离的“通用工作区”，不要求 Git 或员工。项目不能包含 ApiX 内部状态目录。已有项目和旧协作工作台保留。
- 默认循环工具为文件读写、目录、直接命令、实际验证、Skill 加载、项目记忆、员工发现/配置、委派与员工消息。复杂委派调用现有架构/契约/调度/监督/返工引擎；子任务全部验收后，主 Agent 再作下一步决定。
- 单次批准绑定会话、请求、版本、参数、权限版本与项目指纹。configure_agents 始终单独请求持续项目授权，明确员工完全访问、实际验收脚本、最多两次返工；不授予额外费用。拒绝后的同类操作在本条用户消息内不能重复申请。
- 会话原文分页保留；历史超过约 28000 字符时整理摘要，固定保留初始目标与最新输入。项目规则、笔记索引、Skill 目录按轮注入；笔记可跨会话查看、修改与删除。Skill 和记忆只是上下文，不授予执行权限。
- 同项目的多个主会话串行写入，未确认进程会阻止其他主会话写入；员工的模块并行由既有工作区调度器负责。停止中断命令和委派；架构推理迟到结果不会启动员工。
- 每轮最多 24 次决策或 30 分钟活动时间；命令最长 120 秒。单次读取/写入有 20000 字节/字符边界；规则与 Skill 为 16000 字节；完整项目指纹最多 3000 个条目、8 MiB（排除依赖、Git 元数据、临时目录和常见凭据）。超出时明确阻塞，需拆分或使用已配置的委派工作区。大型项目的首次配置也可能要求精简验证范围，未宣称任意规模通用。
- 命令为直接进程与 argv，无隐式 shell；有项目目录和环境过滤，但不是操作系统沙箱。进程树完全终止不能保证；状态未知时保留 PID 并要求检查，不自动重放。
- 对话展示公开活动与工具证据，按约 1.2 秒轮询；最终文本不是逐 token 流式输出。真实文件系统 Skill 已接入，旧 MCP 配置页面仍只是草稿，未接入执行。
- 成本路由继续使用已有能力声明、费用与预算策略；不把品牌当实测能力，不编造未知单价。项目持续授权不会覆盖已有员工的全局能力配置：声明不一致时必须使用现有声明或到员工设置明确修改；新员工可保存本次批准的初始声明。是否能稳定完成真实任务仍取决于所配置的模型、CLI 登录状态与验收覆盖。
