# 契约驱动的自主交付与执行就绪改进

用户确认系统需求后，ApiX 先冻结模块边界、接口、共享结构和验收标准，再派发实现。实现结束会运行已授权的实际检查，并依据代码与测试自审；失败产生具体修复任务，重新执行和验收，最终系统集成通过后通知用户。循环受授权、预算、次数和时间约束。

本轮增加：

- 分开估算推理难度、Token/调用工作量和费用；在能力门槛内按声明的模型费率路由，明确传递所选模型。
- 按模块风险持续监督，处理失联、阻塞、超时和合法换人；保持模块契约、共享上下文、mailbox 和 Git 交接。
- 持久化实测、修复和恢复证据，阻止撤权、配置变化、代码冲突及未知进程被自动绕过。
- 前端自主交付配置与证据面板、最终通知及对应文档。
- 标准 JSON Schema 校验和旧契约摘要重验；修复资源暂不可用时持久化等待，按具体 Run 关联，资源恢复后自动继续。页面在自动检查时显示执行中，不再在主对话提示人工验收。
- 非 Git 或尚无首次提交的项目使用计划级托管输入快照，复用隔离 worktree、冻结与交接，保持源目录不被隐式初始化。计划格式/依赖无效时分别进行预算准入，携带错误纠正一次；仍失败则保持草案，连接失败与内容校验失败分开显示。消息内容不再误触发会话切换，当前会话重复点击保留草稿。

此 PR 还包含开发分支先前五个提交（本轮前已完成）：模型连接测试、项目上下文与权限修复、就绪/重连/历史分页改进、跨员工编码验收修复、真实 Pi/Codex/Claude 补验及相关文档。对应自审和未验项保存在 `协作/`，本轮未重写这些提交。

后续提交包含项目 Wiki 与旧文档清理、先设计再执行的高度可用测试，以及针对非法契约和资源等待的稳定交付修复。原能力探测失败记录保留，修复后的两条契约负例均通过。

非 Git 项目与对话稳定性修复完整回归 156/156；完整回归后的两个边界保护通过最终静态检查与 18/18 定向单元及 3/3 HTTP 补验。真实浏览器验证点击消息及当前会话后，未保存的需求和消息草稿仍保留。宿主执行、Git、SQLite 为真实，模型响应为测试替身；未额外请求生产付费模型。

验证：Node 24.19.0 下 npm run check 通过。自主交付原阶段完整回归 130/130；稳定交付主体修复完整回归 147/147，最终追加的状态呈现修复通过 8/8 相关定向回归及桌面验收。等待期间重启、资源释放后返工、时钟回拨不误用旧 Run、历史数据迁移和旧契约拒绝都有覆盖。隔离桌面通过“实际检查失败→暂停等待→恢复返工→重验→系统集成→交付通知”，宿主 Git/Node/SQLite 为真实执行，模型与 CLI 响应为测试替身。此前真实基础协作补验不等于本轮新增自主流程的真实模型验收。

范围限制：本轮为 Codex 自审；未用付费模型验证大型系统。能力、费率是声明值，工作量为估计；费用预估不替代预算批准或供应商限额。架构/代码超限、未知进程、冲突或扩大需求进入待处理。冻结交付保留在托管工作区，不自动应用源仓库、部署或合并 main。
