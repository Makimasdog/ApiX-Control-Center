# 多 Agent 分步骤失败自动恢复自审

日期：2026-10-22。执行与审查：Codex 自审，未启动子 Agent，不是独立审查或人工批准。

## 问题与范围

用户反馈多个 Agent 分步骤协作时，单步失败阻塞后续任务，需要手动处理。检查发现普通自动协作没有接入自主交付的修复循环；调度器还会把下游永久标记 blocked。原恢复路径只循环八次，并可能恢复自身曾执行失败或较新审批已拒绝的任务。

本轮保留现有协调器、预算、权限和验收边界，局部补齐恢复链路，不做整个系统的重写。沿用分支 `codex/apix-flow-model-project-refactor-20261022`，未经要求不推送。

审查文件：`control-plane.mjs`、`src/coordination/workflow-recovery.mjs`、`task-scheduler.mjs`、`autonomy.ts`、`coordinator.ts`，对应三个测试文件，`package.json` 与 `README.md`，以及本记录。

## 实现与自审结论

- 普通自动协作仅恢复当前已确认且仍在运行的计划中的 failed 任务；校验项目、会话修订、自动协作设置、员工当前权限和原任务授权。自主交付计划排除在普通恢复器之外，避免两个监督循环重复派发。
- 复用恢复检查、工作区指纹、策略审批与预算准入。优先选择授权范围内其他可用员工，保留原任务范围与已有工作。每任务最多两次自动恢复，窗口三十分钟；容量等待不消耗次数。
- 新增持久化恢复账本，保存原指令、次数、原运行和状态。并发 tick 有互斥；派发前落盘 prepared，重启后遇到未确认派发不重复执行。修复指令从原始指令生成，避免逐次嵌套增长。
- 自动恢复检查原运行明确结束，拒绝未知进程和代码交接冲突；检查期间任务发生变化则停止。取消、拒绝、权限撤销和额度等不满足条件时不提升授权、不绕过准入。
- 可恢复前置失败时，下游保留排队；恢复后仅重新排队未执行、没有自身错误或交接冲突、最新启动审批仍批准的依赖任务，循环至收敛，移除固定八轮限制。实际启动仍须前置验收、审批和运行准入。
- 自主交付中，修复已派发时干净的被阻塞后继继续等待，不再误判整条计划需要人工处理。普通协作不自动验收代码；自主交付沿用用户已批准的真实检查与自审。
- 新模块通过现有桌面准备脚本对 `src/` 的复制进入后端资源；新测试已加入默认测试脚本，语法检查已加入 `check`。未增加依赖，未修改版本或锁文件。

已审查调用方、异常路径、重启与数据一致性、访问边界以及新增文件。修正了仅检查当前权限而未检查原任务授权的问题，并将普通协作的修复提示改为通用工作详情入口。最终自审通过，可提交。
