# 桌面对话与自动协作开发审查

日期：2026-10-12。Codex 单独实现前后端并自审，未启动其他开发 Agent。

## 用户流程

默认进入对话工作区。左侧选择项目和历史对话，中间输入消息、接收流式回复与工作状态，右侧查看 Agent 活动、计划、代码变更与验收。新对话第一条消息直接创建目标并调用 ApiX，无须先创建目标表单。需求、预算、权限、会议及模型设置折叠为详情，保留原有功能。项目切换隔离记录与草稿，最近选中的对话按项目记住。窄屏默认收起详情，保留新对话和项目设置入口。

用户在每个项目一次点击“授权并开启自动协作”，选择可用员工。该操作明确批准 ApiX 和这些员工的完全访问权限以及项目默认执行范围、交付和验收要求，可能产生模型费用；不会自动授权后来注册的员工。项目有执行中、排队或状态未知任务时不能重新授权，避免破坏正在使用的授权版本。

开启后，真实模型把明确工作请求分类为 work，后台沿用用户已授权的项目默认范围和验收，补齐未给出的通用字段，自动确认、规划并按现有权限派发。用户具体说明优先。一般问题、冲突、信息不足或模型失败仍按聊天/澄清处理，不把任意消息或规则降级当作工作授权。计划失败显示真实阻塞，不编造完成。已确认的运行中目标仍不能通过聊天扩大范围，须调整需求或开始新对话。

严格费用/额度策略、绑定收费账户、只读权限及能力约束继续生效。需要费用上界时计划保持待审，不把 work 或完全访问当作费用授权。新的计划涉及未在自动协作中选中的员工时不自动派发。会议仍单独批准，不擅自增加会议成本。代码结果仍须审查并冻结验收，进程退出成功不代表用户验收。

“暂停自动安排”只关闭后续聊天的自动规划，不撤回已经批准的任务或完全访问权限；可在权限面板另行更改权限。“停止工作”先取消未启动任务、撤回相应授权，再请求停止本对话正在执行的员工；未知进程状态仍需原恢复流程确认。停止按钮不承诺中断尚未返回的经理推理。

## 实现与自审

- 新增 SQLite `apix_workflows` 保存项目级开关、版本和授权员工列表；既有数据不重置。
- 新增 GET/POST `/api/projects/:id/workflow` 与 POST `/api/coordination/sessions/:id/stop`，沿用现有 Host/Origin/请求体限制和员工凭据隔离。
- 使用 SAVEPOINT 原子保存工作流及权限；明确 approved、版本、布尔值、可用员工和重复输入检查。保存失败不得部分放宽权限。
- 对话自动调用既有 confirm/dispatch/scheduler；规划前后的授权版本一致才继续，规划途中关闭或重新授权会阻止派发。
- 停止入口拒绝无计划的聊天、已验收目标和未知运行，避免篡改已验收状态或跳过未知进程的停止确认。
- Pi 执行员工也兼容真实安装版 `agent_end`，保留 `agent_settled`、错误与中止状态检查。
- 复用既有聊天流、需求表、模型配置、执行/预算/会议/恢复/差异检查组件；新增桌面布局 CSS，没有新增项目依赖。
- DOM 重组时修复脱离文档节点查询产生空摘要及需求表残留的问题；聊天首条目标不重复显示；按钮忙碌状态、项目/对话切换、模型连接错误及窄屏布局均检查。

自审范围：workflow/contracts/apix-agent/coordinator 与 control-plane/server 调用链、调度/授权/停止异常路径、SQLite 一致性和版本竞争、前端布局/草稿/输入/恢复/验收、夹具及文档。结论：**Codex 自审通过**，不是独立审查或人工批准。提交前核对明确白名单和 Git blob，保留用户原有 `.gitignore` 与资料，不推送。

## 设计依据与边界
