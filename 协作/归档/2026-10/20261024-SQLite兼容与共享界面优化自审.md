# SQLite 兼容与共享界面优化自审

日期：2026-10-24。执行人：Codex。本记录是单 Agent 自审，不是独立审查或人工批准。分支为 `Kimi/sqlite-ui-polish`，未推送或合并。

## 范围与结论

已审查本轮最终代码 diff、调用方、错误路径、数据一致性及访问边界，范围为无 FTS5 环境的启动与知识库检索、旧项目记忆建表、桌面构建探测、Web/Electron 共享视觉与交互，以及对应测试和说明。

在下列验证范围与未验证项内，自审通过，可以提交。Node.js 支持范围没有放宽；FTS5 降级不等于支持 Node 22.15。Electron 45 目标运行时的真实打包冒烟未完成，不宣称桌面安装包已验收。

## 实现与审查发现

1. 知识库先建立持久化文档与分块表，再探测 FTS5。无模块时使用 `instr(lower(...))` 文本检索，保留项目隔离、空间授权、ready 状态和文档版本约束，不执行不可读的旧 FTS 虚拟表。
2. 通过 `sqlite_master` 区分 FTS 虚拟表与普通降级表，避免普通表在恢复 FTS5 后被错误用于 `MATCH`。恢复 FTS5 时对账索引：只清理失去分块的索引项并补建缺失项，不重建或删除用户文档。
3. 最终自审发现“无 FTS5 期间新增文档，恢复 FTS5 后全文检索漏文档”的跨运行时问题，已补索引对账和回归测试；补建后的文档可检索，删除后索引同步移除。
4. 旧项目记忆迁移中的 `memory_fts` 改为普通表并保留原触发器；当前项目记忆检索不依赖该表。已有数据库不被强制重建。
5. 桌面准备脚本不再把 FTS5 作为构建前置条件，Node 版本要求保持不变。README 同步说明可选 FTS5、降级行为与支持版本。
6. Web 与 Electron 继续共用同一 HTML、CSS 和前端模块。视觉调整包括深浅色表面、品牌与选中态、卡片层级、输入焦点、按钮按压、消息气泡、空状态、对话框及移动端间距，保留 reduced-motion 等既有约束。
7. 交互审查补齐动态页面标题、主要表单重复提交防护与忙状态、异步提交中的稳定表单引用、Assistant 发送状态，以及 Skills/MCP 选项卡的 ARIA 关联、roving tabindex 和方向键/Home/End 操作。
8. 表单忙状态只恢复本次实际禁用的按钮；异步失败仍沿用现有错误提示。知识库降级 SQL 复用原有授权过滤，没有新增员工、所有者或跨项目访问路径。
