## 采纳范围与最终行为

| 来源改进 | 本轮处理 | 实际行为 |
| --- | --- | --- |
| 记忆编辑重名校验 | 采纳并增强验证 | 编辑与创建使用相同的 project/scope/category/title 重名规则；冲突返回错误，原内容、版本、搜索索引保持原状。 |
| 交付引用缩短 | 采纳 | task/run 标识生成 32 位十六进制摘要，Git ref 使用单层短名称，减少 Windows 锁文件路径长度。消费者仍使用数据库保存的 commit，旧引用无需迁移。 |
| 上下文预算 | 按数据性质重写 | 历史超过 24000 字符时仅保留预算内的最新完整记录，并标出省略数量；进度超过 18000 字符时明确省略，不能拼接出残缺 JSON。已确认需求和本轮用户消息保持完整。 |
| 验收上下文 | 修复原分支缺陷后采纳 | 契约最多 24000 字符，验收证据最多 100000 字符，预算内完整送审，超出即抛错；不依赖模型自行判断截断。自动验收进入 attention，保留错误证据，不通过、不派发修复、不消耗修复次数。 |
| 规划上下文 | 完整性校验 | 员工列表、授权检查分别最多 16000 字符；契约保持完整。超限停止规划，错误不再误报成推理后端不可用，也不生成缺失上下文的规则草案。 |
| 员工环境过滤 | 修复别名与认证问题后采纳 | 过滤管理者配置的密钥变量、Ali 历史别名、同值密钥别名以及 ApiX 内部入口/数据目录、旧运行身份。匹配变量名时统一大小写；保留 PATH、HOME 和独立员工凭据等正常运行环境。 |
| 共用认证兼容性 | 明确启动前检查 | 已知运行时的认证变量如果与管理者共用名称或密钥值，启动前报出配置冲突，要求分离密钥或移除共用变量后使用独立登录；不静默移除后再启动。任务标记 blocked，避免自主循环把配置问题当代码失败反复修复。未知自定义运行时仍过滤管理者凭据，其具体认证约定需由适配器配置保证。 |
| 项目基线路径返回方式 | 不采纳 | 缺少专门失败证据和别名回归，保留当前 canonical path 与非 Git 基线逻辑。 |

保留当前版本的授权复用、qwen3.8-27b 测试模型、路由硬条件提示及相关验证记录。没有引入新依赖、数据库迁移或前端/API 配置项。

## 涉及文件与调用链

- `src/environment.mjs`：环境过滤为纯函数，不读取数据库、不修改父环境、不记录密钥值；由 `control-plane.mjs` 启动员工前调用。命令入口仍由宿主解析，Pi 仍在过滤后补齐 Windows Bash PATH，启动时注入新的 task/run/mailbox 身份。
- `src/consultation.mjs` 与 `control-plane.mjs` 的规划会议入口：Claude 与 Pi 参与者复用相同过滤，管理者自身推理仍保留必要认证。相应 fake CLI fixture 校验规划参与者不继承管理者数据目录或 Ali 密钥别名。
- `control-plane.mjs`：环境预检先于运行记录、预算预留、工作区及邮箱凭据创建；原审批/调度错误路径记录清晰的 task.launch_failed，不留下伪 running 记录。记忆重名检查先于任何写入，保留原乐观版本校验及事务。
- `src/task-scheduler.mjs`：与直接审批启动一样，将 `WORKER_CREDENTIAL_CONFLICT` 归类 blocked，普通启动错误仍为 failed，前置阻塞会传递至后续任务。
- `src/apix-agent.ts`：仅可选历史/进度允许省略；冻结输入使用完整 JSON 或拒绝处理。规划超限向宿主传播明确错误，避免错误类别混淆。
- `src/code-handoffs.mjs`：仅改变新交付的 ref 名；交付 commit、fingerprint、调用方读取逻辑不变。
- `test/agent-os.test.mjs`：HTTP 重名拒绝，并核对原记录版本和内容未改。
- `test/apix-agent.test.mjs`：最新完整历史、合法 JSON、确认需求不丢失；50 KB 证据中段保留；证据/契约/员工上下文超限在调用模型前失败。
- `test/autonomy.test.mjs`：使用实际 Agent 审查函数，验证超预算在宿主自动验收中进入 attention、检查记录为 error，且不接受、不重试。
- `test/environment.test.mjs`：大小写、密钥别名、父环境不变、独立凭据保留、共享凭据明确拒绝、自定义适配器名称兼容。
- `test/coordinator.test.mjs`：实际员工子进程的环境存在性验证；共用凭据在创建 run/workspace 前失败；短 ref 指向数据库交付 commit，后续任务读取冻结成果而非未验收修改。

## 自审结论与限制

已审查本轮源码、测试、调用方、失败路径、记忆一致性、凭据边界和交付引用消费者；没有把原分支的截断逻辑或旧版整文件直接覆盖到当前分支。上下文超限选择停止并交由用户检查，不自动切块，也不承诺所有供应商都能容纳字符预算以内的提示；字符上限不是 Token 精确估算。

环境过滤只改善子进程环境传递，不构成操作系统或文件系统隔离；获得完全访问权限的员工仍受现有执行权限模型约束。已知 CLI 认证冲突可明确诊断，自定义适配器的任意认证变量无法自动识别，需要自行配置独立凭据。

本轮未进行真实模型付费联调、浏览器交互或 Linux/macOS 验证，也未重启现有 ApiX 服务。此项改进不能单独证明完整系统达到高度可用。真实模型联调继续使用既定的 qwen3.8-27b 测试配置。

最终自审结论：通过。最终配置阻塞处理已补测；全量回归无失败。仅暂存本轮明确文件，保留原 `.gitignore` 修改和其他未跟踪文件；不切换分支、不推送、不合并。提交前复核暂存区与被审查文件一致。
