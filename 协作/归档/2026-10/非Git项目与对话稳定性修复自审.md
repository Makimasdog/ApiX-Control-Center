## 问题与验收用例

- N01 普通目录、无首次提交的 Git 目录、空目录：建立计划级输入快照，创建任务 worktree，原目录无隐式 Git 初始化/提交。
- N02 排除 `.env`、常见私钥、依赖目录，遵守 `.gitignore`；忽略目录内的大文件不计入快照。链接和超限输入拒绝，失败不发布半成品基线。
- N03 同计划复用冻结输入，新计划重新取输入；篡改托管 HEAD 或路径拒绝。既有 Git 项目仍使用源仓库。
- N04 HTTP 实际派发、冻结、依赖代码交接、服务重启、检查和集成；非 Git 集成不能被误写入输入基线。
- N05 没有 worktree 的失败任务可检查非 Git 源目录指纹；源内容变化使恢复指纹失效。恢复核对最多 20000 条目/100 MiB，保留已有进程与授权校验。
- N06 ApiX 数据目录本身不能作为快照输入；未找到、无权限执行或超时的 Git 入口不标为普通非 Git 项目就绪。
- P01 模型响应具有非法前序依赖：携带宿主错误纠正一次，成功后生成正常待审计划；尚未授权时仍不执行员工。
- P02 连续非法依赖：有限重试后保留草案，不启动员工，显示模型内容校验失败。推理连接失败不走内容修正分支。JSON 代码围栏前后空白可解析。
- U01 真浏览器中点击用户消息、ApiX 回复和当前侧栏会话：保留未保存需求编辑及未发送消息草稿，不重选当前会话。

## 诊断与实现

只读检查本机 SQLite 的最近模型错误，实际记录为“计划依赖无效”。原提示将推理异常和模型内容校验失败都说成后端不可用，此结论不成立。没有发送新的生产模型请求，也未读取或展示密钥。

`project-baseline.mjs` 使用计划 ID 和规范源路径绑定托管输入目录，快照原子发布，显式文件列表暂存，通过 commit-tree 创建内部基线，避免运行提交钩子。原有 `git-worktree` 登记、common_dir 核对、交付指纹、冻结和依赖补丁流程保持适用。工作区创建、重用、集成、就绪判断和恢复检查同步适配。非 Git 集成仅提供成果工作区，应用入口明确拒绝修改托管基线。

计划校验失败分类为 inference/response，内容失败最多纠正一次，各次经 `metered` 独立预算准入。重试不会将无效计划当作成功，也不扩大员工授权。自主架构失败显示具体原因。前端会话切换仅由侧栏 `button[data-session]` 触发，重复点击当前会话跳过；主内容按钮事件不再匹配用于渲染缓存的 `data-session`。
