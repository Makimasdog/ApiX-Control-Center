`task_started → task_baseline → delivery_record` 保存在现有 `assistant_events`；快照在现有 `assistant_outputs`，没有新增表、重复状态数据库或重写旧数据。原会话 API 保留，额外返回 `review`。旧会话没有原始基线时明确 unknown scope，不把历史编辑冒充当前任务贡献。首条新对话消息创建任务；后续消息、审批和恢复不重开任务，显式“开始下一任务”才切换边界。

任务基线不是 Git HEAD。多次编辑合并、恢复原字节消失；命令新增/删除及外部变化也纳入，只有文件工具的 SHA 链完整连接基线/最终结果时认领来源。冻结交付包含任务/交付 ID 与版本、manifest、基线/最终引用、代码指纹、契约与检查证据、日志引用以及单独的模型摘要。只读任务可交付说明而无需假检查。

`delivery-review` 仅作为用户 API，不注册模型验收工具；文本/模型 JSON/MCP 输出不执行此动作。仍沿用本机信任边界，不把任意本机程序隔离视为已解决。模型有 full_access 时的任意恶意程序不在 OS 沙箱保证内。

确认绑定会话版本、taskId、deliveryId 与版本，并重新核对当前指纹、契约、必要输出/日志的完整性及保留期，以及当前/同项目会话的活跃和未知操作。用户决定和版本递增在同一 savepoint，记录或会话更新失败会回滚。相同请求幂等，换动作/内容不可复用同一请求 ID。历史 accepted 不因后来变化被删除；当前检查失败、证据失效、工作区变化时不继续显示当前 accepted。

修改意见保存后检查失效，同任务重新检查产生 v2；保存意见不自动调用模型、不回滚、不授予权限/预算、不重放。显式继续沿用已有模型、费用与权限路径。归档/删除依旧由现有会话访问门槛处理；重启通过持久化事件/快照重建，不依赖内存 busy 保证安全。

## 实际浏览器流程

执行 `node scripts/verify-delivery-browser.mjs`，启动真正的 `server.mjs` 与生产页面，使用独立临时数据和回环 HTTP 模型；CUA 操作实际控件，没有离线 HTML 代替 E2E。

1. 在生产“与 ApiX 对话”发修复目标，批准固定 `unit` Node 检查与 `src` 范围。
2. 查看 v1 的 `src/add.cjs` 冻结净差异、代码/契约哈希、检查完整性与 stdout 尾部。
3. 保存修改意见，观察“已请求修改”、旧检查失效及未自动执行。
4. 点击“按意见继续”，同任务产生 v2；点击“确认验收此版本”，刷新仍显示已验收。
5. 显式发送下一任务，仅新增 `src/note.md`。任务 B 有新 ID，v1 净差异只有 note.md；历史任务 A v2 仍有用户验收记录，同时因当前内容变化标为过期。
6. 最终界面再次刷新，历史回看没有重复意见输入或验收按钮。窄屏补了实际可打开的详情面板。

## 边界与自审结论

保留原可信契约的完整扫描限制；审阅快照额外限 3000 项/8 MiB、文本 256 KiB/文件、单工件 24 MiB、总计 128 MiB/30 天，日志沿用 7 天。超限拒绝、不跳过验证。容量/期限淘汰保留事件元数据但相关版本不可再验收。差异最多单文件 16000 字符、合计 64000 字符，大跨度通过冻结文件分页核对；二进制仅元数据。链接拒绝，凭据文件排除，不提供通用回滚。

核对了新增文件、生产调用方、错误路径、会话/项目归属、版本冲突、失效、数据库 savepoint、HTML 转义和范围边界。最终 check/build 通过；B 定向及生产浏览器流程通过，新增真实文件操作未知与重启/审阅组合为 11/11（`p11-review-safety-final.log`，26.19 秒）。B 范围自审通过；提交时组合完整测试仍在运行，终态后补到总报告，不把当前进度当全量通过。暂存仅 B 文件及其共享夹具目录，package.json 分开暂存 B 清单，保留工作区 C 清单；未纳入用户原有改动。未削弱可信验收/进程恢复门槛，未重写调度、模型后端或增加依赖。结论为 Codex 自审，不是独立审查或用户批准。
