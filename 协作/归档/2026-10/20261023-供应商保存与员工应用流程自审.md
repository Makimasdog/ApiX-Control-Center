# 供应商保存与员工应用流程：自审

日期：2026-10-23。Codex 实施并自审，非独立审查。

## 实际原因与范围

只读检查当前桌面供应商目录：唯一配置为 Chat Completions，绑定 ApiX；Codex 和 Claude 员工均无供应商绑定。地址仍含 workspaceid 占位符。现有进程适配代码已支持 Responses/Codex、Anthropic/Claude 的私有覆盖；问题是保存与应用语义不清、UI 隐藏不兼容选项、允许保存未填实际值的地址。用户明确选择分别配置各 CLI 原生兼容接口，不建设转换代理。

修改 web/provider-center.ts：显示员工绑定来源、兼容协议，保留不兼容项但禁用并标注；提供员工定向创建及保存并应用。仅保存不新增绑定；编辑已绑定配置继续沿用原有更新语义。两步请求失败时如实显示已保存但未应用，刷新目录并清空密钥输入。对已绑定同一配置的保存不重复应用，防止 ApiX 管理配置版本在保存后变化引发错误。

修改 src/models/agent-providers.mjs：拒绝未替换的花括号/尖括号占位符（含 URL 编码形式），在密钥存储前校验，不自动改写旧配置。员工空闲状态、协议匹配、版本检查、独立费用维护与进程隔离规则保持原路径。

测试涉及 test/agent-providers.test.mjs、coordinator.test.mjs、fake-provider-worker.mjs、scripts/verification/verify-provider-center.mjs；使用指南补充操作步骤和协议边界。

## 限制与下一步

不调用真实 CLI 的付费推理，不修改用户现有地址/密钥/员工绑定，不转换协议，不推送、不重新打包 Electron。用户需在新版本中为 Codex 提供支持 Responses 的实际接口，为 Claude 提供 Anthropic Messages 的实际接口及支持的模型；不能只将现有 Chat 接口改名。当前桌面进程仍运行此前打包产物，需重新打包后才能测试本轮 UI。
