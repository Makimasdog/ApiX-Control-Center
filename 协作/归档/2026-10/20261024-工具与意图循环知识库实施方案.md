# 工具安全、意图澄清、循环恢复与知识库

日期：2026-10-24。执行与审查：Codex 单 Agent；本文件为实施方案，完成状态以同日验证记录为准。

## 现状与兼容边界

- `assistant-loop.ts` 统一驱动 ApiX 工具，`tool-registry.ts` 已有 AJV 校验；文件沙箱、审批、版本绑定验收、`assistant-effects.ts` 副作用收据继续复用。缺口是未知字段、跨字段约束、按工具授权与统一审计。
- `permissions.ts` 按项目及 apix/employee 控制 full_access/ask_approval/read_only；员工的 role 是岗位说明，不是安全角色。系统没有登录账号或租户表，实际身份是本机所有者和带运行令牌的员工。普通管理 API 目前只有 Host/Origin 防护，需要所有者能力凭据。
- 对话已有持久化 pending、版本号、requestId、选择/自由输入。增加 intent 类型与三选一契约，不另造对话系统。
- 主循环已有 24 步/30 分钟上限；模型退避重试、员工失联检测和副作用未知暂停已实现。增加持久化调用观察及无进展检测，保持现有故障策略。
- SQLite、项目记忆、来源显示及桌面启动链可复用。知识库是用户管理的参考资料，独立于自动记忆，不自动提升为系统规则。

## 1. 工具权限与参数

所有者凭据使用随机能力令牌；Electron 启动时传入后端并通过请求头换取 HttpOnly/SameSite Cookie；独立浏览器通过本机登录页输入数据目录内令牌。管理 API 默认拒绝无凭据访问；员工令牌只开放员工通道。凭据从员工环境移除。它不是 OS 沙箱：与所有者相同操作系统权限的任意 CLI 仍可访问本机文件，不声称支持恶意租户隔离。

工具网关按 project/subject 查询角色与 allow/deny；planner 只读、executor 不能配置/委派、coordinator 可编排；所有角色继续受原有项目策略、员工授权及操作审批约束，deny 优先。所有者负责管理角色，Agent 无管理接口。 builtin schema 拒绝未知字段；MCP 保留其声明的 schema；统一限制深度、字节数、原型字段、NUL 及读区间。错误包含 code/retryable/action/details，不回显敏感原值。审计保存调用身份、工具、脱敏参数摘要、结果状态与原因；不复制完整结果。

接口：项目工具策略 GET/POST（乐观版本）；受限员工工具 POST 从运行令牌推导项目与员工，不能接受调用者伪造身份。数据：tool_access、tool_audit。验收：跨项目、员工冒充所有者、未知字段、危险参数、撤权与敏感日志测试。

## 2. 意图澄清

新增 JSON 动作 clarify，携带 question 与恰好三个非空、互异、受长度限制的 candidates；宿主追加第四项“以上都不是，我来补充”。提示要求候选基于用户原话与上下文、差异影响执行，不借机请求新权限。明确任务直接执行。安全角色、项目范围或批准不由候选结果改变。

复用 pending/requestId/version；等待时主循环停止，允许显式列出的只读准备工具，不运行写入、远程或费用操作。答复支持单选、文本修正、纯文本；第四项必须补充文本。确认事件与新的用户指令共同写入，后续上下文读取确认内容。重启保留 pending，过期答复拒绝。验收：精确四项、选项数错误、重复候选、空补充、并发过期答复、等待期间不写入。

## 3. 工具死循环

以本轮用户指令/恢复事件为 turn，持久化规范化参数散列、语义结果散列、错误代码与观察。有效分页参数保留；结果中时间戳/执行 ID 不构成进展。轮询单独限次并延时，真实状态变化视为进展。相同调用相同结果、连续失败、短周期 A/B 回路与总调用/时间/返回字节预算分别判断。

首次重复路径阻断后返回结构化纠正指示，允许模型选择其他路径；继续重复则暂停并显示原因。确定性参数/授权错误必须改变参数或权限版本；临时请求重试沿用现有退避，未知副作用不自动重放。缓存收据复用也纳入观察。配置按项目保存，范围受硬上限限制，不能由模型无限放宽。数据 tool_observations/tool_limits。验收：重复、A/B、合理翻页/轮询、权限错误、预算、恢复及有副作用操作只执行一次。

## 4. 知识库

选择本地 SQLite FTS5 关键词检索，兼顾英文词与中文字符/双字；不增加嵌入模型、向量服务或网络数据流。适合本机小型项目资料；语义改写召回有限。首版支持 UTF-8 txt/md/html/json/csv；不支持的 PDF/DOCX 明确拒绝。每文档最多 1 MiB、有限分块；上传 JSON/base64 有总大小限制。

库/文档 CRUD、文档状态、检索与引用读取 API 按项目及主体授权；管理只允许所有者。数据 kb_spaces/kb_documents/kb_chunks/kb_fts/kb_grants；文档版本和内容哈希绑定分块。上传/更新先在事务内清除旧索引并置 processing；纯本地后台解析用版本 CAS 原子发布 ready。删除级联清理，过期任务不能复活文档；服务启动重新处理 processing 文档。失败可查看并重新上传，不返回旧内容。

工具 search_knowledge/read_knowledge 返回 reference_only、不可信数据标签、稳定引用（库/文档/版本/块）、文件与行号。检索先做权限过滤，引用读取再次核验版本与授权；回答引用必须来自本会话实际检索且仍有效。无结果明确证据不足；宿主无法自动证明语义蕴含。接触知识库后写操作继续需要绑定参数的明确批准，不能靠资料中的指令触发。UI 提供库/文档管理、上传、状态、检索预览及来源查看。

## 验证与部署

增量 CREATE TABLE/INDEX 迁移，旧表不破坏；先用隔离临时数据库及本地模型桩验证，不消耗真实模型额度。覆盖权限、参数、并发版本、删除/重建索引、重启、意图等待、循环停止、UI。运行构建、相关测试及回归，最终 diff 自审和暂存区一致性核对后提交；不推送或合并。部署沿用 npm build / Electron prepare，所有者令牌及数据库必须留在本机数据目录，不提交或写日志。
