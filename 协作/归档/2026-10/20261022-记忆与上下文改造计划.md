# 记忆与上下文改造（Codex 实施、自审）

## 核对与规范来源
- assistant-loop 创建、写入并召回 assistant_notes；assistant 页面编辑它。control-plane 的 memories CRUD、Director 自动提取、员工上下文及项目记忆页面使用旧表。read_memory 有旧表回退。这是需要消除的双写/双读。
- project_profiles 保留为用户维护的结构化档案，不复制成自动记忆。apix_ledger 保持协作事件账本。
- assistant_events 是原始事件，assistant_outputs 是不可变结果引用；不删除它们。chat-history 的归档/软删除、重启中断与审批路径保持原义。
- 当前压缩目标是 72%，只有 before 估算；根指令只有三种根文件且 16KB 上限；员工还会携带同旧对话的任务历史。这些与目标存在差异。

## 迁移与读取路径
规范长期记忆为扩展后的 assistant_notes。增加稳定 ID、范围、任务关联、版本审计及项目设置；旧 memories/memory_revisions 保留只读，幂等版本迁移保留内容、来源、版本、任务范围。标题冲突使用稳定旧 ID 后缀，避免覆盖已有笔记。敏感旧内容隔离停用，原始旧表不改；API 不回显敏感内容。

统一路径：主循环/协调器/员工 → 相同记忆服务 → 项目隔离索引 + 相关正文；员工仅携带任务范围相关内容及前置交付物。旧 HTTP 记忆接口作为同一规范服务的兼容适配，不再写旧表。项目档案独立结构化区明确标识。

迁移使用 SQLite savepoint 和版本标记；任一失败全部回滚。回退旧程序前应停服务并备份整个数据库，旧表保留迁移前原值；新期间数据在 assistant_notes 与版本审计中保留，不能直接回退程序并声称新数据已自动回流旧表。实施测试核对逐条内容/版本以及重复启动不重复迁移。

## 实施与验证
1. 统一服务、迁移、安全过滤、索引与生命周期。
2. 分层文件解析（复用 projectPath）、作用路径、导入确认与预算。
3. 分类预算、分级裁剪、手动/自动压缩审计与重新注入。
4. 三种 Agent、现有 UI/接口接入。
5. Node/浏览器离线测试、build/check、最终 diff 自审、明确文件提交；不推送、不合并、不调用付费模型。
