# 五项使用反馈修复与自审

本轮由 Codex 完成前后端及自审，没有启动子 Agent。分支 `codex/readiness-p0-p2`，基础提交 `5cecf41`。本记录属于自审，不是独立审查或人工批准。

## 问题与实现

| 反馈 | 排查结果与修复 |
|---|---|
| 无法添加项目 | 在本机隔离环境，合法绝对路径原本可以创建，未取得另一台电脑的失败响应，不能断言其唯一原因。修复项目保存与进行中的快照刷新竞态；创建后取新快照，再选择新项目。目录选择及手工路径会自动补充空项目名，用户填写的名称不覆盖；新建目录仍需显式勾选，错误保留在表单。实际浏览器验证已有目录选择和新目录创建均成功。 |
| 历史不能归档/删除 | 新增共同历史服务，为主对话和协作目标增加 `archived_at` / `deleted_at`；提供当前、已归档、最近删除及恢复。删除是可恢复的软删除，原始对话、工具结果、任务和验收证据保留。活动、待审批、排队、未知进程未处理时拒绝归档/删除。旧版本请求拒绝。 |
| 查额度返回 DSML/JSON 错误 | 主循环新增 `inspect_quota` 只读工具，调用现有真实 Codex 查询，并分别返回关联账户手工快照与执行暂停。Schema 校验员工 ID，不接受任意命令；无官方接口时保留未知。非 JSON 回复未执行，最多额外一次受预算与步数约束的协议纠正，仍无效则明确暂停。旧协作引擎也改为可理解的协议错误，不直接显示 Unexpected token。 |
| 侧栏及通用工作区混乱 | 主对话和协作目标共用一个侧栏，记录标记类型，切换管理总览不再更换侧栏来源；点击记录进入对应页面。保留“新协作目标”入口。切项目、换对话时清空旧正文、记忆、摘要、工具、审批和状态，响应核对项目与会话归属；不把旧项目的对话渲染到新项目。 |
| 最后任务长期排队 | 截图明确写着 Codex 因额度/速率错误暂停，不是单纯等待前置。新增五秒定期队列复核，恢复漏通知或服务重启后已批准且可执行的队列；前置未验收、暂停、额度、预算、权限及并发仍会阻止启动。对话底部直接显示排队原因和“查看执行暂停与账户阻塞”入口。重复复核不重复启动，不对未变化的排队原因重复写入。 |

## 使用方式

- 添加项目：选择文件夹，或填写绝对路径；新目录勾选创建目录。项目名可自动填充，也可以修改。
- 归档、删除和恢复：侧栏每条记录右侧操作；切换“已归档”或“最近删除”后恢复。正在执行的记录先停止并处理遗留任务。
- 查询额度：在“与 ApiX 对话”提出查询员工额度，主循环可先查看员工，再按员工 ID 查询。实际运行时额度与用户维护的预算快照不能混为同一来源。
- 截图中的排队：核对账户实际额度后，在任务下方点击“查看执行暂停与账户阻塞”。检查“执行与暂停”及“能力与预算”，按实际状态明确恢复相应运行时/共享账户；只恢复其中一层时，另一层仍可能阻止启动。系统不会因为用户说“前置已完成”就绕过冻结验收或费用审批。

## 自审范围与边界

检查所有新增文件、调用方和错误路径：`chat-history.ts`（后端/前端）、两种会话服务、HTTP 路由、项目保存与文件夹选择、统一侧栏、额度工具、模型协议解析、调度器、测试夹具与测试脚本入口。

- 历史表迁移保留现有数据；操作类型、版本、会话归属和执行状态检查在宿主完成。恢复仅修改历史元数据，不重放工具或自动恢复运行。
- 归档/删除不能藏起待检查的进程不确定性；主循环原有项目并发保护、审批、文件指纹和验证门槛未移除。
- 主循环按实际会话 ID 获取历史，并核对项目归属。自审发现统一历史上限与原 100 条主会话索引不同：较早的合法会话不能被短列表误判为失效；已修复，并在 150 条记录的浏览器项目中打开最早一条验证。
- 历史渲染转义标题和状态，动态结果不执行 HTML；异步加载有项目/代次保护。切项目时清理当前会话与所有详情，保留按项目/会话保存的输入草稿。
- 额度查询只读，不修改账户余额、费用账本、暂停标记或模型。运行时实际值和手工快照注明来源；认证或额度接口不可用时不编造剩余数值。
- DSML 不转换为宿主调用，也不执行其中参数；纠正请求不回灌原 DSML 内容。额外推理仍走原预算预留与停止/权限撤销检查，最多一次。持续协议不兼容仍会暂停，不能宣称已兼容所有模型原生工具格式。
- 五秒复核只处理已排队任务，仍检查前置验收、启动批准、运行时暂停、共享账户、费用和并发。运行中和未知任务不会自动重放；正常检查后恢复才允许排队。
- 队列 API 和界面同时显示真实阻塞原因；保留原有恢复、换人和验收入口。不把“模型回复同意”视为实际执行或验收通过。
- 不修改原 `.gitignore`、用户技能、说明文档和临时测试页面；不推送或合并。

## 未验证及限制

- 未访问或修改用户另一台电脑的 `127.0.0.1:4173`，也没有代用户恢复其真实 Codex 暂停、增加预算或验收 KMeans 任务。截图中的具体任务是否能启动，仍须在目标机器更新后核对实际账户和暂停状态。
- 主循环支持一次 JSON 协议纠正；若供应商持续返回 DSML/XML 或原生 tool_calls，仍会明确停止。旧协作目标保留原受限 JSON 决策流程，实际工具/额度查询使用主对话入口。
- Claude、Pi、自定义 CLI 尚无已接入的统一官方余额接口时会返回未知；不将其当作零，不从品牌推测额度。
- 历史当前每种会话、每个筛选最多取最近 500 条。没有提供永久擦除原始审计数据的按钮，也没有新增跨项目统一历史视图。
- 没有进行真实付费模型、真实多账户压力测试或其他操作系统的浏览器验证。
