## 范围与结论

已审查最终工作区 diff、新增模块及调用方，覆盖 HTTP 身份边界、主循环/员工宿主工具、Schema、审批与副作用收据、澄清持久化、预算/循环观察、知识库处理/授权/索引/引用、Electron 启动认证、前端表单/来源展示，以及测试客户端的认证兼容修改。原有模型供应商配置、全局 CLI 配置和用户生产数据没有被本轮更改。

## 发现与修复

1. 普通管理 API 只有 Host/Origin 约束，员工可以删除自己的 Bearer 后尝试管理接口。增加独立所有者能力凭据；员工仍使用运行令牌，不能回退到所有者 Cookie。Electron 自动认证，浏览器有显式连接页；无测试后门。
2. 新 schema 最初将 `reasoningLevel` 写成字符串，与现有整数能力档案不符。修正为整数 1–5/null，并复测委派、档案隔离和中止流程。
3. 初版审批预览把普通命令参数一起隐藏，影响用户核对和验收清单绑定。分离审计载荷隐藏与审批预览脱敏，保留普通参数，识别到的秘密仍隐藏。
4. 新增严格未知字段校验和操作收据复用后，旧测试仍假定 run_check 接受额外命令参数、重复相同写入会再执行、超时只会走旧提示。修正测试为先拒绝非法字段、修正后运行全部可信检查、确认只执行一次，并保留真实超时/失败证据断言。
5. Skill 记忆夹具未提供既有记忆协议要求的 evidence。改为引用真实加载的 Skill 原文、作为 reference 候选，不伪造用户确认。
6. 部分原生 `http.request` 测试绕过了 fetch 包装，没有携带新所有者凭据。补齐真实认证头；保留无凭据/员工凭据访问管理接口为 401 的负例。
7. 首次项目载入可能覆盖刚输入的知识库表单。未就绪时禁用表单，处理切换项目的过期响应，保留后续编辑草稿。
8. 直接 read_knowledge 最初未登记来源观察收据。已补齐，搜索和直接读取均可生成合法可追溯引用。
9. 相同参考文件在真实修改多个文件时可能被误判无进展。增加实际文件哈希进展标记；同一轮询工具的真实结果变化与跨工具回路分别处理。
10. 澄清请求或答复的事件落盘失败可能留下部分状态。请求及确认都加入保存点事务；注入存储失败验证全部回滚。
11. 旧对话中的知识库摘录可能在更新/删除/撤权后通过旧上下文继续使用。现在在构建上下文、接收模型决定、派发工具前复核本对话观察过的来源；失效则暂停并要求新建对话，旧审批也不能执行。所有者历史审计仍保留，不宣称供应商能“忘记”已接收内容。
12. 新增 owner-access.json 是敏感文件。已补入项目读取/搜索、诊断清单、交付快照和知识库上传的凭据排除规则，并测试大小写路径。员工环境也清除令牌同值别名。
13. HTML 文本提取及分块行号计算改为线性扫描，避免大量未闭合脚本标签与逐块重复前缀扫描带来的无进展消耗；格式错误仍进入 failed，不发布半索引。

## 未验证项与限制

- 未做付费模型/各 CLI 供应商的真实语义质量评测；候选意图是否符合业务、引用是否足够支持结论仍依赖模型与用户判断。宿主验证结构、来源观察、有效版本和授权。
- 不是多用户/多租户服务器，也不是恶意 OS 进程沙箱。外部 CLI 自带的原生工具不经过本轮宿主调用检测器，不能宣称其全部原生操作已被统一管控。
- 首版知识库是本地文本与关键词检索；PDF/DOCX/OCR、向量/混合检索未实现。单文档上限 1 MiB。检索片段用于 Agent 时会进入当前模型/CLI 供应商上下文并消耗原有额度。
- 失效知识来源采用保守的“新对话重新检索”流程；删除库/文档会删除当前库原文与索引，但不抹除先前对话/审计中已经保存的历史摘录。失效对话不会再把这些摘录交给模型，所有者仍可回看。
- 未做断电/磁盘损坏、跨进程共享同一数据目录的压力与恢复验证；支持的部署是一个实例管理一个数据目录。解析状态恢复覆盖重建服务对象与持久化状态分支；不把它描述成强制断电演练。
- 未重新生成安装 exe，也未用用户真实数据自动启动新业务任务；Electron 验证使用隔离开发实例。部署及备份步骤见接口与使用说明。
