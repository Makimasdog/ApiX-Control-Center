# 外部 Agent 工作台实施自审

日期：2026-10-30。Codex 自审，不是独立审查或人工批准。用户要求在新分支实施，并在本轮明确选择持续推进 D0–D4。基线 `8b754ef`，分支 `codex/external-agent-workbench`；未额外启动子 Agent，未推送、合并或启动真实员工推理。

## 范围与结论

审查本轮最终差异、新增源码/脚本/测试、调用方、异常路径、数据一致性与访问边界。交付 D0–D4 的本地闭环，新后端继续按员工显式试验，默认 CLI。契约及实现差异见 [实施文档](../../../docs/设计/2026-10-30-外部Agent运行与协作工作台实施.md)。自审未发现遗留阻断项；真实供应商与生产桌面门未登记通过。

检查项：

- 旧 CLI 通信迁出后，所有原任务 child 调用方改用运行句柄；旧原生解析/故障、用量、Pi 结束/abort、UTF-8、分块事务与末行继续保留。咨询专用的独立只读/受限进程不改为执行 Run；Codex 额度与执行只共享握手，不共享进程。
- 原生 turn 完成与物理进程退出分开。完成后还有已接收队列则继续同 Run；否则先关闭再收尾。保存实际 exitCode，另存 native outcome；unknown 不按成功处理。根先退出不能冒充后代停止证明。重复终态/输出、异步 spawn/断连、停止与关闭异常均走有界收尾。
- 附表迁移幂等、不回填猜测事实；Run/任务/员工归属由旧事实源推导。配置指纹含供应商、权限、能力、执行文件身份等非秘密值。模型/后端变更影响后续 Run，设置保存与原能力版本递增同事务。新表按归属级联；回退不删表。运行结束释放内存中的脱敏秘密匹配表。
- 供应商继续由既有 prepare 隔离；SDK 要求显式 Anthropic Messages 绑定，独立配置根、关闭 hooks/设置自动加载、限制工具；不复制认证文件、不修改 process.env。私有思考不进入公开事件；仅已知有效用量字段持久化，其余厂商字段不入回合 usage。API 不回传原生 session、env 或凭据。
- 新 API 走原 owner/Host/Origin/限额/ToolError 管线；只接受 ApiX ID。分页方向互斥、limit≤200、游标绑定 Run；旧原始事件仅作类型摘要。答案按当前问题结构验证，审批只能批准/拒绝本次，不可传入工具/env/目录。未知原生方法明确拒绝，不默认批准整轮权限。
- 指导先写 mailbox/投递状态再进入原生通道；宿主 ack 不等于员工已处理。requestId 与内容/模式指纹幂等，可能已接收时保留 unknown，不自动重投。旧协调入口接到同一服务，展示原生投递状态；无 requestId 的旧客户端保留原边界。问题、权限与期限检查和原恢复准入继续生效。
- 原生延续仍通过既有 recovery 及工作区指纹检查，新建 Run/令牌/预算。不同员工、配置、工作区、原生会话或未知停止拒绝延续；不静默变 fresh，不复活旧交互。自动修复/改派保持 fresh。已 accepted 的任务不允许继续修改。
- UI 共用纯折叠模型，Run+事件 ID 去重；选择代次阻止旧响应写入新面板。公开输出通过 html/textContent，工具与问题不执行厂商 HTML/链接。增量不重建指导表单，历史投递状态可重载；缺少统一帧时明确说明，公开报告严格按 Run 读取，不能拿最新任务报告覆盖旧 Run；失效交互不可继续提交，双员工不串答。实际宿主检查与报告分开，未验证明确标示，验收继续调用原入口。

自审中已修正：将 native outcome 与真实退出码分离；重复完成与 SDK 多轮输入边界；源读取与旧回合请求顺序；关闭/投递不确定性；设置版本与旧批准；原生 session 不匹配不得静默续聊；使用宿主组件和中文状态，保留历史投递反馈。修正后重跑重点测试与工作台浏览器。
