# 节省模式补读优化与真实对照（Codex 自审）

结论：本轮范围自审通过。相同任务、相同模型的两组反向顺序实测中，节省模式均完成任务且无补读；两次合计 Token 减少 **54.16%**，观测总耗时减少 **50.01%**。只读单任务小样本不代表跨任务收益，更不代表费用节省。扩大验证仍有一项基线 Windows 命令测试失败，见下文，不能称全套测试通过。

## 范围与实现

- 基线 bf76bd8，继续使用 codex/token-usage-optimizer；本轮用户要求测试、自审及提交，没有推送授权，不推送或合并。
- 仅改 assistant-context.ts 的节省模式模型历史投影、assistant-loop.ts 的节省模式回读提示、相关测试与文档。没有新依赖、数据库迁移、业务入口或供应商配置改动。
- 旧策略：文件结果也会因事件变旧触发 1200/800 字符折叠，模型即使刚读过正常大小的文件，也可能只能看到短预览，转而补读引用或重复读文件。
- 新策略：对 `ok=true` 且有 content 的 read_file 页，按原始 body JSON 的 UTF-8 字节数提供额外保留池，单页不超过 24 KiB、不同原始结果合计不超过 32 KiB，优先近期页。同一原始 body 多次出现只占一份预算。入选页不因年龄折叠，池外保持原规则；不是整段上下文的硬字节上限。已有总 Token 预算和受控压缩继续生效。
- 对当前实际 history 中完全相同且 `ok=true` 的 read_file/read_context 结果，只保留首次正文，后续项用 contentAlreadyInHistory/duplicateOfEventId 指向当前 history 内已有正文，其他字段全部保留。不同哈希、范围、下一页、内容或其他元数据不合并。原事件离开窗口后重新输出正文；不持久化去重状态，不跨会话、跨压缩保留悬空链接。
- 模型新增 contextReadPolicy，提醒已有正文可直接用于核查，缺范围、下一页或新版本才补读，不能将部分页当成完整文件。宿主不禁止模型再次读取。
- UI history、输出读取 API、会话归属、权限/审批、未知结果门禁、Token 账本与费用口径均未改变。原始事件和引用正文不删改，read_output 不参与此次去重。
- 未实现设计中的 stable-prefix-v1、持久投影帧、供应商缓存诊断或显式缓存控制。
