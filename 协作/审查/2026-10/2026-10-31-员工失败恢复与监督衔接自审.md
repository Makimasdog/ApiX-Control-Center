# 员工失败恢复与监督衔接自审

日期：2026-10-31。分支 `codex/external-agent-workbench`，基线 `0a90dd3`。本记录为 Codex 自审，不是独立审查或人工批准。

## 问题与范围

用户反馈员工失败后整个流程阻塞。只读检查本机历史库，确认一条 easyreader 失败记录为“计划任务要求 Git 项目以创建独立 worktree”；未修改用户项目、历史任务、运行方式、权限或预算。历史记录不证明当前项目仍缺少 Git 条件。

源码已有有限自动恢复，本轮定位并修复其与主会话监督、展示之间的断层：

- 普通协作整体状态没有区分“具备资格、等待自动修复”和“必须人工处理”。补充只读 recovery 视图，可恢复 failed 不立即聚合为 attention；unknown、拒绝、冲突等不被掩盖。
- 子流程仍运行/排队时，模型 finish blocked 会提前结束主会话监督。现在继续等待，员工最终全部验收后接回主循环；真正阻塞仍暂停。
- 普通修复指令缺少实际失败诊断，主会话观测也缺少失败与恢复信息。现在补充脱敏、限长诊断；工作台显示失败原因、恢复次数和处理原因。
- Git 工作区准备条件失败不应消耗重复员工修复；该明确错误归为 configuration，保留人工核对条件。

没有引入第二套重试流程、额外权限或新模型调用通道。普通协作仍最多 2 次/30 分钟，自主交付策略不变。没有自动解除已有 attention，没有自动初始化用户仓库，也没有把员工完成等同验收通过。

## 最终 diff 自审

检查 control-plane 装配、coordinator 状态/接口调用方、workflow-recovery 的资格/限额/原进程/代码冲突/依赖、assistant-loop 的监督和重启路径、前端 html 插值、提示词投影、所有新增测试及文档索引。

修复与核对：

1. 恢复展示资格与实际恢复门禁对齐，原运行未确认结束、交接冲突、未验收前置不能显示可自动修复；原因具体展示。
2. 恢复结果没有新建任务身份或复用旧 Run；HTTP 验证旧失败 Run 保留、新 Run 改派、工作区文件保留，后续依赖仍等待验收。
3. 新 supervision_waiting 仅是展示提示，标准和稳定布局均排除；既有 delegation_blocked 作为失败事实明确登记，避免 stable 遇到未知事件失败。
4. 前端新增失败片段一度使用嵌套 html 插值，浏览器验证发现被双重转义；改为完整片段拼接，保留外部错误文本转义，已复验。
5. 接入方式与单次原生问题/审批边界未变；员工行的等待回答/批准优先于自动修复文案。

无新增数据库迁移；恢复状态来自既有表，新增任务 recovery 字段允许 null。人工恢复、暂停账户、未知操作和验收路径继续使用原服务。
