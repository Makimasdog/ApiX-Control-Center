## 1. 结论

按 `docs/redesign/` 既定规范执行了 B1（令牌层落地）并把组件视觉收敛为一套取值：

- `web/styles/tokens.css` 成为全仓唯一的色值定义处，其余 11 个 CSS 的十六进制硬编码清零（重构前 73 处绕过令牌 + 115 处色值）。
- `web/styles/design-system.css` 从「原文件 + 三层后置覆盖」重写为单一分层文件（16 节，425 条规则），消除了同文件内反复覆盖同一属性的历史包袱。
- 修复了 6 个可验证的视觉缺陷（见 §3），其中 3 个在浅色主题下是「看不见」的问题：侧栏条目 hover、活动流连接线、顶栏分隔线。

## 7. 第三轮：思考过程与流式动效（参照 Alma 的 streaming 语言）

用户反馈"动画过于简单"，要求参照 Alma 的流式加载。实现方式与来源如下。

### 7.1 从 Alma 提取的动效原语

| Alma 选择器 | 取值 | 在 ApiX 的对应 |
| --- | --- | --- |
| `streamingCursorPulse` | 1.2s ease-in-out，opacity .4↔.9，scaleY 1↔1.05 | `apix-caret-pulse`（1.15s）：思考行光标 + 气泡末尾跟随光标 |
| `workingDotBlink` | 2s，2×2 点阵，逐点 0/.25/.5/.75s 错峰 | `apix-dot-blink`：`.thinking-dots` 2×2 点阵 |
| `shimmerTextSweep` | 2s linear，background-position -100% → 250% | `apix-text-shimmer`：思考文字高光扫过（`background-clip:text`） |
| `streamingTextReveal` | .5s cubic-bezier(.22,1,.36,1)，opacity 0→1 + translateY 4→0 | `apix-reveal`（260ms）：新消息、展开的证据块 |
| `streamingGlow` | 2.4s，box-shadow 0 → 12px 2px `--primary` | `apix-work-glow`：执行中输入框外环 |
| `--streaming-fade-duration/curve` | .5s / cubic-bezier(.22,1,.36,1) | 复用 `--dur-4` / `--ease-in` |

### 7.2 新增的界面结构

- `web/assistant.ts`：对话区新增常驻节点 `#assistant-thinking`（caret + 点阵 + 微光文字 + 计时），`setThinking(busy,status,tool)` 按会话状态切换：
  - `running` → "正在思考并调用工具"；若最后一条事件是 `tool_started`，显示"正在调用 <工具名>"
  - `waiting_agents` → "等待员工执行与验收"，并显示 2×2 点阵
  - `waiting_user` → "需要你的决定"，改用 `--warning` 且停掉全部动画（这不是"在工作"）
  - 非忙碌一律 `hidden`，另外每 1s 更新"· Ns"计时
- `#assistant-transcript[data-busy]`：忙碌时给最后一条气泡末尾加跟随光标（带 8px 主色辉光）
- 新事件入场：`renderTranscript` 记录已渲染事件 id，**只给本轮新到达的消息**加 `.is-new`。这是必要的，因为整段 transcript 每次轮询都重建 innerHTML，纯 CSS 的 `nth-last-child` 错峰会在每 1.2s 的刷新里重放，看起来像闪烁。
- `details[open] > pre/p`：展开证据块时内容淡入。
- `prefers-reduced-motion` 下：微光文字回退为纯色、光标与点阵停摆、入场动画时长归零。
