# 前端界面重构自审（2026-11-18）

自审，非独立审查、非人工验收。范围限定在 CSS 与 `web/index.html` 的导航图标，未改任何 TS 渲染逻辑、未改任何接口。

## 1. 结论

按 `docs/redesign/` 既定规范执行了 B1（令牌层落地）并把组件视觉收敛为一套取值：

- `web/styles/tokens.css` 成为全仓唯一的色值定义处，其余 11 个 CSS 的十六进制硬编码清零（重构前 73 处绕过令牌 + 115 处色值）。
- `web/styles/design-system.css` 从「原文件 + 三层后置覆盖」重写为单一分层文件（16 节，425 条规则），消除了同文件内反复覆盖同一属性的历史包袱。
- 修复了 6 个可验证的视觉缺陷（见 §3），其中 3 个在浅色主题下是「看不见」的问题：侧栏条目 hover、活动流连接线、顶栏分隔线。

## 3. 一并修掉的缺陷

| # | 缺陷 | 验证方式 |
| --- | --- | --- |
| 1 | `#page-assistant` 强制 `color-scheme:dark`，浅色主题下该页输入控件、滚动条、光标仍是深色 | 读取 `assistant.css` 规则与浏览器 `getComputedStyle(document.body).colorScheme` |
| 2 | `.assistant-welcome>span` 在浅色主题下白底白字（方块里的「ApiX」不可见） | 规则推导 + 改为 `--gradient-brand`/`--on-accent` |
| 3 | `.topbar-divider` / `.context-separator` / `.activity-item:before` 用 `var(--surface)` 作分隔线，浅色下与背景同色 | 同上，改为 `var(--border)` |
| 4 | 主按钮为警告橙（`--warning-subtle` 底 + 橙色阴影），与主色 `--accent` 不一致 | 规则推导 + 实测浏览器取值为 `rgb(154,166,255)`（深色主色） |
| 5 | 任务事件面板 `#192333`/`#141e2d` 深色硬编码，浅色主题下出现深色块 | 全局十六进制扫描为 0（仅 `tokens.css` 保留定义） |
| 6 | 活动流/顶栏字体 8–10px（`.tiny-eyebrow` 8px、`.activity-title-line strong` 10px），低于本项目 11px 下限 | 浏览器扫描「可见且在 11px 以下的文本节点」：改前 3 处，改后 0 处（`section-caption`、`badge-meta` 等为规范内的 11px） |
