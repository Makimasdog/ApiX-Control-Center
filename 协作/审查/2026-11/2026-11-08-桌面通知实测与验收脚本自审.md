## 提交范围

新增 `serve-desktop-notification-fixture.mjs`，归档 Windows 原生通知历史、成品启动报告和构建指纹，更新 Windows 桌面版说明及功能索引。原 11-06 的构建停滞记录保留，本轮补充其后完成的构建与实测结果。

夹具使用独立临时数据、本地 Git 项目、本地规划 HTTP 服务和既有 Codex 原生协议对端。派发前预置主子会话关联，后续使用真实服务产生、答复和失效处理请求。控制文件只允许简单 ID 用作快照文件名，Windows 历史来自 WinRT 通知历史接口。

## 本轮自审与验证

核对脚本的 HTTP 调用方、规划协议、项目与员工创建、派发前数据库写入、权限版本失效、控制文件 ID 校验、UTF-8 BOM 兼容及历史文件写入。脚本显式展示打包应用，供操作者完成原生点击，不在脚本中代写通过结果。证据仅含验收员工、请求元数据、原生历史与构建数据，未包含所有者令牌或个人模型配置。

自审补充了指令 ID 的字符串类型与动作白名单校验，并将启动检查改为确认实际 HTTP 就绪，避免只读到端口文件就认定成功。有效验收指令沿用实测路径。

本轮重新核对五份原生快照、成品启动报告和安装包的 SHA-256，补充两轮本地调用计数与退出清理状态。`node --check scripts/verification/serve-desktop-notification-fixture.mjs`、仓库 `npm run check` 和 `git diff --check` 均通过。自审结论为验收脚本、文档与已记录证据范围通过，未核实项按下节保留。提交前核对明确暂存清单与已审查工作区一致。该文档为自审记录。

## 未核实与限制

原生验收实例在退出过程中收到物理 Escape 桌面输入中断信号，窗口是否完成退出、后端及子进程清理均未核实。独立成品启动检查中的退出结果不能替代该原生验收实例的退出结论。本轮按用户要求不再操作桌面界面，也未执行新的退出清理。

实测覆盖本机 Windows 上的打包应用和本地协议夹具。安装器已生成，安装、升级、卸载及其他 Windows 主机不在本轮实测范围。未运行本轮全量回归或真实供应商模型能力测试。

两条已处理通知曾被用户点击，Windows 点击行为本身可能移除通知。当前记录证明处理后的历史为零，不能独立归因于提交后的应用撤回。未点击通知在处理后清除的路径尚未单独验收，第三条未点击通知的失效清除已被独立核对。
