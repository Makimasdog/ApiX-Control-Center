# Agent 主循环优化第一批自审（MCP / Skill / 请求缓存 / 循环性能 / 压缩约束 / 记忆索引）

- 日期：2026-11-19
- 性质：实现者自审（非独立审查、非人工批准）。
- 范围：`src/assistant/mcp-manager.ts`、`src/assistant/assistant-tools.ts`、`src/models/model-request.ts`、`src/assistant/assistant-loop.ts`、`src/assistant/project-memory.ts`、`src/assistant/assistant-memory.ts`、`control-plane.mjs` 的 `discoverTools` 与 `describe` 接线，以及对应测试。
- 对应方案：本会话《Agent 主循环优化方案》P0-1/2/3/5/7 与 P1-10/11。

## 改动

### 1. MCP 发现缓存（P0-1）

- `discover()` 的单服务循环体抽为内部 `discoverOne(projectId, c, signal)`（不导出，返回 `{ok, errors}`），`discover()` 与新增 `ensure()` 共用；失败清理与错误收集语义不变。
- `ensure(projectId, signal?)`：键为 `${projectId}:${serverId}:${config.version}`，值=上次成功发现的时间戳；TTL 默认 300000ms，可用 `MCP_DISCOVERY_TTL_MS` 覆盖。命中后仍要求 `apix_mcp_tools` 中该服务还有行，否则重新发现。返回结构与 `discover()` 相同。
- `save()` 按 `${projectId}:${serverId}:` 前缀清缓存；缓存 Map 超过 200 条删除最早插入项。
- `control-plane.mjs` 只把主循环的 `discoverTools` 指向 `mcp.ensure`；HTTP 手动刷新仍走 `mcp.discover`，语义不变。
- 收益方向：`search_tools` 不再每次重连所有服务（原实现每个服务 connect 10s + listTools 10s 超时）。

### 2. MCP 工具只读映射（P0-2）

- `readOnly = annotations.readOnlyHint === true`；`changesWorkspace = !readOnly`，注解缺失或非布尔一律按写。
- 版本哈希改为 `c.version + ':' + sha256(JSON.stringify([name, inputSchema, annotations ?? null]))`，前缀格式不变，`call()` 的版本校验继续成立。
- 影响：声明只读的 MCP 工具不再走审批门禁、不再置 `needs_verification`，只读项目内也可执行。

### 3. Anthropic 前缀缓存断点（P0-3）

- 稳定布局的提示词以 `\nCURRENT_STATE ` 为界：`prepareModelRequest` 用 `lastIndexOf` 求出边界，按 UTF-8 字节切成两个 text block，核心段带 `cache_control:{type:'ephemeral'}`，其余段不带。
- **边界从提示词自身推导，不依赖诊断描述符**：描述符仍是只读诊断数据，线上字节不因是否传诊断而变化（`prompt-projection` 的 wire-byte 断言因此仍成立）。
- 无该标记（例如 legacy 布局、压缩请求）时保持单条字符串；`openai-completions` / `openai-responses` 完全不受影响。
- `bodyText`、`parameterHashes`、诊断用 `prepared.prompt` 语义不变。

### 4. Skill 可发现（P0-5）

- `skillsFor()` 解析 `SKILL.md` frontmatter 的 `name` / `description` / `when`（兼容 `when_to_use`）；无描述时回退到第一条非空且不以 `#` 开头的行。
- `id` 改为目录名 slug（原为 `sha256(path)` 前 16 位，项目挪动即失效）；按 `.apix/skills` > `.claude/skills` > `.agents/skills` > `~/.apix/skills` 扫描并按 id 去重，先出现者优先。
- `load_skill` 支持按 id 或 name 查找；`authority:'context_only'` 与 16000 字节加载上限不变。
- `describe` 最多透出 20 条 `{id,name,description,when}`。
- 元数据按 `(mtime, size)` 缓存（上限 200 条，单文件 >64KiB 跳过），因为 `describe` 每步都会调用，避免每步重新读取整份技能文件。

### 5. 工具改动文件增量扫描（P0-7）

- 原实现每次工具调用都全表扫描本会话 `tool_result` 并 `JSON.parse` 全部 body，只为计算 `scopeVersion` 的 changedFiles。
- 改为按会话缓存 `{upto, files}`：先取 `MAX(id)` 作 watermark，只扫描 `id > upto AND id <= watermark` 的区间，再更新 upto；返回浅拷贝，调用方改不到缓存。Map 上限 64 条。
- 安全前提写在注释里：`assistant_events.id` 单调递增且事件不会被删除（归档/删除只改 `assistant_sessions` 行）。

### 6. 压缩保留硬约束（P1-11）

- 压缩摘要改为 `{"summary","constraints"}`；`constraints` 缺失时行为与旧格式完全一致。
- 存储格式：有约束时 `【硬约束】\n- …\n\n【工作摘要】\n…`，无约束时保持纯文本。
- `mergeConstraints`：字符串数组、trim、去空、去重、单条 ≤160 字、最多 8 条、逐条过 `sensitiveMemory`，与 `payload.constraints` 里带去的旧约束取并集（旧在前）。
- 组装后总长超过 8000 字符时截断摘要正文，保留约束段完整。
- 由于 `summary` 位于 CHECKPOINT（稳定核心的一部分），硬约束天然跨压缩、跨重启保留，无需新增事件类型或表结构。

### 7. 记忆索引预算化与近因召回（P1-10）

- `memoryIndex(notes, budgetBytes=5000)`：用户/反馈类固定记忆优先，其余按 `updated_at` 倒序填充；仍在 200 行或预算处停止。原 25KB 上限（约 8k token）收敛到约 1.7k token。
- `context()`：assistant 变为 pinned（≤20）+ recalled + 其余按时间倒序，再交给 `memoryIndex`；worker 分支保持原有可见范围，不因预算化扩大权限面；usage 记录按实际入选条目还原。
- `recallNotes`：只对已有匹配的笔记加近因分（7 天 +2、30 天 +1），避免无关但较新的笔记被召回。返回结构、5 条上限、6000 字符预算不变。
- 未引入 FTS5、未新增表：向量/BM25 召回留待实测证明 bigram 不足后再做。

## 已知限制 / 未验证

- 未调用真实 Anthropic 服务核对缓存命中与计费；只验证了请求体结构与字节边界。
- MCP `annotations` 由服务端声明。若服务端谎报 `readOnlyHint:true`，宿主会按只读处理（不置 `needs_verification`）。这是对 MCP 注解的信任边界：启用服务本身已要求所有者明确批准，且服务进程本就具备本机权限，因此本次只影响审批与记账，不新增能力面。
- frontmatter 解析为最小实现，不支持多行 YAML（`|` / `>`）。
- 压缩摘要的 `【硬约束】` 段依赖模型按要求产出 `constraints`；模型返回非法值时会丢弃该条而不是截断。
- 记忆召回仍是 bigram + 近因，未做语义召回；索引预算 5000 字节是经验值，未做跨项目压测。
- 未运行浏览器/UI 回归与真实模型端到端；`dist` 刷新后未重启长期运行的本地实例。
