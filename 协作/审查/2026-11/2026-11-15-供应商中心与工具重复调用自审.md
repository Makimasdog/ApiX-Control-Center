# 供应商中心与工具重复调用自审

## 修改范围

- 供应商中心用可搜索列表显示域名、模型、密钥保存状态和实际绑定。添加入口单独展示本机 Codex 登录、模型 API 预设和自定义通道。历史通用名称按域名显示，凭据值保存在原有本地存储。
- ApiX 旧对话的初始模型配置和明确恢复默认后的配置都跟随应用默认值。手动选择过模型的对话保留自己的通道。前端在应用默认配置变化后刷新当前选择。单纯给供应商改名或重复绑定原通道时保留员工的预算账户和费率。
- `list_files` 省略路径与显式 `.` 共用进展记录。可信验收结果的运行编号和时间变化不计为进展。项目指纹、检查结论、分页和授权变化仍按真实结果计算。
- 将“下一任务：”迁移到主对话输入框，消息收据和任务切换在同一事务内保存。协作异常的“交给 ApiX 处理”由服务端校验当前项目授权、指定任务和运行记录，只允许未生成工作区、无既往运行的失败任务走该快捷入口。恢复失败直接显示原因。

## 验证与结论

- 构建、静态检查和 Git 差异检查通过。供应商、对话模型、主循环、工具治理与员工恢复共 121 项定向测试通过。
- Chromium 验证供应商目录、列表搜索、密钥保护、协议兼容、员工绑定、已有对话跟随新默认模型，以及桌面和窄屏布局。截图位于 `.tmp/verification/providers/`。
- 浏览器任务流、协作导航和项目交付回归通过。已验证主对话开启独立任务、新任务净差异、旧验收历史、离线 npm 检查，以及同一协作异常选择稍后处理后保持关闭。交付夹具失败时读取原始异常，避免一直等待页面出现交付结果。
- 自审核对了模型切换的版本冲突、凭据地址变更、重复员工绑定、任务事务回滚、恢复失败和已有运行边界。本轮用本地测试服务复测，尚未用真实供应商和真实 CLI 复跑，历史项目的具体失败记录未触发恢复。已有 4173 实例的重启命令被自动执行策略拦截。
