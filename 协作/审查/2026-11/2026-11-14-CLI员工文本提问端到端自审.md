# CLI 员工文本提问端到端自审

2026-11-14 · Codex 本地自审 · `codex/external-agent-workbench`

普通 CLI 的标准输入在任务启动后关闭（Pi 使用已有 RPC 生命周期），所以使用运行中的任务信箱传递文本问题和答复。运行令牌确定项目、任务和进程；CLI 采用启动说明发送 `worker_question` 请求，并用信箱返回的 ID 关联和确认收到 `worker_question_answer`。原生结构化问题与审批继续使用原协议。

ApiX 对已授权任务复用此前的证据核查，可引用原始需求、冻结需求、项目约定和现有已批检查。重复发问用原消息幂等键去重。消息与问题登记、消息与答复登记、确认收到与投递状态分别在同一 SQLite 保存点写入。答复只发给发问运行；只有该员工先领取并确认后才记为接收。无证据的题保留在主对话待办和协作页。CLI 提问后未确认答复便自行退出时，即使退出码为零也记为阻塞，不触发验收。

本地端到端用 HTTP 模型替身、普通 Codex CLI 协议替身、生产服务、临时 Git 项目和真实 Node 检查：重复提交一个换行问题只登记一次，ApiX 基于 README 代答，员工确认后写文件，员工交付与集成交付均被实际检查并冻结。计费选项需人工回答，回执后继续并验收。提前退出不会触发检查或冻结。另验证原生员工流程、已授权派工、答复证据限制和现有原生回执。

功能依赖 CLI 员工遵循任务信箱提示；不会将任意 stdout 问句当成请求。未验证真实供应商、真实 CLI 模型遵循提示的表现或外部平台。未提交、推送或合并。

最终构建、静态检查和 diff 检查通过；3 项协作端到端回归、22 项模型和运行时回归及 Edge 员工工作台复测通过。确认用户实例没有运行中的任务后已重启，4173 返回 HTTP 200。
