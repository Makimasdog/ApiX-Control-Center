# Windows 安装、升级和卸载隔离验收自审

## 范围

Codex 自审。使用 Windows x64、Electron 45.0.0 和 electron-builder 26.15.3，按仓库的 NSIS 配置构建两份当前用户安装包。旧包来自 `8b754ef`，新包来自 `3716ec5`。两份包的测试版本分别为 `0.3.2` 和 `0.3.3`，使用同一套随机应用标识、注册表键和快捷方式。`0.3.3` 是验收版本号，仓库发布版本未调整。

本机没有可用的 Windows Sandbox，VirtualBox 管理接口也无法初始化。验收因此使用同一主机上的独立应用标识、安装目录、数据目录和进程环境。待验应用只使用测试数据和本地后端。正式桌面版、开发版数据库和配置以及正式安装的注册表与快捷方式进行前后指纹比对，日志和提交中只记录比对结果。

## 问题追踪

首次运行在旧包解压阶段触发 `spawnSync ETIMEDOUT`。安装进程持续占用 CPU，目标目录已有解包文件，NSIS 尚未写入安装登记，现有数据指纹未变化。原因是验收脚本通用的 180 秒超时对本机解包过短。安装进程的等待上限单独调为 600 秒。复验复用两份 SHA-256 一致的测试安装包，在新的空目录重新安装。

旧版安装成功后，冒烟项目收到 `/npm-proposal` HTTP 400。该项目将 `npm test` 直接指向 `src/value.cjs`，而测试的可修改范围包含 `src`。验收契约按预期拒绝允许修改受信任脚本。将入口移到 `test/check.cjs` 后，用已安装的旧版和新建数据库通过项目、会话与启动检查。

electron-builder 的 NSIS 模板在安装阶段将安装器复制为 `%LOCALAPPDATA%\<应用标识>-updater\installer.exe`。新增卸载钩子直接使用构建器提供的 `APP_INSTALLER_STORE_FILE`，仅在正常卸载时删除该文件并尝试移除空的缓存目录。原位升级触发的旧版卸载保留缓存，由新版安装覆盖。应用数据继续由 `deleteAppDataOnUninstall: false` 保留。

旧版到新版的原位升级通过。新版首次启动前，数据库及配置文件的指纹与旧版退出后一致。新版启动后，SQLite 完整性检查通过，项目与会话记录一致。原版卸载器的后台清理超过脚本最初的 30 秒等待。后续复查确认安装目录和登记已删除，仍存在与 `0.3.3` 安装器 SHA-256 一致的 354,320,282 字节缓存文件。验收脚本将后台清理等待调整为 180 秒。

`npm run test:desktop` 的 7 项桌面进程回归通过。`npm run check` 通过。测试全程未发起付费模型调用。

## 修复复验

- 使用 `3716ec5` 与本次安装器配置、卸载钩子构建测试版 `0.3.4`。正常安装后，缓存副本与测试安装包的 SHA-256 一致。重装前后，隔离数据库和配置文件的指纹一致。应用启动后读取原有项目与会话，SQLite 完整性检查通过。
- 修复后的卸载移除了程序目录、当前用户登记、桌面和开始菜单快捷方式及缓存安装器。缓存目录中的独立测试文件、隔离数据目录里的数据库和配置、Roaming 默认目录中的哨兵文件均保留。现有桌面版与开发版受检数据和正式安装记录的前后指纹一致。验收后移除测试哨兵与空的测试缓存目录。
- 新增可重复运行的 `npm run test:desktop:installer`，从已提交源码构建两个版本。本轮通过分段实跑验证原位升级和补丁卸载，保留各次尝试的结果。[验收数据](../../验收数据/2026-11-05-desktop-installer/result.json)

## 验收边界

Windows x64 同一主机上的当前用户静默安装。正式包的应用标识、交互向导、全用户安装、签名和自动更新未验证。安装包和排查日志留在 `.tmp/installer-verification/`。首次超时留下的解包目录也留在该临时区，自动审批拦截了递归清理命令。
