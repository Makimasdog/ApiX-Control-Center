## 真实管理模型与 Codex CLI

使用临时 Git 仓库、真实 OpenDesign 管理模型和已登录的普通 Codex CLI。只授权本次项目和宿主 Node 验收命令。测试文件 `a.txt` 的完整内容应为 `APX-OPEN-READY` 后加一个 LF。

- 员工必须从任务信箱发问、收到 ApiX 答复并确认，再继续执行。ApiX 根据项目 README 给出 LF。涉及关键业务选择时仍转交用户，分段实测与自动化回归均覆盖此路径。
- 真实测试发现退出检测会把员工完成报告引用的历史问句识别成仍待答复。改为优先读取 Codex 最后一条员工消息，忽略成对引号内的引用。仍可接管员工在终端留下的实际问句，原有信箱回执和运行失败规则继续生效。
- 模块自审最初缺少员工问答证据。现从宿主保存的问答和已确认回执提取本轮记录，集成自审还可读取同一计划内已验收且冻结的直接前置任务记录。内容脱敏后作为不可信材料随宿主证据送审。证据可核对询问、答复及回执，文件写入时间需由独立证据确认。
- 集成自审最初只收到增量差异和宿主命令输出。单模块交付被继承后，集成任务可无新增修改。修复交付检查的参数转发后，自审会从现有只读检查线程读取冻结契约限定路径的当前文件。公开交付查询仍使用默认摘要。定向 HTTP 回归已确认模块和集成自审均收到 `a.txt` 正文与 LF 回执，宿主命令和模型自审都通过才可冻结交付。

11 月 15 日端到端复测通过。活动流按时间记录了员工提问和 ApiX 的 LF 答复，任务在员工确认答复后继续。模块与集成的宿主字节检查均通过，自审接受两项交付，流程状态为 `completed`，两项任务均有冻结提交。员工提问后全程无需手动答复或验收。实调日志位于 `.tmp/opendesign-real-workflow-final.log`。
