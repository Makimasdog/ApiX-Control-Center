Claude Code 经 CC Switch 路由 DeepSeek 是用户确认的预期配置，不作为模型映射缺陷。本轮测试使用隔离数据、协议夹具、真实本地进程、浏览器及桌面包；真实 CLI 探针只做握手，不发送用户消息。Claude 探针使用独立配置目录、占位凭据、回环地址并关闭非必要流量，未调用 CC Switch 的付费推理路由。没有重跑上一轮的真实模型协作、语义裁判或账单接口。

## 首次 Claude unknown 追踪

原始报告仍保留在 11-03 预检目录：握手成功，根进程在停止前尚未退出，stopMs=470，最终 exitCode=1、signal=null、stopEvidence=unknown。不能仅凭 exitCode=1 判停止失败或成功；强制停止成功的本轮样本也出现此退出码。

结合当时 stopRuntimeTree 源码：Win32 下要求 taskkill /T /F 成功且根进程 close 已观察到才返回 quiescent；未观察到 close 会等 6000ms。原始 470ms 记录因此可归到“进程树终止未获确认”分支。原报告没有 taskkill 错误码或 stderr，无法进一步证明是哪个 Windows 系统错误、某个后代先退出、还是其他命令执行失败；不将这些可能性当作已确认根因。

本轮做了 8 次独立 Claude 零推理诊断：4 次调用原生产 stopRuntimeTree，全部 quiescent；4 次直接观察 Windows taskkill，退出码全部 0，均看到根 exit/close。随后新兼容性探针对 Codex 和 Claude 都得到 tree_stopped / quiescent。未复现原未知，原记录不覆盖。

修复的是诊断缺口：共用停止 helper 增加可选结构化诊断，两个原生适配器将其保存为 runtime.stop，探针写 stopDiagnostic。字段区分 root_unavailable、root_already_exited、tree_stop_failed、root_close_timeout、tree_stopped，并保存 treeStopConfirmed、rootClosed、errorCode。不记录终止命令输出、凭据或原生会话标识；不重试杀进程、不放宽停止/恢复/交付判定。测试覆盖真实进程树停止、根已退出仍 unknown、适配器诊断事件及公开 HTTP 事件。

证据见[停止追踪](../../验收数据/2026-11-04-free-regression/claude-stop-investigation.json)、[真实零回合兼容性](../../验收数据/2026-11-04-free-regression/compatibility.json)。当前 Codex 版本为 0.166.0-alpha.6，Claude Code 2.1.114 / SDK 0.3.314；免费握手通过不替代新版本真实模型能力验收。
