# Agent 设计层加固自审

更新：2026-11-18。分支 `feature/structural-hardening`。未推送、未合并。

## 范围

本轮修三件事：**事件写放大**、**零改动即完成的缺口**、**工具契约不一致**。
都是 Agent 设计层的问题，不是数据层。

## 一、事件写放大（`565ce8a`）

### 实测到的规模

用真实 SQLite 造一次典型运行（4 个任务 + 50 条运行时事件 + 一份 20KB 交付）：

| 项 | 行数 | 字节 |
|---|---|---|
| `events` | 50 | 1,990 |
| `apix_ledger` | 151 | **4,030,925** |
| ├ `runtime.*` | 100 | 4,730 |
| └ `coordination.snapshot` | 50 | **4,006,150** |
| `artifacts` | 1 | 20,000 |
| `shared_artifacts` | 1 | 20,000 |
| `tasks.result` | 1 | 20,000 |

**快照占了 99%**。原因：`recordTask` 对每条运行时事件都写一份「整份会话 + 全部任务」，而 `turn.started` / `usage.updated` / `message.delivery` 这类事件根本不改变会话投影。

### 改动

1. **checkpoint 按投影签名去重**。签名只覆盖影响回放的字段（状态、归属、队列原因、验证状态、交付 commit、结果内容），时间戳不算状态变化。状态真变时仍写快照，回放精度不受影响。签名缓存上限 500 条，防止长期运行无限增长。
2. **快照里的任务 result 截到 2000 字符**，标注 `resultTruncated` / `resultBytes`；完整内容仍在 `tasks.result` 与 `artifacts`。
3. **`artifact.collected` 账本事件改为引用 + 有界摘要**（artifactId / digest / contentBytes / 2000 字 excerpt），不再复制全文。此前同一份输出写四处：`tasks.result` / `artifacts` / `apix_ledger` / `shared_artifacts`。

**实测后：同样 50 条事件，快照从 50 份 / 4MB 降为 1 份 / 318 字节。**

保留 `shared_artifacts` 的全文：它是下游依赖任务实际读取的交接物，删掉会破坏交付链。

## 二、零改动即完成的缺口（`a00e68a`）

### 问题

`observe()` 在三种情况下都返回 `{changes: []}`：
- 没有当前任务
- 没有项目根
- 没有任务基线

这与「观察了，确实没有改动」**返回值完全相同**。于是基线扫描受限时（`task_baseline_limited`），完成路径会走"零改动"分支直接标 `completed`——模型只要声称完成，即使什么都没做也能通过。

### 改动

- `observe()` 明确返回 `observed: false/true`。这是行为契约的变化：「没有观察」与「观察后没有变化」不再共用同一个返回值。
- 完成路径新增判定：存在项目根与当前交付任务、却拿不到基线时，记录 `completion_unobserved` 并要求核对；不再视为已确认的空改动。

### 关于「误伤普通问答」

我此前担心加严会误伤项目内的普通问答，所以先做了区分实验：**有基线且确实没改动时，普通问答仍然正常 `completed`**（见 `test/assistant-completion-evidence.test.mjs` 第二项）。加严只作用于"无法核对"这一个分支，不影响"核对过确实没改"。

同时验证了另一条边界：有改动但没验证时仍被拦下，且不会误报 `completion_unobserved`——三种状态互不混淆。

## 三、工具契约不一致（`d197c48`）

### 修的两处

1. **`write_file` 没有 `expectedSha256`**。`edit_file` 早就强制该参数，`write_file` 却会直接覆盖任何文件——包括用户在模型读取之后手动改过的内容，且没有任何提示。现在支持可选的 `expectedSha256`：传了就必须匹配，否则在写盘前拒绝。检查放在 `PreflightError` 之前完成，不会留下"已记录意图但没写"的中间态。新建文件仍可省略。
2. **`delegate` 的描述不实**。描述写「冻结模块契约后委派」，但 schema 只有 `goal` + `requirements`，没有任何契约入参——描述在暗示一个不存在的参数。改为如实说明流程。

### 新增守卫

`test/tool-dispatch.test.mjs`（5 项）：
- 每个内置工具都能在两处分发（`assistant-loop` / `control-plane`）找到处理位置，防止"已声明未实现"只在运行时暴露成「工具不存在」；
- 工具名不重复、只读工具不声明改工作区；
- `write_file` 支持 `expectedSha256`；
- `delegate` 描述不得承诺不存在的字段。

`test/write-file-conflict.test.mjs`（4 项）：sha 不匹配拒绝覆盖且文件不变、匹配时正常覆盖、新建文件不需要 sha、对不存在的文件传 sha 也拒绝。

## 没做

- **MCP 幂等缺陷**：`host_metadata` 指纹被常量化，同一 turn 内第二次完全相同的 MCP 调用会被"复用"而不执行；反之 MCP 首次失败不会写入完成，同 turn 重试直接抛「结果尚未确认」。**但仓库有测试明确断言这个复用行为**（`assistant-loop.test.mjs:431`），说明它是设计意图而非疏漏。改它属于改变产品语义，本轮不动。
- **压缩摘要的间接注入**：摘要是模型从含不可信工具输出的历史生成的，压缩后直接进上下文。风险存在但改动落在提示词层，没法用确定性测试证明有效，本轮不动。
- **工具分发单一真源（结构性收敛）**：本轮只加了覆盖守卫，没有把两处分发重构成一张表。重构会动 `assistant-loop` 的主分发链，风险高于收益。

## 边界

- 写放大是实测数字（真实 SQLite，非估算）；性能收益未做端到端压测。
- 未运行 `test:ui:*` 与真实模型批次。
- 这是自审，不是独立审查或人工验收。
