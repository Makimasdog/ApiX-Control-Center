# 账本事务与投影自审

## SQLite 写入边界

| 调用 | 本次核对的同事务数据 |
|---|---|
| `createSession` | 会话、对话轮次和账本快照 |
| `confirmSession` | 计划、步骤、待审批项和 `plan.created`。模型推理结束后才开启写事务 |
| `dispatchSession` | 授权、审批、会话状态和派发证据。提交后推进任务 |
| `instructEmployee` | 信箱消息、消息事件、人工指导或熔断提醒 |
| `recordTask` | 任务事件、所属会话的镜像事件及快照。用保存点加入调用者的事务 |
| `authorizeRetry` | 员工绑定、执行授权、待处理审批、任务状态及交互证据 |

任务执行入口还给启动准备、停止、验收、调度失败、结果兜底和服务重启补记了状态证据。事务只涵盖同步数据库操作。员工进程启动、停止、模型推理及检查仍在事务之外。

回归使用真实 SQLite 触发器注入账本写入失败，核对相关行随事务回滚。故障注入覆盖上表六个调用，以及指导熔断、保留监督拦截记录、嵌套保存点、独立对话轮次和取消快照。

## 投影校验

`npm run verify:ledger -- --db <SQLite 路径> --json` 在一个只读事务中读取账本及当前表。会话和任务从账本快照及其后的事件恢复，计划创建证据和创建时快照共同确定计划及依赖关系。报告列出参与比较的字段和排除项。`--strict` 把证据不足与存在差异都作为失败。

使用真实服务和隔离合成数据库跑完协作任务，覆盖计划替换、任务取消与实际员工运行。比较结果为零差异。后续注入无快照历史数据、状态和结果差异、缺失行，校验器均给出相应判定。历史库缺少快照或增量事件的部分依赖现有证据，个人助手及普通对话任务也可能落在覆盖范围外。此校验仍读取状态表作对照，覆盖范围以报告为准。生产库验证未执行。

在此分支上，`npm run check` 通过。账本、投影、消息、自治、恢复和追溯的定向回归共 55 项通过。
