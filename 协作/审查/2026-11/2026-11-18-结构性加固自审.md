# 结构性加固（P1：数据层、上下文预算、终态语义）自审

更新：2026-11-18。分支 `feature/structural-hardening`，基于 `feature/agent-collaboration-hardening`。本轮未推送、未合并。

## 起点

进入本轮前工作区已有大量未提交改动（前端画布改版、供应商中心、协作动态、Run 终态加固等）。为让本轮改动可独立审查和回滚，先把它整体记录为基线提交 `1abef2b`，再从基线往上做。

## 做了什么

### 1. 索引与预编译语句缓存（`d9418a1`）

`schema_migrations` 版本 14，为 `events`/`artifacts`/`tasks`/`runs`/`shared_artifacts` 补 11 个索引。这几张表承担每次快照、恢复和任务详情的主查询，此前一个索引都没有（全仓 17 个索引全在消息/协调表）。

`row`/`rows` 改为走 800 条上限的预编译语句缓存，避免每次调用重新解析 SQL。纯加法，不改任何查询语义。

### 2. 快照按域设上限（`8d06625`）

`snapshot()` 里 `artifacts`、`sharedArtifacts`、`directorMessages` 原本无 LIMIT，`tasks` 还带 result 全文。前端 1.5 秒拉一次全量、在主线程序列化，和 Agent 进程管理共享事件循环。

现在分别是 200 / 200 / 500 条，字段结构不变。完整内容仍可通过任务详情和交付详情按 id 读取。

### 3. 信箱终态语义（`053bc35`）

- `completeMessage` 对 `expired` 报错，不再静默返回成功。此前员工会收到 2xx，但宿主从未写入 `message.completed`。
- `ackMessage` 续租：`expires_at` 从领取时刻按 `timeout_ms` 重新起算，长任务不会在处理途中被判过期。

新增 `test/mailbox-terminal.test.mjs`（3 项，真实 SQLite 内存库）。

### 4. 员工上下文按优先级分配预算（`a4ca4a2`）

`workerPrompt` 支持 `{text, priority:'required'|'normal'}`。必需资料先占至多 60% 剩余预算，普通资料再分剩下的；纯字符串保持原等权语义。返回值新增 `requiredTruncated` 与 `pressure`。

`control-plane.mjs` 把项目档案、项目记忆、项目规则标为 required；模型生成的前置交付物移到必需资料之后，仍可截断。需求 brief 与信箱协议不再借道 references（原先用 `context.shift()` 取回，结构脆弱），直接进 approvedContext。

`context.truncated` 事件补充 `requiredTruncated` 与 `mandatoryRatio`，强制指令超过 70% 时即使没有截断也记录。

新增 `test/worker-context.test.mjs`（4 项）。

### 5. 服务进程未捕获错误兜底（`9092c1a`）

`server.mjs` 此前没有 `unhandledRejection` / `uncaughtException` 处理。现在：拒绝只记录并继续服务；未捕获异常记录后复用既有优雅退出流程（此时进程状态已不可信，重启会把未完成的 Run 按 unknown 收口）。

### 6. Schema 漂移守卫（`49ab312`）

新增 `test/schema-consistency.test.mjs`：

- 同名表的多处声明列集合必须一致（括号配对解析，只比列名+类型）；
- 迁移版本必须从 1 连续，不跳号；
- 迁移 14 的核心索引必须存在。

这是守卫，不是收敛。把 107 张表的 DDL 集中到单一文件是更大的改造，本轮不做。

### 7. 主循环记账（`81e5865`）

- `SESSION_CHANGED` 的 `continue` 发生在 `steps++` 之前，理论上可无界空转；连续 3 次即停止。
- 格式修复分支硬编码 `fresh.steps>=24`，改用配置的 `maxCalls`。

### 8. 其它（`b6d13c6`, `f1383a8`）

`.archify/` 加入 `.gitignore`；`parallelScope` 的告警去重集合加上限。

## 没做（明确取舍）

- **Schema 单一真源**：把 107 张表收敛到一个迁移文件、用 `PRAGMA user_version` 驱动，是 2–3 天的改造，且要同步替换 30 个测试文件里手抄的 DDL。本轮只加守卫。
- **零改动即完成的缺口**：`assistant-loop.ts:575` 在 `observe()` 无变更时不置 `needs_verification`，于是「什么都没做但声称完成」可以过。修它需要区分「回答问题」和「声称改了代码」，属于产品语义决策；贸然加严会误伤项目内的普通问答。留给后续单独立项。
- **事件写放大**：`recordOutput` 仍把同一份 output 写进 tasks.result、artifacts、apix_ledger、shared_artifacts 四处；`recordTask` 仍对每个事件写全量快照。改动会波及读模型，未在本轮动。
- **工具分发单一真源 / `write_file` 缺 expectedSha256**：会改变工具契约，未动。
- **运行中预算硬阈值**：目前仍是启动前预留，不是运行中硬停，未动。

## 边界
