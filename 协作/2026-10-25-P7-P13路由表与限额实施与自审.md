## 1. 变更内容

- **新增 `src/infrastructure/api-routes.mjs`（173 行）**：全部 API 路由改为表驱动——每条一行声明 `{method, pattern, limit, legacy?, raw?, handler}`；处理器收到统一 `ctx={req,res,m,query,body,send}`。SSE 事件流、协作流式对话、snapshot ETag 三个自写响应端点标 `raw:true` 留在表内。`requiredProject` 与三类限额常量从此导出。
- **`server.mjs` 450 → 164 行**：只保留执行管线（Host/Origin 校验 → 所有者门禁 → 员工通道 → 知识/工具域 → 路由表分发）、静态文件区与优雅退出。`readBody`（P5 排空语义）与 `send` 提升为管线内单一实现。
- **404/405 语义修正（P7.3）**：路径未注册一律 404（GET 也不例外，旧行为是落入 POST 门禁误报 405）；方法不匹配才 405；`legacy:true` 路由未设 `APIX_LEGACY_API=1` 时 409，且校验顺序保持「413 先于 409」。
- **限额分类（P13）**：对话消息类 256KB 字节（messages/reply/compact/tasks/delivery-review/coordination 问答与指导/director messages）；配置类 64KB 字节（供应商/权限/模型设置/工作流/排班/packs/记忆设置等）；知识上传 1.5MB 字节（原有）；其余默认 30000 字符（原有语义）；owner/login 1000 字符、员工通道 30000 字符不变。
- **测试**：`test/tool-knowledge.test.mjs` 排水测试新增断言：250KB reply 非 413 / 280KB 413；60KB 配置非 413 / 70KB 413；GET 未注册路径 404；`GET /api/projects`（仅 POST 路由）405。
- **文档**：README「配置指南」新增「请求体限额」小节；`docs/INDEX.md` 流式对话行的限制描述同步更新。

## 2. 审查结论

- **逐路由核对**：GET 39 条、POST 76 条（含 3 条 raw、12 条 legacy）自旧 if/else 链逐条搬迁；`/api/messages/thread` 保持在 `/api/messages/([^/]+)` 之前（表序即匹配序）。全量 486 项测试（含 agent-os 全 UI 流、messaging、coordinator SSE、delivery、npm-http）通过是搬迁完整性的主要证据。
- **行为变化点（均为本方案预期）**：① GET/PUT 未注册 API 路径从 405 改为 404；② 未知的 `/api/director/*` POST 从 409（旧前缀门禁）改为 404；③ 消息/配置类路由限额按新类目放宽/收紧。除③外无测试依赖旧行为（grep 确认）。
- **错误路径**：统一 catch 出口未动（SQLITE/TypeError→500、ToolError→自带状态码、其余 400）；员工通道与知识域的结构化 ToolError 语义原样保留在管线内的两段特判中。
- **安全边界**：Host/Origin/所有者门禁顺序不变；知识域凭据文件拒传、audit 405 守卫等断言全部通过。
- **管线顺序**：content-type 405 → 读体（413）→ legacy 409 → handler，与旧链「405 → 413 → 409 → 分发」一致。
