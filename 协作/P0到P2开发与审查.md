## 批次一：消息隔离与确认

- 数据库版本 10 增加目标任务、目标运行、来源运行和运行领取时间，不删除历史消息。
- 运行凭据校验运行及任务身份；POST 读取请求体后重新认证，避免任务结束后的旧请求仍生效。
- 凭据接口只领取当前 task/run 的消息，无法确认或回复其他任务消息；任务结束后凭据失效。
- 同事交接须指定同计划正在运行的目标任务，来源与目标运行由服务端决定；团队接口只列当前计划的运行任务。
- 幂等键按来源运行隔离，避免同员工并行或重试时误用旧消息。
- 页面展示“待接收 / 已送达待确认 / 员工已确认接收 / 员工已报告处理 / 失败与超时”。“已报告处理”不等于验证已采纳。
- 通用 CLI 默认不声明实时消息支持；自定义适配器可显式声明 mailbox=true。实际领取证据独立记录，不根据声明伪造确认。
- 可执行文件探测缓存 10 秒，显式扫描会清缓存；文件消失时不继续使用旧命令。抑制缺失可选程序的重复终端输出。

审查：自审。检查消息接收、回复、幂等、项目与计划边界、任务结束、请求体等待期间凭据变化、迁移历史保留，以及页面输出转义。非法/标量消息载荷规范化后显示，避免页面异常。

check/build 通过；完整回归 57/57 通过（约 112 秒）。最后补充同计划团队任务列表及标量载荷保护后，相关三个 HTTP 测试再次全部通过。实际浏览器将在最终执行界面完成后统一验收；本批不宣称真实 CLI 或模型已联调。

自审通过。后续批次仍须完成，不以本批完成替代全部 P0–P2。

## 批次二：冻结交付与代码交接

- 数据库版本 11 记录工作区输入版本、冻结交付和交接报告。验收采用独立临时 Git index 捕获已暂存、未暂存、删除和未跟踪的非忽略文件，保留原工作区 HEAD/index；生成 Git commit-tree 对象并保存在 refs/apix/deliveries 下。
- 页面按需提供代码差异、文件列表、输入版本及交接报告，用户看过差异后可在面板验收；验收携带内容指纹，工作区变化时拒绝旧指纹。预览最多 12,000 字符并提示截断。
- 后续 coordinator/collaboration 任务遍历已验收的依赖，应用各任务自身相对其输入版本的冻结补丁，避免把整个累积差异重复集成。只修改 ApiX 托管工作区，不自动修改源仓库。
- 路径、Git common-dir 与 worktree 登记均核对。历史工作区可在验证源仓库与登记后补齐 common-dir；历史已验收交付由用户查看差异并显式冻结，不自动认定当前文件为旧验收内容。
- 冲突保留工作区、文件和错误报告，消费者标为 blocked，Run 无 PID，后续依赖不启动。跨仓库代码变更和不同基线默认阻塞，需在对应仓库集成并重新审查。
- 最终集成使用冻结的任务自身补丁。准备时记录集成补丁 digest，应用前重新核对；审查后改动集成内容必须重审，旧版未记录 digest 的集成需重新准备。

自审发现并修复：只枚举 ls-files --modified 会漏掉“已暂存且工作区与 index 一致”的改动，因此同时纳入相对 HEAD 的 staged 差异；临时 index 避免覆盖员工自己的暂存区。检查了工作区冒用、冻结内容与活文件分离、指纹过期、依赖闭包、冲突保留、消费前阻塞、集成内容变化与页面目标切换。

- 批准后按已验收依赖、项目暂停、运行时暂停和并发逐一准入；进程结束或用户变更设置后释放/重新调度，不重复启动。额度/速率限制在调度下一项前暂停对应项目/运行时，须用户明确恢复；普通错误不误当作剩余次数或额度。
- 恢复检查包含最新 Run、PID 线索、是否仍由当前服务托管、完整 Git 指纹和工作区路径。用户检查后重新批准，unknown 还需确认原进程停止。需求/计划变更、权限失效、未验收依赖、原进程仍托管或检查后内容变化均拒绝。
- 可重新分配给当前可用且非只读的员工，创建绑定新员工的授权与新 Run；保留工作区部分成果，不重放旧凭据或旧指导。用户在工作区解决并暂存交接冲突后，可检查并明确批准该解决版本；未知 PID 不自动杀死，也不自动重新连接。
- 目标工作台显示排队原因、最近保存的运行报告、指导真实状态、代码版本、工作区路径和恢复操作。根任务没有依赖交接时显示“工作区就绪”。排队目标显示“排队中”，任务 completed 显示“待验收”，全部 accepted 才显示“已验收”。
- 目标列表 summary=1 省略历史与完整任务，只读取选中目标详情；完整接口保留兼容。快照按 SQLite 变化、重启标记和 10 秒运行时检查周期生成 ETag，无变化返回 304，省去全表查询与全量传输；刷新互斥，避免事件与轮询重叠。没有删除历史，也没有宣称已实现超大数据分页。

### 使用边界

PID 探测只能提供线索，可能复用；unknown 由用户确认原进程停止。额度识别覆盖明确错误码/文本，不读余额、不全局管理多个项目共用账户，未知第三方形式按普通失败处理。暂停和降低并发不停止现有任务。真实 CLI/模型、复杂子模块、超大历史压力与恶意本机程序隔离未验证；当前本地管理 API 仍信任本机用户。无需为上述边界启动真实 Claude。
