# 自主交付四阶段开发计划

日期：2026-10-13。用户要求开发架构契约、自动质量闭环、难度成本路由、持续监督与动态重规划，并管理文档和 Git/GitHub。本轮由 Codex 实施前后端并自审，不启动子 Agent。

基线：`codex/readiness-p0-p2` / `4f35e21`。保留用户已有 `.gitignore` 和未跟踪资料，不切换分支。审查通过后按明确文件清单本地提交；GitHub 同步需以最终交付内容确定，不自动合并。

## 实施范围

1. 项目可选择自主交付策略。需求确认后先生成并校验模块边界、接口、数据结构、验收检查及风险，保存契约版本；实现任务必须绑定模块并读取同一冻结契约。最终集成任务接收所有模块代码。
2. 宿主运行已授权的检查命令，记录退出码、输出、工作区版本，ApiX 根据实际差异和测试证据审查。失败产生持久化修复任务记录，保留工作区并重新派发，达到上限则停下。模型自称成功和员工报告不能独自通过验收。
3. 将难度与工作量分开；已声明的推理能力为质量门槛，模型版本对应的人工费率用于估算并解释路由。估算不等于批准费用上界，不改变现有预算准入。
4. 按风险周期请求进度、处理阻塞与超时；结束已知运行后在原范围内重新派发或换员工。未知进程、冲突、权限和预算问题保留人工恢复门槛。新范围仍须重新确认需求。

## 验证与提交门槛

覆盖契约缺失/失效、跨模块规范、难度与成本独立排序、真实检查失败后的修复与重验、最终集成、超时/停止/撤权/重启、指纹变化与并发去重。使用已有 Node 24.19.0；假 CLI 回归与真实模型验收分别说明。最终 diff 自审、静态检查、完整回归、文档同步和暂存内容核对后提交。
