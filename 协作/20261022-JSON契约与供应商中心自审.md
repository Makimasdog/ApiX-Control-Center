# JSON 动作契约、供应商中心与入口收敛

日期：2026-10-22。分支：`qoder/unify-json-contract-provider-center-20261022`，基于 `codex/apix-flow-model-project-refactor-20261022`。本轮由 Qoder 完成实现和自审，没有启动额外 Agent；本文不是独立审查或人工批准。

## 范围与实际行为

- 助手 JSON 动作解析改为先去除 BOM，再依次尝试完整 JSON、Markdown 代码块和括号配对的顶层对象；普通解释文字、前后说明或围栏不再直接触发格式纠正。数组、字符串等非对象回复仍视为无效。
- 动作对象增加语义校验：`action` 只能是 `tool`、`ask`、`finish`；`tool` 动作必须包含非空工具名和对象参数。首次无效时只请求一次格式纠正，提示包含解析原因和截断后的上次回复；再次失败返回“连续两次未返回有效 JSON 动作”，不执行未识别操作。未知工具仍由工具层报告，不会被误当成合法执行。
- “Agent 供应商中心”成为唯一模型配置入口。删除独立“模型设置/模型偏好”页面、`web/model-settings.ts` 和重复的“ApiX 的推理模型”表单；设置页的供应商中心同时管理 ApiX 模型通道与 Codex、Claude Code 等执行员工绑定，支持供应商预设、密钥掩码、编辑版本校验、未使用供应商删除、本地回环服务免密钥与本地模型目录读取。
- 已有 ApiX 模型配置可一次性导入为供应商；导入复用其地址、模型、协议和密钥引用，避免要求用户重新抄写。未导入时页面显示提示，导入后仍可编辑和切换。
- 更换供应商地址或协议时，只要旧供应商保存过密钥，就必须重新填写 API Key，即使新地址是本机回环地址，防止旧密钥被发送到另一个本地服务。无密钥的本地服务仍可保存和启动员工。
- 入口收敛：侧栏“工作空间”保留“与 ApiX 对话”“管理总览”“多 Agent 任务”“任务与员工”，“协作设置”留在设置区；“多 Agent 任务”不再藏在“更多设置”。主对话头部增加“多 Agent 任务”，高级页增加“返回与 ApiX 对话”，高级页聊天标题改为“任务对话”，避免与主对话同名。
- 供应商中心内的连接测试仍要求先选择项目并明确批准可能产生的费用；测试不启动员工、不执行项目工具，结果不代表员工或工具可用。

## 审查与修复记录

- 审查供应商保存路径时发现：地址从远程切换到回环地址时，旧密钥可被复用而无需重新输入。已修正为“旧配置存在密钥引用时必须重填”，并增加后端断言与浏览器断言。
- 审查页面刷新后发现：刷新复用了“已保存”提示，且失败路径可能让按钮保持禁用。已为刷新、保存、删除、导入、绑定分别提供结果文案，并在动作结束后统一恢复表单可用状态。
- 删除已无监听方的 `apix:provider-manager-changed` 派发，避免残留事件协议；保留 `apix:manager-settings` 作为顶部模型入口跳转到供应商中心。
- 检查新增文件、删除文件引用、路由、前后端字段、版本冲突、密钥边界、HTML 转义、入口跳转和文档旧说法；同步修正 README、使用指南、Windows 桌面版说明、`.claude/MODEL_PROVIDERS.md` 与手工验证说明中的独立模型设置入口和变量名配置描述。

自审结论：本轮范围通过，未发现阻止提交的问题。提交后如代码再变化，需要重新审查和验证。
